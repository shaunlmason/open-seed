Design §10 Q3 (provisional default): "Opinionated stack variants (e.g. a TypeScript flavor with lint/test/typecheck pre-wired into `make check`) are v2 template flavors, never the v1 core." The v1 core's only stack contract is `make check` plus the hooks (§10 Q3); flavors are the mechanism for going beyond it without breaking the language-agnostic core.

Scope:
- Decide the flavor mechanism before building any flavor: template variant repos, a flavor directory + install step in the template, or an engine-side `seed init --flavor`. The decision must state how flavors interact with the template release/update surface (template.lock, `seed template upgrade`, §10 Q4) so a flavored instantiation can track template releases.
- Ship the first concrete flavor, the one the design names: TypeScript, with lint/test/typecheck pre-wired into `make check`.
- The flavor must not leak into the core: the unflavored template's contract stays make-check-plus-hooks.

Acceptance: instantiating the TypeScript flavor yields a repo whose `make check` runs the flavor's lint/test/typecheck and fails fast on a deliberately broken fixture; the unflavored template is byte-identical to today (validate.sh green, fan-out drift check green); the flavor mechanism decision is recorded in decisions/.
