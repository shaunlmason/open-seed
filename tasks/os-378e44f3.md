Four review findings on #191 (Phase 9 item 1c), all verified correct
against the code, arriving after that PR merged. A merged PR cannot
track new work, so they land as a fresh change.

P1 - the loop's actor was supplied beside its key rather than derived
from it. New() checked both were non-empty and nothing more, so a
misconfigured caller polls offers under actor B's eligibility, signs
every act as actor A, and writes liveness under B. The classifier keys
the observation stream by the holder, so it reads silence from a worker
that is working. Fix: derive the fingerprint from the key; drop the
parameter, so there is nothing to disagree through.

P1 - a claim reaped between the take's push and the post-claim read
turned ordinary contention into an error. Orient succeeds but reports
no window; the loop ignored Holds() and reserved anyway, which refuses,
and the park after it refuses too for want of an active claim. The
build plan's middle convergence arm is exactly this case: a refreshed
position-stamped read showing the act is no longer owed. Fix: treat the
missing window as idle before attempting further acts.

P2 - claim take is a declared liveness source in the shipped
implementer manifest, but observe() ran before the post-claim Orient
populated the fence. First iteration: dropped for an empty fence. Later
iterations: attributed to the previous claim's fence. So the claim's
own liveness was never observable under its own window, which is
exactly when a worker is most likely to stall. The claim result already
names the fence it opened. Fix: adopt it before emitting.

P2 - packet temp files were never unlinked. An unattended lane leaves
one per completed or parked iteration, leaking the host's temporary
storage and the packet contents, which are work product rather than
scratch. Fix: remove after the verb has consumed it, on every path.

All four fixes are implemented and mutation-checked already (each
reverts to a failing drill). Two drills had to be corrected as part of
it: the e2e liveness assertion hard-coded a shorter list copied from a
unit fixture and passed only because the fence bug meant claim take
never emitted, and the fence drill's pre-claim read supplied a window
it should not have had, so it passed without the fix.

Coverage needs attention: the new error paths dropped the gate reading
below 90 on the branch where they were written.
