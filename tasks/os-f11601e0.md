Found by a read-only review of the tree at bfa01638 (2026-09-05). Two gaps in the cross-org capability card (Phase 13 item 5, #279). (1) No production path verifies the signature: Makefile:51 runs seed boundary check without --pubkey, and check (next/cmd/seed/boundary.go:144-174) strips signer/signature and reports success when --pubkey is absent; the only call to boundary.Verify is that optional flag, and no reader-side verb verifies a fetched card against an out-of-band key without a local declaration, so plans/os-40ed0ca0.md D1's "a reader verifies the signature against the operator key it was given out of band" has no path. (2) Card.Canonical() (next/internal/boundary/boundary.go:132-153) is plain encoding/json, not RFC 8785: it escapes U+2028/U+2029, which JCS does not (tested against github.com/gowebpki/jcs, the library internal/event uses), so a card signed over the implementation's bytes is rejected by an independent JCS verifier. This card: a reader-side verification path (card plus out-of-band key, no declaration), the gate verifying against a pinned key, and Canonical() through the same JCS transform as the event model. Tier: standard. Plan-first.
