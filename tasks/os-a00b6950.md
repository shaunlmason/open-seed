Found while planning os-6a08b166 (Phase 9 item 4, small-team and fleet
end-to-end fixtures), and deliberately NOT taken there: that card's
scope guard forbids widening a CLI posture from a fixtures card.

runVerdictRender in next/cmd/seed/verdict.go defines its flag set as
--ledger, --subject, --repo, --key, --verdict, --artifacts, --timeout.
There is no --remote. Every other admitted surface reaches both
postures: openLoopSession branches on --remote vs the local store, and
offer publish, seal and the loop verbs all push through remote.go's
pushDraft.

The consequence is concrete and blocks a charter row. SEED-NEXT.md
III.J's closing row requires small-team mode AND fleet mode to "both
run the full loop in CI". Fleet mode means disjoint actors per lane
against ONE shared ledger, and a shared ledger is the remote posture -
contention between two workers racing claim take needs remote.go's
optimistic AppendLoop, since ledger.Store.Append has no retry at all
and returns ErrWrongPrev the moment the tip moved. So the fleet's
verifier lane has no way to render a verdict onto the fleet's own
ledger. Small-team mode is unaffected: one principal on one machine
runs the local posture, where verdict render already works.

This is NOT a flag plumbing job, which is why it is its own card. The
verdict payload carries "submission": "<position>" - a DERIVED value,
bound by the verdict rule to s.Submission.Pos. On the remote path the
tip moves between attempts, so the position must be re-derived per
attempt and the act REFUSED rather than silently re-pointed if the
binding changed. That is exactly the seam pushDraft's recheck parameter
exists for, and exactly the defect class plans/os-9b3f3ef3.md D1
records: "a derived value is re-examined against the refreshed tip and
refused rather than replaced". Getting it wrong the obvious way - fetch
the tip, recompute submission, sign, push - would bind the verdict to
whatever submission happens to be current, which is a laundering shape.

Scope: next/cmd/seed/verdict.go (the flag set, the session, the push
path with its recheck), next/cmd/seed/verdict_cli_test.go (a remote
drill, including one asserting a verdict whose bound submission moved
mid-flight is REFUSED rather than re-pointed), and a sentence in
next/spec/verdicts.md recording that the render verb reaches both
postures and how the binding survives the retry.

Above L1: plan first at plans/<id>.md via its own PR.
