Both `seed upgrade` and `seed template upgrade` resolve the target release by following the HTML `/releases/latest` redirect (internal/upgrade/upgrade.go:207). That endpoint 404s for a private repo even with a Bearer token, because github.com HTML does not honor token auth the way api.github.com does. The repo is public today (so the open-seed template works), but anyone running open-seed from a private fork hits `template_host_unreachable` regardless of credentials.

Origin: os-0f76f772 closed (done) with the engine-side fallback explicitly "a separate open-seed-engine change, out of scope for this repo"; the original gap card os-bb20001f was cancelled when the repo went public without resolving this; no open issue exists in open-seed-engine (verified 2026-08-24: zero open issues).

Scope:
- Resolve the latest release via `api.github.com/repos/<owner>/<repo>/releases/latest` with an optional bearer token (e.g. GITHUB_TOKEN / GH_TOKEN / an env override), falling back to the existing HTML redirect for the public/anonymous case.
- Cover both `seed upgrade` (engine releases) and `seed template upgrade` (template releases), which share the same resolution rule (internal/upgrade/upgrade.go:412).
- Keep the no-token public path byte-identical to today; record the env-var contract in the engine README / the handbook upgrade section.

Acceptance: against a scratch private repo with a published release, `seed template upgrade --check` resolves the target with a token and still works anonymously on the public repo; exit map unchanged (0 ok, 1 refusal, 7 unreachable); no regression to the checksum/attestation preflight.
