Phase 9's item 5 part (b) is the ONE numbered item in the phase with no
implementation, and the build plan says so in its own text:

  "Part (b) is **partially met**: the obligations, windows and budget
  block landed, and the unread messages did not, so the read a lane is
  told to orient from cannot yet tell it that it has mail. (b) is
  complete only when `seed situation` carries the messages addressed to
  the caller, with 'unread' derived from the cited `--since` position
  rather than from stored read-state."
  (docs/next-build-plan.md, Phase 9 item 5)

next/docs/progress.md records the same gap twice, most recently under
"9.5 part (b) is PARTIALLY MET".

Why it blocks the phase exit rather than being backlog: the one-inbox
doctrine says push channels wake and position-stamped reads convince.
`seed situation` IS the read every lane fragment names as the single
surface it orients from. A lane that has mail and cannot learn it from
that read has to either trust a wake as a fact about the world (which
the doctrine forbids) or run a second read the fragments do not name.
The exit's loop-completeness gate is what this fails.

Scope, as the plan's own text fixes it:

- `seed situation` gains a messages SECTION, not a new concept: the
  messages addressed to the caller.
- "Unread" is DERIVED from the cited `--since` position, never stored.
  The position a lane carries forward IS its read cursor.
- Therefore NO `message.read` verb is introduced. A verb whose only
  purpose is to record that someone looked would give the lane a second
  cursor that can disagree with the one it already carries.
- `--since <position>` keeps its delta semantics for the new section as
  it has for the others.

Open questions for the plan (decide per the plan's rubric, do not
escalate): whether the section reports message bodies or only their
identities and senders; how a message addressed to a lane rather than
an actor resolves; and whether the mail verbs already on the ledger
carry enough addressing to derive this without new facts.
