Deferred from the review of #196 (thread
https://github.com/shaunlmason/open-seed/pull/196#discussion_r3906512204),
verified real and deliberately not fixed there: choosing a shape from a P2
comment on a PR already in its fourth round is how a scope guard stops
meaning anything.

The window. internal/loop re-derives its actor by fingerprinting the key
file before every act (next/internal/loop/loop.go, checkIdentity). The act
itself then passes --key <path> across the CLI seam: loopdrive.go enters
run(), which reaches loopSigner (next/cmd/seed/loop.go) and reopens the
same path independently. An atomic replacement landing between those two
reads is observed by exactly one of them. The check is time-of-check, the
signature is time-of-use, and they can disagree.

Severity, stated honestly so the deferral is not convenient. The window is
microseconds between two reads in the same process and needs a rename(2) to
land precisely inside it. The outcome is bounded by the fence rule
(next/internal/admit/admit.go:190): a holder-signed event is admitted only
from the holder, so a cross-identity work act still refuses at the
boundary. What the race defeats is the loop's ability to DIAGNOSE a
rotation cleanly, not the invariant that a window is worked only by its
holder. That is why it is P2 and not P1.

Two candidate shapes, both with real costs, and picking between them is the
work:

1. Widen the loop verbs to accept key material rather than a path, on stdin
   or an inherited file descriptor. Closes the race completely: one read,
   one identity. Cost: it changes a protocol surface seven verbs share, and
   a material-bearing seam is a bigger security surface than a path-bearing
   one.

2. Have the Driver copy the key to a private path it owns for its lifetime
   and sign from that. Cheap and local. Cost: it puts private key material
   in a second place on disk, which plans/os-eb35672a.md already argues
   against for the loop.

A third option that should be considered before either: compare the
fingerprint AT the signing site instead of eliminating the second read. The
loop would pass its expected fingerprint down and loopSigner would refuse a
key that does not match. That does not make check and signature atomic, but
it moves the check to the same read the signature uses, which is the actual
defect. It costs one optional flag rather than a protocol change.

Acceptance: the chosen shape is implemented, the decision recorded in
next/docs/decisions.md with the shapes rejected and why, and a drill that
FAILS if the race is reintroduced. The drill needs a deterministic
interleaving seam, not a sleep: an injection point in the same style as
InjectPacketWriter, so the replacement is forced to land inside the window
rather than raced for.
