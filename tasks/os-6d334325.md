Observed 2026-08-24 on os-501a29c2. 'seed task close <id>' was run without --resolution. record_review sets Review.Evidence = a.Resolution, so the review block was written with an empty evidence field. The done-consistency lint (internal/task/statelint.go lintDone) then fails with 'done without evidence (merged PR URL or no-PR artifact, D4.5/D7)'.

Blast radius: state lint reads the shared seed-state ref, not the branch, so the check-validate 'check' job fails on EVERY open PR and on main until the card is repaired. os-221f5929 (PR #58) hit this with an otherwise-green branch.

Attaching PR evidence afterwards does not help: 'seed task attach-evidence' appends to the card's evidence list, while the lint reads the review block's own evidence field. os-501a29c2 now carries ev-309dbfe7 with the merged PR URL and still fails.

'done' is terminal with no re-record verb, so the only repair is a hand-authored state-ref commit, which AGENTS.md forbids agents from making.

Fix candidates: (a) accept/close refuse when the resolution is empty and no --no-pr marker is given, so the trap cannot be entered; (b) a supported repair verb that sets review evidence on a done card, operator-class; (c) have the lint fall back to the card's pr evidence entries before failing. (a) plus (b) looks right: prevention, plus a sanctioned way out for cards already in this state.
