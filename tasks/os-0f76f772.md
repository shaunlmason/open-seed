seed template upgrade resolves the target release by following the /releases/latest HTML redirect. That redirect only exists once a GitHub Release is published - a bare git tag is not enough. docs/handbook.md 'Cutting a template release (maintainers)' (line ~426) currently reads: bump version in .seed/template.lock, commit, tag that commit. It omits the required step of publishing a GitHub Release (e.g. gh release create v0.1.0). Add that step to the checklist so the resolution path actually works.

Verified 2026-08-23: with shaunlmason/open-seed public and a GitHub Release v0.1.0 published, /releases/latest 302s to tag/v0.1.0 and 'seed template upgrade --check' resolves (target v0.1.0). The engine-side fallback (resolve via api.github.com with an optional token, for consumers on private forks) is a separate open-seed-engine change, out of scope for this repo.
