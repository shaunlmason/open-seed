Found by a read-only review of the tree at bfa01638 (2026-09-05). The federation reader (next/cmd/seed/federation.go:152-207) fetches and fully verifies each remote but never calls gitref.Client.RecordVerifiedHead, so the monotonic-head rule (next/internal/gitref/gitref.go:204-277) is never armed on this surface: a remote that rewinds its ledger ref to a valid ancestor re-verifies from genesis and is reported verified on the next run in the same state dir, with no head_regression. Repro: seed federation report --state <dir> at remote tip B; force-push the remote's ledger ref back to ancestor A; re-run with the same state dir; A is reported verified. next/spec/requests.md promises "a remote that does not verify is reported as such and never folded" and "byte-identical on the same tips" but is silent on rollback; the client's own guard (RecordVerifiedHead: "the caller's statement that it fetched and fully verified this tip") exists and is simply not called. This card: persist the verified head per remote after full verification (the state dir is already per-remote) and report a head_regression refusal row instead of folding the rewound chain. Tier: standard. Plan-first.
