verbs.json declares comment_id (comment) and evidence_id (attach-evidence) as required verb outputs, and envelope.schema.json admits them since os-69bd5a64 — but the engine's builtin task service (filecards + fastcards) never populates either (observed: seed task comment returns comment_id: null). The tracker adapters (jira, linear) conform; the builtins should too. Small engine change in internal/task: mint stable ids for comment/evidence records and return them in the envelope; extend the port conformance tests so a missing id fails for every backend, builtin included.
