Found 2026-09-07 while the state ref was halted. `accept` (review -> done) enforces one precondition, `resolution_present`. It does NOT check whether `plans/<id>.md` resolves. So an operator can accept a plan-less card with a plain --resolution, and the card lands in `done` carrying evidence but no `no-pr:` prefix. The D3/D7 conformance lint then fails on it forever.

Unrepairable by design: `.seed/port-schema/transitions.json` has exactly one transition touching `done` (review -> done via accept) and its own note says "done is terminal, so no transition can repair it". Confirmed at the CLI: `task close --no-pr` on a done card returns invalid_transition; `task record-evidence --no-pr` returns evidence_already_recorded; `reinstate` is cancelled -> backlog only; the port spec declares no amend, edit or repair verb. The only remaining route is a direct edit of the seed-state ref, which AGENTS.md forbids agents and which is a protected surface.

Operational cost: `state lint --halt-on-fail` runs at :17 hourly (.github/workflows/seed-maintenance.yml), so the repo re-halts every hour and every mutating verb is refused for every actor until someone resumes by hand. Observed 2026-09-07: HALT at 06:52 after three accepts at 06:26, manual resume at 07:18, lint still failing.

Live instances (all three legitimately plan-free, all missing the flag): os-0dba8c6a (its deliverable WAS a plan PR, #319), os-5fe43832 (merged as a docs: PR, #305), os-405d3b20 (an L1 card merged from a claude/ branch, #342; its own evidence records "no receipt: the card is L1 and receipt generate refuses without a plan").

Scope: add the precondition to accept so the refusal happens while the card is still in `review` and still fixable, naming --no-pr in the failure detail (the fail_detail text already explains the exemption; it just is not enforced). Engine change, mirrored in .seed/port-schema/transitions.json (protected surface: PR + owner review). Open question for the plan: whether the lint should also treat a done card whose evidence names a merged PR as satisfying D7, which would retire the three live instances without a state-ref edit; if not, those three need an owner-side edit either way. Above L1: plan first.
