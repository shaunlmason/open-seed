Design §10 Q4 (provisional default): "In v2 the evolving parts (skills, roles, workflows) additionally ship as a Claude Code plugin/marketplace package to soften R8 — plugin carrying capabilities, template carrying structure — with `.seed/version` + lockfiles as the update surface on both paths." R8 (template drift after clone) names this the mitigation the template repo alone cannot provide.

Scope:
- Package the evolving parts (skills/, rules/, .seed/agents/ role definitions, workflows) as a Claude Code plugin/marketplace artifact: manifest shape, install surface, and the provenance story (research/09 §Plugins & marketplaces: marketplaces are git repos with `.claude-plugin/marketplace.json`; a repo can declare plugins in `.claude/settings.json`).
- Reconcile the update surface with what already landed: os-23494e11 (template.lock + pull-based `seed template upgrade`) and os-6f3104db (seed.yaml/seed.lock skills manifest). The plugin channel and the template channel must share one drift-detection story, not invent a second.
- Additive by design: template-only users stay unaffected; the plugin channel softens R8, it does not replace the template structure.

Acceptance: a fresh template instantiation can also install the plugin channel, and `seed sync --check` / validate.sh still pass; drift between the channel and the in-template sources is detectable offline; the handbook documents the two distribution paths and when each is the right one.
