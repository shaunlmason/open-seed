Phase 9 item 1, first of three cards. The item bundles four deliverables and is too large for one plan, so it splits the way item 5 did (os-52d5da3f for (a)+(b), os-7e197768 for (c)):

- 1a (this card): the six lane role definitions as composable FRAGMENTS, carrying the four obligations docs/next-build-plan.md item 1 binds, plus the validation that keeps each declaration real.
- 1b: dispatcher least-capability posture and the injection conformance suite (hostile corpus) against dispatcher input handling.
- 1c: the worker lane's loop made executable, with exhaustion parking: a budget refusal at a spending gate triggering the claim.parked exit with packet (the III.H row the Phase 7 exit routes here), consuming Phase 8's envelope budget block.

1c depends on 1a because the worker's loop is part of the worker's fragment; 1b is independent of both.

The four obligations (build plan item 1, as amended by os-68ea0b2d, #180) are each a new consumer of a table that already exists rather than a new authority:

1. ONE POSITION-STAMPED READ ON WAKE. The fragment names the single read it orients from -- "seed situation --key <its key> [--since <last position>]" -- and the position it carries forward; fragment validation checks the declaration is present and names a real surface. This makes promotion criterion 1 a property of the role file rather than of whoever writes the agent.
2. THE LOOP ACTS THROUGH THE LOOP VERBS of item 5(c) ("claim take|release|park", "submission make", "budget reserve|settle|release"), never the raw append seam, which consults the admission boundary not at all and so cannot answer a refusal with what IS legal.
3. LIVENESS RIDES THE WORK. The observations the expiry/wedge classification reads are emitted by the loop's own steps, so a working lane is a live lane by construction; the vocabulary contains no verb whose only purpose is to report liveness, and a bare heartbeat is forbidden rather than discouraged.
4. THE ONE-INBOX DOCTRINE. Push channels wake, position-stamped reads convince: no lane treats a wake, an event or a message as a fact about the world, only as a hint to read.

Prerequisites are all merged: the obligations projection and situation read (#171), the loop verbs (#173), and their post-merge fixes (#181).

Open question for the plan: what a FRAGMENT is mechanically. v1 has role files under .seed/roles/ with a variant and fan-out mechanism; next/ has no role surface at all yet. The plan decides whether fragments live under next/ as their own surface or reuse the v1 shape, per the build plan's decision rubric, and must respect the rule that Seed work never modifies v1 surfaces except the integration points the plan names.
