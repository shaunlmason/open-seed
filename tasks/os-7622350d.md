Found by a read-only review of the tree at bfa01638 (2026-09-05). Note (next/internal/refusals/refusals.go:120-137) appends directly after the existing tail and only truncates a short write of its own line; Load (:161-166) ignores a final unterminated fragment only while it remains the final fragment. So after a torn write (crash, full disk) leaves an unterminated fragment, the next journaled attempt glues a valid line onto the fragment and terminates the combined invalid line; Load then rejects the journal on every future read, blocking the refusal metrics the report's refusals section is built from. This violates the invariant the code states ("a failure must never poison the journal for later builds"). Repro: leave attempts.jsonl ending mid-line without a newline, perform any journaled admission attempt, then Load. This card: on append, terminate or drop the uncommitted fragment before writing (or make Load recover the glued line), with a torn-tail-then-append drill. Tier: standard. Plan-first.
