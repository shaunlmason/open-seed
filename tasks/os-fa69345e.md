Review finding on #168. runLedgerShow with --position <missing> opens the ledger, scans it successfully, and then returns not_found (next/cmd/seed/ledger.go, the found == nil branch) WITHOUT setting Position — although the scan established a count, so the position exists and is known. That contradicts the envelope rule (a response stamps the position it was computed at whenever one was established; only responses that never established a position carry null) and it costs the caller the very thing the field exists for: without the stamp, a caller cannot tell whether the position they asked for might have appeared concurrently. Fix: track the count during the existing iteration (no second scan) and stamp it via the shared stampTip helper on the not_found return; an empty chain establishes no position and correctly stays null. Leave the chain_invalid branch alone — a failed scan establishes no trustworthy count, and null is the honest answer there. Add a CLI drill asserting the not_found envelope carries the tip ordinal and that the empty-ledger case stays null. Note: runLedgerShow does not call journalAttempt, so stamping here does not turn a read surface into a journaled admission attempt. Recorded as a named deviation in the Phase 8 exit record (#168) rather than glossed; this card discharges it. Plan-first (L2).
