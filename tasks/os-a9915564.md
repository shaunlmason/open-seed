Every `scripts/seed task <verb>` prints a single-line, unindented JSON envelope.
That is correct for agents and unreadable for humans: `task list` on this repo is
one ~4KB line, and `maintain report` buries five counts in an object. Operators
inspecting the queue currently pipe everything through `python3 -m json.tool` or
`jq` by hand.

Scope: add human-readable rendering for the read-only surface, without weakening
the machine contract.

- Verbs in scope: `task list`, `task ready`, `task get`, and `maintain report`.
  Mutating verbs keep emitting the envelope unchanged.
- Selection rule to settle in the plan; the starting proposal is TTY-sensing —
  human table when stdout is a terminal, envelope otherwise — so every existing
  scripted/agent caller (always non-TTY) is byte-for-byte unaffected.
- `--json` forces the envelope even on a TTY. Note that
  `.seed/port-schema/envelope.schema.json` already describes the contract as
  "every `seed task <verb> --json` invocation", so the flag is spec-anticipated,
  not new surface. A `--format json|table` spelling is the alternative to weigh.
- Table shape: id, state, priority, squad, title (truncated to terminal width),
  sorted by state then priority rather than by id. Colour only when the terminal
  supports it and `NO_COLOR` is unset.

Out of scope: changing the envelope schema, the exit-code map, or any verb's
JSON field set. This is presentation only.

Notes for the planner:
- The engine is a separate Go repo (`shaunlmason/open-seed-engine`, §7.5), so the
  implementation lands there and this card tracks the pin bump here.
- Check whether the port spec / `docs/design-options.md` needs an addendum
  recording that human output is a non-contractual presentation layer — the
  envelope stays the single source of truth for anything parsed.
