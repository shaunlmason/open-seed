# Plan: next — the contention benchmark at target scale (os-a00d3f34)

Charter III.C row 4: "A contention benchmark demonstrates the target
scale (hundreds of concurrent actors) without lost updates, tracked in
CI." The Phase 12 exit record recorded the row PARTIAL and routed it
to the build plan's §3 backlog: the per-PR storm stays at 24 writers
under the perf gate, because a storm at the target scale costs minutes
a run, and the target scale is a scheduled run tracked against the
same budgets. The conformance table (os-83bc3d84) carries C.4 as

schedule, its reading attached and its miss failing the run. No
change to the per-PR gate. Tier: standard. Deps: none.

## What the tree actually shows

- **The gate is already parameterized by size.** `perfgate.Budgets`
  carries `history` and `writers` beside the five ceilings, `Load`
  refuses a ceiling without provenance, `cmd/perfgate -budgets <file>`
  measures at the file's size, and `Measurer.storm` asserts no lost or
  doubled update at any writer count (`rep.Count != res.Records+writers`
  fails the run). `seed perf run --budgets <file> [--writers n]` reads
  the same numbers as an envelope. A scale run is therefore a second
  budget file and a schedule, not a second tool.
- **The cost grows faster than the writers.** The optimistic loop's
  attempts per landed append is 12.5 at 24 writers and about 51 at
  200 (measured for this plan: a landed writer leaves the pool, so
  the ratio sits under the writers/2 of a pool that never shrinks),
  so 200 writers cost about 10,000 fetch-and-push attempts against
  one bare remote, sixteen minutes on a four-core host, which is why
  the row was routed to a schedule.
- **A scheduled workflow is linted.** `protections.LintWorkflows`
  flags a `schedule:` trigger beside `contents: write` (scheduled
  identities are least-privilege, III.L row 5); a read-only scheduled
  job passes. `.github/workflows` is a protected path in
  `.seed/guardrails.yaml` and lands only through owner review at
  merge, the one v1 surface this card touches beside the docs tree;
  Phase 13 item 6's platform matrix (#273) is the precedent.
- **Nothing documents a second profile.** `next/spec/checkpoints.md`
  "Performance budgets" describes one file and one gate.

## Design decisions (binding for this task)

- **D1 — one gate, two sizes.** `next/perf/budgets-scale.json` has
  the shape of `budgets.json`: `history` 40 (the same representative
  history, so the ceilings and the per-PR readings are about the same
  chain), `writers` 200 (the smallest count that is hundreds, plural),
  and the five metrics with ceilings and provenance. `cmd/perfgate`
  and `internal/perfgate` change by nothing; the scale run is
  `go run ./cmd/perfgate -budgets perf/budgets-scale.json -last
  perf/last-scale.json`, the same re-measure-cold-once rule, the same
  no-lost-updates assertion.
- **D2 — the ceilings are measured, then held.** During
  implementation the storm is measured at 200 writers on the
  implementing host at least twice (`seed perf run --writers 200`),
  the ceilings are set at about three times the slowest reading for
  the timings and twice the reading for the attempts ratio (the
  budgets file's own convention), and the provenance names the host,
  the readings and the date. The admission, replay and rebuild
  ceilings are copied from `budgets.json`, since the history is the
  same. If the runner's first scheduled reading misses a timing
  ceiling while the attempts ratio and the lost-update assertion
  hold, the ceiling is re-based by a reviewed edit of the file citing
  the runner's readings, never by loosening the assertion.
- **D3 — the schedule is weekly, read-only, and attaches its
  reading.** `.github/workflows/perf-scale.yml`: `schedule` (weekly,
  off the hour) plus `workflow_dispatch`; `permissions: contents:
  read`; one job on `ubuntu-latest` with `timeout-minutes` 180 using
  the `go-env` action, running the gate in `next/`, then uploading
  `next/perf/last-scale.json` as an artifact whether the gate passed
  or not (`if: always()`), so a miss carries its numbers. A miss fails
  the run; nobody is paged, the run's red is the signal, and the next
  agent reads the artifact.
- **D4 — the profile's scale is pinned by a drill.**
  `TestScaleProfileIsHundredsOfWriters` (`internal/perfgate`) loads
  `perf/budgets-scale.json` through `Load`, asserts `writers` at or
  above 200, `history` at or above `budgets.json`'s, and the attempts
  ceiling at or above the per-PR profile's (attempts per landed append
  grow with writers, though under writers/2 at scale, since a landed
  writer leaves the pool), so the profile cannot shrink below the
  charter's scale or claim a cheaper loop than the small storm's
  without failing `make check`. `TestTreeWorkflowsHaveNoScheduledWriters`
  (`internal/protections`) runs `LintWorkflows` over this
  repository's own `.github/workflows` and expects no finding outside
  v1's `seed-maintenance.yml`, whose `contents: write` is the state
  ref's anchor and the operator identity's by design, so the scale
  workflow and every later scheduled one stay read-only; a copy of
  the scale workflow given `contents: write` is a finding.
- **D5 — the spec says what runs where.** `next/spec/checkpoints.md`
  "Performance budgets" gains the second profile, the schedule and
  the rule that the per-PR gate stays at 24 writers; the III.C row 4
  bullet in its conformance mapping names the scheduled run. The
  conformance table's C.4 row is flipped by the Phase 13 exit record
  citing the first green scheduled run (plans/os-d63c7441.md D2),
  not by this card.
- **D6 — bounds.** No change to `budgets.json`, `Makefile`,
  `cmd/perfgate`, `internal/perfgate`'s code, `internal/history` or
  the storm; no new verb; no product path. The workflow file is the
  only file outside `next/**` and the docs tree.
