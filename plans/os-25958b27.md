# Plan: Jira backend adapter (os-25958b27)

External plugin over Jira Cloud REST v3 — the enterprise-reach adapter.
Jira's twist: statuses are workflow-specific and moves happen via the
transitions API, so the adapter resolves transitions **by target status
name** at call time rather than assuming ids.

## Steps

1. **Adapter** — `.seed/backends/jira/bin/seed-backend` (POSIX sh + curl +
   jq) against `$JIRA_BASE_URL/rest/api/3`. Env via `requires_env`:
   `JIRA_BASE_URL`, `JIRA_EMAIL`, `JIRA_API_TOKEN`, `JIRA_PROJECT_KEY`.
   Verb mapping:
   - `create` → POST issue (type Task); priority P0–P3 →
     Highest/High/Medium/Low. **The port contract says create returns
     `backlog`, so the issue must actually land there**: a Jira workflow
     whose initial status is `To Do` (common default) would mint `ready`
     cards. After the POST, the adapter reads the created issue's status
     and, when it is not `Backlog`, transitions it there (refusing with
     exit 5 + remediation if no such transition exists); `backend
     verify` and the README's workflow-setup section both require the
     `Backlog` status. Contract case: create against a fake whose
     initial status is To Do still yields a backlog card.
   - `ready` → JQL search `project = X AND status = "To Do" AND assignee
     IS EMPTY ORDER BY priority`
   - `get`/`list` → issue GET / JQL; status mapping by name against the
     documented convention (Backlog→backlog, To Do→ready,
     In Progress→in_progress, In Review→review, **Blocked→blocked** —
     required so above-L1 tasks can park on their plan PRs; the README's
     workflow-setup section shows adding it — Done→done; cancelled =
     Done + resolution "Won't Do"). A workflow missing a required status
     → exit 5 with a remediation message (declared requirement). Worker
     parking and operator block/unblock are both contract-tested, with
     `blocked_on` entries persisted as Jira labels (`seed:bo:<entry>`),
     released entry-by-entry (plan-unblock/unblock) only when empty.
   - **Actor identity**: Jira Cloud assignment requires an `accountId`,
     not a name — the adapter resolves actors through a checked-in
     mapping file (`.seed/backends/jira/actors.json`:
     `{actor: accountId}`), refusing unknown actors with exit 5 and a
     remediation message; holder comparisons use accountIds throughout,
     with the reverse mapping for envelope `holder` fields. The mapping
     file and its lookup are contract-tested.
   - `claim` → read assignee, exit 2 + holder if set, exit 2
     `rejected_author` when the caller carries `seed:rejected:<actor>`
     (lockout persisted via labels, as in the beads adapter), else PUT
     assignee + transition to In Progress. **Emulated** (last-write-wins
     race window, declared); fence = assignee-match → exit 6.
   - `transition`/operator verbs → GET available transitions, match by
     target status name, POST the transition id; no matching transition →
     exit 3 (Jira's workflow is the arbiter, honestly surfaced)
   - `close`/`cancel` → transition to Done (resolution set; "Won't Do"
     for cancel) **with the required cascade emulated** (the optional
     `dep` editing verb stays absent, but close/cancel's cascade is
     required semantics): `--blocked-by` entries ride `seed:bo:dep:<id>`
     labels; close and cancel remove their entry everywhere and
     transition blocked issues whose set empties back to To Do,
     returning released ids in `cascaded`.
   - `comment`/`attach-evidence` → comment (ADF body); `event-append` →
     comment; Jira's changelog is the audit substrate
   - `lease-renew` → no-op success (declared)
2. **Manifest + lock**: `atomic_claim = "emulated"`, `offline = "none"`,
   `budget = "none"`; in-template lock entry.
3. **Contract test** — `test.sh` + `testdata/fake-jira` (Python3
   `http.server`: issues, JQL subset, transitions-by-name, assignee).
   Covers all required verbs, claim contention, missing-status refusal,
   transition-not-available → exit 3. Wired into validate.sh behind the
   python3 guard.
4. **README**: API token setup, the status-name convention table and how
   to satisfy it in a company-managed workflow, declared variances
   (emulated claim, no leases, server is truth, rate limits; the cascade
   is **emulated via `seed:bo:*` labels** — implemented and contract-
   tested, never described as absent; its limitation is that label
   bookkeeping is only as trustworthy as label write access), and the
   note that Jira Server/DC (v2 API) is out of scope.
5. **Handbook §6**: one line adding Jira to the backend menu.

## File Scope

- `.seed/backends/jira/**`, `.seed/backends.lock.json`,
  `scripts/validate.sh`, `docs/handbook.md`

## Acceptance Criteria

- All nine required verbs round-trip against the fake server with valid
  envelopes and mapped exit codes; claim contention exits 2 with holder;
  a transition unavailable in the workflow exits 3; a missing
  convention status exits 5 with remediation; an unmapped actor exits 5.
- Parking, block/unblock entry isolation, the rejected-author lockout,
  and the close/cancel cascade are all covered by the contract test.
- No engine changes (v0.7.0 dispatch seam suffices); existing validate
  chain unchanged.
- Every variance declared in README + manifest.

## Validation Commands

- `test -x .seed/backends/jira/bin/seed-backend`
- `sh .seed/backends/jira/test.sh`
- `sh scripts/validate.sh`
