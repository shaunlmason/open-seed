# Plan: remaining lifecycle shims (os-7792a002, §131 + §7.3)

v1 shipped the runner-agnostic lifecycle contract (`.seed/hooks/` with
setup/run/teardown + `post-create.d/`/`pre-merge.d/`, the
`.worktreeinclude` file, `seed hooks run` as the portable runner) and
integration guidance for the top three external worktree tools
(superset, agent-deck, vibe-tree). This card ships "the rest v2": the
remaining surveyed tools from inspirations/07 — octomux, amux, dmux,
tmux-ide, ouijit, parallel-code — each as a checked-in shim honoring
the contract, with every tool's fidelity gaps declared rather than
papered over (the dmux lesson: its `pre_merge` is detached and cannot
gate, so CI stays the merge authority — R11).

## Steps

1. **Shim home**: `.seed/hooks/shims/<tool>/` — one directory per
   tool holding the tool-native config fragment that wires that
   tool's lifecycle points to `seed hooks run <name>` (or directly to
   the hook files), plus a short README stating install steps and the
   tool's fidelity table (which contract points it can honor, which
   it cannot).
2. **The six shims**, each per its inspirations/07 source-level
   contract:
   - **octomux**: hook config mapping its worktree lifecycle +
     loop-budget events onto setup/post-create/teardown.
   - **amux** (`.amux/workspaces.json`): workspace create/remove
     wired to post-create.d/teardown; trust prompts documented.
   - **dmux** (`.dmux-hooks/`): `worktree_created` →
     post-create.d, `before_worktree_remove` → teardown,
     `pre_merge` → pre-merge.d **with the declared caveat** that
     dmux spawns hooks detached and non-blocking — the shim README
     states plainly that dmux cannot veto a merge and the CI verify
     gate is the real backstop.
   - **tmux-ide**: session lifecycle → run/setup mapping.
   - **ouijit**, **parallel-code**: minimal mappings per their
     (brief) surveyed surfaces; where a tool exposes no usable hook
     point, the shim README says exactly that instead of shipping a
     dead file.
3. **Fidelity table** (docs): the handbook's lifecycle section gains
   the per-tool support matrix (blocking pre-merge: which tools can /
   cannot), extending the "declared, never silent" posture from the
   permission tiers to worktree tooling.
4. **Validation**: `scripts/validate.sh` structurally checks each
   shim directory ships a README plus at least one config fragment,
   and that every fragment references only hook names the contract
   defines (a sed/grep lint — no tool binaries required in CI).
5. No engine changes: the contract is already engine-side
   (`seed hooks run`); this card is template content only.

## File Scope

- Template: `.seed/hooks/shims/{octomux,amux,dmux,tmux-ide,ouijit,parallel-code}/`
  (new), `.seed/hooks/README.md` (shim index), `scripts/validate.sh`
  (structural shim lint), `docs/handbook.md` (fidelity matrix)

## Acceptance Criteria

- Each of the six tools has a shim directory with a README (install
  steps + fidelity table) and its config fragment, referencing only
  contract-defined hook names.
- The dmux shim explicitly declares the non-blocking pre_merge
  limitation; any tool without a usable hook point says so instead of
  shipping a dead file.
- validate.sh fails on a shim directory missing its README or
  referencing an unknown hook name.
- The handbook carries the per-tool fidelity matrix.

## Validation Commands

- `test -d .seed/hooks/shims/dmux`
- `grep -rq "pre_merge" .seed/hooks/shims/dmux/`
- `grep -qi "fidelity" docs/handbook.md`
- `sh scripts/validate.sh`
