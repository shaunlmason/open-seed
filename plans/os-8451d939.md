# Plan: next — Phase 9 item 5(b), `seed situation` carries the caller's messages (os-8451d939)

Phase 9's item 5 part (b) is the one numbered item in the phase with no
implementation, and the build plan says so in its own text: the read a
lane is told to orient from *"cannot yet tell it that it has mail"*, and
(b) *"is complete only when `seed situation` carries the messages
addressed to the caller, with 'unread' derived from the cited `--since`
position rather than from stored read-state"*.

**Why it blocks the phase exit rather than being backlog.** The
one-inbox doctrine (charter §II, `docs/next-build-plan.md` Phase 9 item
1) says push channels wake and position-stamped reads convince.
`seed situation` IS the single surface every lane fragment names as the
one it orients from — `internal/lane` validates that declaration against
the real surface. A lane that has mail and cannot learn it from that
read must either treat a wake as a fact about the world, which the
doctrine forbids, or make a second read its fragment does not name. The
exit's loop-completeness gate is what that fails.

## What the tree actually shows

Measured, not assumed:

- **`message.sent` is admitted today and has no payload rule at all.**
  It has no row in `next/spec/transitions.json` and no case in
  `keyring.AcceptedCapabilities`, so it falls into the standing-only
  class: any enrolled active actor appends it. The drills append
  `{"n": 1}` (`cmd/seed/remote_test.go`,
  `internal/admit/affordances.go`'s probe view). There is no recipient
  field, no schema, and no folder that reads one.
- **`message.acked` is named in `protocol.md` and is unimplemented.**
  `next/spec/lanes.md` says so explicitly: it "appears in neither"
  the affordance catalog nor the spec table, "being unimplemented, so
  the suite cannot speak about" it.
- **`situation`'s result is `{actor, obligations, windows}`**, plus
  `{since, discharged, unchanged}` under `--since`, with affordances
  stamped when a key and a subject are both given
  (`cmd/seed/situation.go`). The budget block rides the affordance
  envelope, not the result.
- **`--since` cites a tip ORDINAL**, so the prefix a lane last saw is
  `records[:pos+1]`. The obligations delta already turns on that
  off-by-one and names it.

## The constraint this card runs into, which is the whole design

`message.sent` is a **named residual of the injection conformance
suite** — `next/spec/lanes.md`'s residual table calls it *"the one that
RELAYS"*: no capability at all, bounded only by the classification
lint's 512-byte size bound, which the residual's own row observes "the
sixty-byte instruction that matters sails through".

And `cmd/seed/injection_cli_test.go` currently sweeps `situation` — both
the per-subject and whole-board forms, in serialized form — for a marker
planted in hostile prose, and it is clean.

Putting message **bodies** into `situation` would hand any enrolled
actor an automatic prose channel into the read every lane orients from.
That converts the residual from *"a persuaded dispatcher can relay
deliberately, and a reader must choose to look"* into *"any enrolled
actor writes into every lane's orienting read, unbidden"*. The suite
would go red, correctly, and the honest fix would not be to relax it.

## Design decisions (binding for this task)

- **D1 — `situation` carries message NOTICES, not bodies.** Each notice
  is `{from, subject, at, bytes, unread}`: who sent it, which contract
  it concerns, the ledger position, the payload's size in bytes, and
  whether it falls after the cited cursor. No payload text whatever.

  This satisfies the item's requirement exactly as written — the read
  can now tell a lane that it has mail, from whom, and about what — and
  it keeps the injection sweep green **by construction** rather than by
  a filter that a later field could slip past. The contract id and the
  sender fingerprint are generated identifiers, not free text.

  The alternative, bodies with sanitization, is refused: the residual
  table's own point is that a size bound does not stop a short
  instruction, and no sanitizer of prose is going to do better against
  the exact channel the suite already names as the sharpest one.

- **D2 — addressing is an optional `to` field read by the projection;
  the admission boundary is not touched; and a `to` that does not parse
  fails CLOSED.** Three cases, and the third is the one the first draft
  got wrong (review finding on #209):

  | payload | addressed to |
  |---|---|
  | no `to` key at all | **everyone** — a broadcast |
  | `"to": "<fp>"` or `"to": ["<fp>", …]`, all strings | those actors |
  | a `to` that is present and does not parse | **no one** |

  Absent and malformed are not the same thing and must not resolve the
  same way. An absent `to` is a sender who said nothing about
  addressing, and reading that as "everyone" reads what is there. A
  malformed `to` — `{"to": ["<fp>", 7]}`, a number, an object — is a
  sender who said something the projection cannot read, and every way of
  resolving it invents intent. Broadcasting it is the worst of them: it
  widens delivery from one intended recipient to every actor on an
  ordinary encoding slip, surfacing the sender, the contract and the
  size to everyone, and it contradicts AC1's "and only those" in the
  same document. Delivering to the well-formed entries only is a quieter
  version of the same invention: nothing says which entries were meant.

  So an unreadable address addresses no one. The message is still on the
  chain and still visible to the **keyless** whole-board read, which
  applies no caller filter — so undeliverable mail is discoverable by an
  operator looking at the board, rather than vanishing. A drill covers
  exactly that.

  The admission boundary stays untouched for two reasons, the second
  load-bearing. First, `{"n": 1}` stays legal, so no existing drill or
  probe changes meaning. Second, this item is part (b) of the
  **lane-facing surface**, which is a read: the obligations projection
  is "non-authoritative" by the plan's own wording, and a read has no
  business adding rules to the admission boundary. Validating `to` at
  admission is a real and probably correct future change; it is a
  different card, and one that must reckon with the fact that a
  validated recipient list is a new refusal surface on a verb that today
  refuses nothing.

  Consequence, stated rather than buried: **anyone can address anyone**,
  because `message.sent` already needs no capability. What D1 buys is
  that the worst outcome is a notice saying you have mail from someone,
  which is exactly the sentence a wake would have carried anyway.

- **D3 — "unread" is the cursor, and there is no read-state.** A
  message at position P is unread iff `P > --since`. With no `--since`
  cited, **every** addressed message is unread, because a caller that
  names no cursor has told us nothing about what it has seen. No
  `message.read` verb is introduced (the build plan's own instruction),
  and `message.acked` stays unimplemented: an ack means "I acted on
  this", which is a different claim from "I saw it" and is not what a
  cursor can derive.

- **D4 — the section is `messages`, and it is present whether or not it
  is empty.** An absent section and an empty one are the same JSON
  question a lane should not have to ask twice. The obligations section
  is already unconditional; this matches it.

- **D5 — the delta applies, and it is the SAME delta.** Under `--since`,
  `messages` reports only messages at positions after the cursor, like
  every other section. Unlike obligations there are no removals to
  derive: a message is an event, and an event does not stop having been
  appended, so there is no `discharged` analogue and none is invented.

- **D6 — the body IS readable, by a deliberate second act, and it lands
  in this card.** `seed message read --key <path> --at <position>`
  returns one message's payload to a caller the message is addressed to,
  and `not_found` to everyone else.

  The first draft deferred this and marked 5(b) complete anyway. That
  was wrong on the build plan's own words (the read must carry "the
  messages addressed to the caller") and on promotion's requirement that
  a lane work entirely through Seed verbs: a lane that learns mail exists
  and cannot obtain it through any Seed read has not been given its mail,
  and calling the item met would have advanced Phase 9 on a half feature
  (review finding on #209).

  The deferral's stated reason — that a body read has the same prose
  problem D1 solved — does not survive contact with D1's own argument.
  What made bodies unacceptable in `situation` is that `situation` is
  read on **every wake, unbidden**, so prose there steers a lane that
  never asked for it. A read naming one position is the opposite: it is
  the "reader must choose to look" case the residual analysis already
  accepts, taken **after** seeing a notice that says who sent it. The
  two surfaces differ exactly where it matters.

  Three things this verb is not, each deliberate:

  - **Not a ledger verb.** Nothing is appended, so the build plan's "no
    `message.read` verb is introduced" holds: what it forbids is a fact
    that records read-state and gives a lane a second cursor to
    disagree with the one it carries. A read that writes nothing gives
    it none.
  - **Not a new refusal code.** A message the caller is not addressed by
    returns `not_found` (exit 4), not a new "not addressed" code — which
    also means the refusal does not disclose that a message exists at
    that position at all. `not_recipient` (exit 23) is emphatically NOT
    reused: it names the sealed-envelope recipient set, whose answer is
    "re-seal to the current set", and sharing a code across two
    different answers is what `envelope.md`'s allocation rule forbids.
  - **Not a mailbox.** It returns one message at one cited position. The
    listing is `situation`'s job and already exists as of D1.

- **D7 — scope guard.** No verb gains a rule, no transition row moves,
  no capability changes, and no lane fragment changes. This card adds
  one derivation and one section to one read, and the drills that prove
  the derivation and pin the containment.

## Steps

1. `next/internal/project/` — `DeriveMessages(records)` returning the
   ordered notices, with the lenient `to` parse (D2) and no payload
   text in the result type. Unit-drilled there: addressing forms,
   malformed `to` shapes, ordering, and the fact that the type has no
   field a body could occupy.
2. `next/cmd/seed/situation.go` — the `messages` section, filtered to
   the caller, cut by `--since` (D3, D5). A keyless read reports the
   whole board, as it already does for obligations.
3. `next/cmd/seed/injection_cli_test.go` — a hostile marker planted in
   a `message.sent` payload addressed to the reading worker, swept
   across the same serialized reads. This is the drill that makes D1 a
   property rather than an intention.
4. `next/cmd/seed/situation_cli_test.go` — the behavioral matrix:
   addressed vs broadcast vs addressed-to-another vs malformed-address,
   the cursor boundary at exactly `--since`, the empty section, and the
   keyless whole-board read (which shows the undeliverable message D2
   addresses to no one).
4b. `next/cmd/seed/message.go` + `message_cli_test.go` — `seed message
   read --at <position>` (D6): the body to a recipient, `not_found` to
   anyone else and for a position that holds no message at all, in both
   postures. Drilled for the disclosure property too: the refusal for
   "exists but not yours" and for "nothing there" are
   indistinguishable.
5. `next/spec/obligations.md` — whose title is already "The obligations
   projection and **the situation read**" and whose "## The situation
   read" section documents the surface: the `messages` section lands
   there. And `lanes.md`'s residual row for `message.sent` is updated:
   the residual is unchanged in kind, and there is now one more surface
   it reaches, which the row must say.
6. `next/docs/progress.md` — 9.5 part (b) moves from PARTIALLY MET to
   met, and Phase 9's frontier becomes the exit record.
7. `next/docs/decisions.md`, `memory/LEARNINGS.md`; the D6 follow-up
   card; receipt; evidence; review.

## Acceptance Criteria

1. `seed situation --key K` reports a `messages` section listing the
   messages addressed to K, and only those: a message addressed to
   another actor does not appear, and a broadcast does.
2. **No payload text reaches the section**, proven by the injection
   sweep with a marker planted in a `message.sent` payload addressed to
   the reading worker, swept across both situation forms in serialized
   form. The drill fails if a body field is ever added.
3. Unread is the cursor: with `--since P`, exactly the messages at
   positions after P appear; the boundary is drilled AT P (the message
   at P itself does not appear) and at `P-1`. With no `--since`, all of
   the caller's messages appear.
4. A malformed `to` — a number, an object, an array of numbers, a
   missing field — reads as a broadcast rather than refusing, panicking,
   or silently dropping the message. Each shape is a row.
5. The section is present and empty when the caller has no mail.
6. `seed message read --at P` returns the body to a caller the message
   at P is addressed to, and `not_found` to a caller it is not — the
   same refusal, byte for byte, as a position holding no message at all,
   so the refusal discloses nothing about what is there. A broadcast is
   readable by anyone; a message with an unreadable `to` is readable by
   no one, which is D2 and D6 agreeing.
7. **Mutation evidence.** Each must fail a drill: the filter dropping
   broadcasts; the filter admitting another actor's messages; a
   malformed `to` resolving to everyone (the review finding's own case);
   the cursor comparison using `>=` instead of `>`; a body field added
   to the notice; `DeriveMessages` ordering by anything but position;
   and `message read` returning a body to a non-recipient.
8. `make check` green with coverage measured **cold**, at least three
   readings above the gate, and the suites pass **unprivileged** under
   `setpriv --reuid=65534`.
9. `next/docs/progress.md` states Phase 9 item 5(b) as met — which it
   can only say because AC6 landed, not merely AC1 — with the remaining
   frontier named as the phase exit record.
