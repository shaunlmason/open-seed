# Plan: MCP transport wrapper (os-67a1bf14, research/10 §5.4)

The decided v2 transport: MCP **in addition to** the CLI, never a
replacement — a generic wrapper exposes each port verb as an MCP tool
by invoking the same engine service, so harnesses that prefer tools
over shell get schema'd calls for free while the CLI stays the source
of truth (the beads `bd`/`beads-mcp` split). One wrapper serves every
backend, because it sits on the shim side of the port: builtin or
plugin, callers still see one surface, and every guardrail the shim
enforces (verb classes, fencing, HALT) applies unchanged.

## Steps

1. **`seed mcp serve`** (engine, `internal/mcptransport`): an MCP
   server over stdio — JSON-RPC 2.0, `initialize` /
   `notifications/initialized` / `tools/list` / `tools/call`,
   protocol version negotiated, no SDK dependency (the surface is
   four methods). Each port verb is one tool (`task_create`,
   `task_ready`, `task_get`, `task_list`, `task_claim`,
   `task_release`, `task_transition`, `task_close`, `task_comment`,
   `task_attach_evidence`, `task_event_append`, plus `plan_unblock`
   and `mail_*` / `handoff_*` if present by then) with a JSON Schema
   input derived from the same arg surface `verbs.json` declares.
   `tools/call` dispatches through the identical service path the CLI
   uses — same fencing, same transition table, same run-log events,
   same envelopes returned as the tool result content.
2. **Registration surface** (template): `.mcp.json` gains a commented
   `seed` server entry (`scripts/seed mcp serve`) — inert until a
   harness loads it; the handbook documents when to prefer the MCP
   surface (tool-native harnesses, Paperclip's MCP gateway
   governance) and that CI, cron, and bare shells stay on the CLI.
3. **Trust posture, stated**: the MCP surface adds no authority — it
   is the same asserted-identity port; `--actor` remains a tool
   argument, operator verbs still check the roster, and a HALT marker
   refuses mutating tools exactly as it refuses CLI verbs.
4. **Tests** (engine, offline): a JSON-RPC round-trip test speaking
   the wire protocol over pipes — initialize handshake, tools/list
   matches the verb surface (golden), a full card lifecycle
   (create → promote → claim → transition → close) driven purely via
   tools/call against a scratch state ref, error mapping (port exit
   classes → JSON-RPC tool errors carrying the envelope), and a
   HALTed store refusing mutating tools. Engine release +
   `seed upgrade` pin bump in the task PR.

## File Scope

- Engine repo: `internal/mcptransport/` (new), `cmd/seed/`
- Template: `.mcp.json`, `docs/handbook.md`, `.seed/engine.lock`
  (release pin via `seed upgrade`)

## Acceptance Criteria

- `seed mcp serve` completes the MCP handshake and lists one tool per
  port verb with accurate input schemas; a full lifecycle runs via
  `tools/call` with identical envelopes, run-log events, and fencing
  to the CLI path.
- Port error classes surface as structured tool errors (contention,
  invalid transition, fenced out, halted) — never as transport
  failures.
- The CLI remains the source of truth: no verb exists MCP-only, and
  the wrapper contains no coordination logic of its own.
- `.mcp.json` ships the inert registration; the handbook states the
  CLI-first posture and the gateway-governance use case.
