# Plan: paperclip live-server contract test (os-2c0c474c)

The paperclip adapter's contract test runs only against
`testdata/fake-paperclip`: a reimplementation of an API subset the adapter
was written against from documentation, never executed. Plan
`os-e2b3a1f9` step 3 deferred the live run; the README's Testing section
still calls it "documented follow-up work". This card delivers it.

**A probe run against a real instance was executed while planning, and it
does not rubber-stamp the adapter: it falsifies its transport layer.**
`npx paperclipai@2026.817.0 onboard --yes --data-dir <scratch>` came up
headless (embedded Postgres, 210 migrations, `local_trusted`/private on
127.0.0.1:3100, `authReady`), and curl against it surfaced nine drifts
(F1-F9 below), two of which fail silently. So this card is a
reconciliation, not a pin bump: the honest framing the design doc's
honesty-over-polish rule requires. The card's acceptance ("every verb
round-trips against a real Paperclip instance") is retained in full;
this plan states plainly that meeting it means rewriting the adapter's
routes, field names, and bookkeeping substrate, which is more than the
card's title implies.

## Findings the live probe established (evidence, not conjecture)

- **F1 route scope**: single-issue routes are **not** company-scoped.
  The adapter builds every call on
  `$PAPERCLIP_API_URL/api/companies/$COMPANY_ID`; live, `GET` and
  `PATCH` of `/api/companies/{co}/issues/{id}` both return **404**.
  Only the *collection* (`GET|POST /api/companies/{co}/issues`) and
  `goals`/`agents` are company-scoped; `get`, `transition`, `checkout`,
  `release`, `comments`, `documents` all live at `/api/issues/{id}...`.
- **F2 field name, silently**: the field is `status`, not `state`.
  `PATCH /api/issues/{id}` with `{"state":"todo"}` returns **200** and
  changes nothing; with `{"status":"todo"}` it moves. Every adapter
  transition would report success while the issue never moved: the
  worst drift class, because no error surfaces.
- **F3 no issue `metadata`**: the port bookkeeping the adapter stores in
  `metadata` (`seedToken` fence, `blockedOn`, `seedAuthor`, `rejected`)
  has no home. A `metadata` PATCH is accepted and dropped. Live probe
  found a candidate substrate: per-issue documents
  (`PUT|GET /api/issues/{id}/documents/{key}`, requires
  `{format:"markdown", body}`), which carry `latestRevisionNumber` and
  `lockedAt`/`lockedByAgentId`.
- **F4 checkout contract**: `POST /api/issues/{id}/checkout` requires
  `{agentId, expectedStatuses[]}`, not the adapter's `{agent}`.
  `agentId` must be a real agent row UUID
  (`POST /api/companies/{co}/agents`), so the port's free-form
  `--actor` needs an actor-to-agent resolution step. Contention **does**
  return **409** with a holder detail block, as the README promises.
  Checkout sets `status=in_progress` + `assigneeAgentId` but leaves
  `checkoutRunId` **null**, so the "no checkout lock" predicate in
  `ready` cannot read `checkoutRunId`.
- **F5 the platform mutates state underneath the adapter**: seconds
  after checkout the probe issue moved `in_progress -> blocked` on its
  own (heartbeat/watchdog machinery against an agent with no runtime).
  The fake models no such actor; a live suite that ignores this flakes.
- **F6 dependency edges** are `blockedBy`/`blocks` arrays on the issue,
  not the `blockerIds` the fake and the `ready` predicate use.
- **F7 no `/events` route**: `event-append`'s fallback POSTs
  `{base}/events`, which does not exist; the real surface has only
  `/api/heartbeat-runs/{runId}/events` and `/api/cases/{id}/events`.
- **F8 the pin does not exist**: the README claims "the manifest pins
  the tested version", and the card repeats it. `backend.toml` carries
  only the plugin's own `version = "0.1.0"`; there is no upstream
  Paperclip pin in the manifest or `backends.lock.json`.
- **F9 `budget = "native"` granularity is wrong**: the README and
  manifest sell the goal's platform-enforced budget as the native R6
  stop. Live, budgets are company- and agent-scoped
  (`/api/companies/{co}/budgets`, `/api/agents/{id}/budgets`); the goal
  object carries no budget fields at all. The headline capability claim
  needs re-grounding or re-scoping, not restating.

## Steps

1. **Share the corpus, then drive it live.** Factor the assertions in
   `test.sh` into `corpus.sh` and have both suites source it, exactly
   as the beads card (`os-435d7b61`) did, so the fake and live suites
   cannot drift apart silently. Add
   `.seed/backends/paperclip/live-test.sh` running the SAME corpus
   through the adapter against a real instance: all nine required
   verbs, the minted-token fence (rotation, stale-token exit 6),
   checkout contention, checkout-aware `ready`, mandatory goal
   ancestry, server-arbitrated transitions, the reviewer lockout, and
   the cascade on close **and** cancel.
2. **Bootstrap recipe, headless and credential-free.** live-test
   either points at an instance the operator supplies
   (`PAPERCLIP_API_URL` set) or, with `--onboard`, runs
   `npx paperclipai@<pin> onboard --yes --data-dir <scratch>` itself,
   waits on `/api/health`, then creates company, goal, and the agent
   rows F4 requires, and exports the four `requires_env` variables.
   Confirmed during planning: `local_trusted` mode serves the API
   unauthenticated over loopback, so **no browser login, device-code
   flow, or API key is needed** (the bootstrap-CEO invite is required
   only in `authenticated` mode). It self-skips with exit 0 and an
   explicit message when neither an instance nor Node 20+/network is
   available, so `make check` stays green and offline.
3. **Reconcile F1-F7 at the source of truth**, never by tolerating
   drift: adapter routes and payloads where the adapter is wrong
   (F1, F2, F4, F6, F7); `testdata/fake-paperclip` where the fake
   mis-imitates the real server (it must reject unknown status fields
   and company-scoped single-issue routes, or it will keep hiding F1
   and F2). Every fake fix re-runs the offline suite. F2 specifically
   gets a corpus assertion that a transition **verified by re-reading
   the issue** actually moved, so a silently-ignored field can never
   pass again.
4. **Re-home the fence (F3).** Port the `metadata` bookkeeping onto the
   per-issue document store, and while there, establish whether its
   `latestRevisionNumber`/`lockedAt` primitives (plus checkout's
   `expectedStatuses` precondition) permit a true compare-and-swap. If
   they do, narrow or retire the README's declared "check-then-act, not
   atomic" variance; if they do not, keep it and say why. Declared
   either way, never quietly.
5. **Pin and re-ground the claims (F8, F9).** Add a real upstream pin
   (`paperclip_version`) to `backend.toml`, echoed by live-test on
   start; an unpinned version warns rather than refuses, since drift
   discovery is the point. Correct the README's pin sentence, and
   re-ground or re-scope the `budget = "native"` claim to the
   granularity the platform actually enforces: if per-goal hard stops
   do not exist, the manifest capability and the R6 "first backend to
   close it" claim change with it.
6. **Decide the home, and record it where the test lives.**
   Recommendation: mirror beads. `live-test.sh` self-skips and is wired
   into `scripts/validate.sh` after the fake suites, plus a **non-required,
   opt-in** GitHub Actions workflow (`workflow_dispatch` + schedule)
   that pays the full onboard for drift detection. Rationale, recorded
   in the README: the run needs no credentials, but it costs a large
   npm install, an embedded Postgres, and 210 migrations (~90s cold on
   the planning machine), and F5 makes the platform's own background
   machinery a flake source. Neither cost belongs on every PR; neither
   justifies having no live coverage at all.
7. **Evidence and learnings.** The live run is executed in-session and
   its transcript attached to the card; F1-F9 and anything the full
   corpus adds land in `memory/LEARNINGS.md`, and any approach
   abandoned during reconciliation lands in `memory/DEADENDS.md`.

## Acceptance Criteria

- live-test passes the full shared corpus against a real Paperclip
  instance: all nine required verbs round-trip with valid envelopes and
  the same mapped exit codes as the fake (0/2/3/4/5/6), checkout
  contention exits 2 with the holder, and the reaped-then-reclaimed
  same-actor stale token exits 6 natively.
- live-test self-skips with exit 0 and an explicit message when no
  instance and no onboard path is available; `make check` stays green
  and offline on a machine with neither.
- Every drift F1-F7 is fixed at its source of truth and covered by the
  offline suite; a transition asserted only by response status can no
  longer pass (F2 has a re-read assertion).
- The fence's storage substrate and its atomicity are declared in the
  README against what the live server actually provides (F3, F4).
- `backend.toml` carries the validated upstream Paperclip pin, echoed
  by live-test; the README's pin sentence matches reality (F8).
- The `budget = "native"` claim in manifest and README matches the
  granularity the platform enforces, or is re-scoped with the R6 claim
  adjusted to match (F9).
- The CI-vs-manual decision and its rationale are recorded where the
  test lives; remaining version-specific variances are declared in the
  README, none discovered later.
- filecards and beads behavior unchanged; `sh scripts/validate.sh`
  fully green.
