# Plan: next Phase 8.2 — affordance regression class (os-148d3ba1)

Implements `docs/next-build-plan.md` Phase 8 item 2: "Regression
test class: affordance-listed verb refused for legality at the same
position = bug." Design authority: SEED-NEXT.md §II.10 (one rule
set, two consumers, zero drift by construction) and charter III.I
row 2 ("an affordance-listed verb refused at admission for legality
(absent a concurrent event, detectable via the position stamp) is a
bug class with a regression test"). Builds on merged 8.1
(`next/internal/admit/affordances.go`, #160): `admit.Affordances`
already computes by running every catalog probe through the
enforcing `admit.Check`, and the walk
(`TestAffordancesWalk`) pins curated stations. This task makes the
bug class *executable as a class*: a harness that sweeps every
position of a scenario ledger for a defined actor/subject matrix
and fails on any listed-verb-refused divergence, plus the CLI drill
pinning the position stamp that makes concurrent events detectable.

## Design decisions (binding for this task)

- **D1 — the class is a sweeping harness in the admit package, not
  more curated stations.** A test-file helper (unexported;
  `next/internal/admit/soundness_test.go`) takes a fully built
  scenario ledger and asserts, at **every prefix position** and for
  **every pair in the actor/subject matrix**: (a) `Affordances`
  computes without panic; (b) the output is sorted, deduplicated,
  and **deterministic** (two computations at the same position are
  identical — map-iteration or time-derived nondeterminism is the
  drift seed the class exists to catch); (c) for every listed verb,
  an independently drafted record for that verb — same synthesizer
  table, same probe-view derivation, same timestamp, signed by the
  same key — admits through `admit.Check` at that position. Any
  refusal fails with the class named: position, actor, subject,
  verb, and the refusal, so a future report reads as the charter's
  bug class and not a generic assert. Today (c) holds by
  construction (the computation *is* the probe run); the harness
  pins the construction so any later split — caching, memoization,
  a parallel legality derivation, a rule consulted by one consumer
  and not the other — fails a named regression class rather than
  drifting silently. That is what "regression test class" means
  here: the executable definition, kept passing.
- **D2 — the corpus is the walk's own scenario, replayed
  prefix-by-prefix, not a second hand-built history.** The walk
  already drives one chain through birth, enrollment, offer, claim,
  plan, budget reserve, run start/interrupt/settle, submission,
  seal, verdict pass and fail, merge, return, block, cancel, and
  halt/lift — the richest admitted history in the tree. Extract its
  append script into a shared builder (`walkScenario(t)` returning
  the store, the named keys, and the subjects touched) consumed by
  both `TestAffordancesWalk` (unchanged assertions) and the new
  sweep, so there is exactly one scenario and two consumers of it —
  the same shape as the rule set itself. Prefix contexts come from
  replaying the recorded append script into a fresh store one event
  at a time and calling `ContextAt` after each append (the script
  is a list of signed records; re-appending a prefix is cheap and
  keeps `ContextAt` the only context constructor, per its seam).
  Anomaly-bearing prefixes (dangling fences, duplicate settles)
  cannot arise here because every prefix of an admitted history is
  an admitted history; fold-level anomaly robustness stays covered
  by the existing fold tests and is out of scope.
- **D3 — the matrix is bounded to keep the sweep inside the fast
  gate.** Full cross-product (every enrolled key × every subject ×
  every prefix × every catalog verb × two determinism runs) is
  quadratic-ish and pointless: most cells repeat the same refusal.
  Binding bound: at every prefix, sweep the canonical pairs
  {root × system, root × c-1, holder × c-1, supervisor × c-1,
  verifier × c-1, sealer × c-1, observer × c-1} — every enrolled
  lane the scenario exercises. (Review finding on this PR: the
  walk's curated stations assert selected presence and absence,
  never re-draft-and-check of every returned verb, so a lane left
  out of the matrix — supervisor-only offer and run verbs,
  sealer-only check.sealed — could drift into exactly the
  refused-listed bug without failing anything; curated stations are
  not class coverage, so the matrix carries every lane itself.)
  Cross-subject pairs beyond c-1 and system stay out: the
  scenario's legality state lives there, and foreign-subject
  honesty is the placeholder-refusal design already pinned by the
  walk. If the sweep exceeds roughly five seconds locally, halve
  by sweeping every prefix for {root × c-1, holder × c-1} and every
  *third* prefix for the rest; record the final bound in the test's
  header comment. Never trim the per-position verb set — the class
  quantifies over every listed verb.
- **D4 — the position stamp is pinned end to end at the CLI.** The
  charter's "absent a concurrent event, detectable via the position
  stamp" only works if the stamped `position` and the stamped
  `affordances` agree — an envelope whose list was computed at a
  different position than it claims makes divergence undetectable.
  Drill (extends `next/cmd/seed/affordances_cli_test.go`): run an
  append, parse the envelope, then independently open the same
  ledger, build `ContextAt`, assert the stamped `position` equals
  the context's tip ordinal — `ctx.Count - 1`, since `ContextAt`
  counts records while `stampTip` stamps the zero-based tip
  position (review finding on this PR caught the off-by-one in
  this plan's first draft) — and assert `admit.Affordances` at
  that context equals the stamped list byte for byte. One success path
  and one refusal path (refusal envelopes stamp too, per 8.1).
- **D5 — no production surface changes.** The class is tests plus,
  at most, test-file helpers. If the sweep finds a real divergence
  (a synthesizer bug, a nondeterminism), the fix lands in this task
  scoped to the smallest production change that restores the
  property, recorded in decisions.md; nothing else moves. The
  refusal-rate metric is 8.3's card; lesson surfacing in envelopes
  is Phase 11's.

## Steps

1. Extract the walk's append script into `walkScenario(t)` in
   `next/internal/admit/affordances_test.go` (or a shared
   scenario_test.go if cleaner), returning the replayable script,
   keys, and subjects; keep `TestAffordancesWalk` green and
   byte-identical in its assertions.
2. Add `next/internal/admit/soundness_test.go`: the sweep
   (`TestAffordanceRegressionClass`) per D1–D3, with the class
   named in every failure message.
3. Extend `next/cmd/seed/affordances_cli_test.go` with the D4
   position-agreement drill (success and refusal envelopes).
4. Update `next/docs/progress.md` (Phase 8 item 2 done, frontier)
   and `next/docs/decisions.md` (bounds chosen, anything the sweep
   surfaced).
5. Receipt, evidence, review.

## Acceptance Criteria

- The sweep visits every prefix position of the shared scenario and
  every D3 matrix pair, asserts determinism and sortedness, and
  re-admits every listed verb through the enforcing `Check`; any
  divergence fails naming the class (position, actor, subject,
  verb, refusal).
- The walk still passes with identical assertions against the
  extracted scenario (one scenario, two consumers).
- The CLI drill proves stamped position and stamped list agree with
  an independent recomputation at that position, on a success and
  on a refusal envelope.
- `make check` green, coverage gate ≥90% held.
