# Plan: next — the flywheel engine drill skips before it builds, and its fixture is hardened (os-222189a3)

`TestValidationRunsThroughTheEngineFromAStagingWorktree`
(`next/internal/flywheel/flywheel_test.go`) failed on #290's `platform
(macos-latest)` leg (run 33815519050) without running a single
assertion: the drill skips by name when the pinned v1 engine is not
in the runner's bootstrap cache (`requireEngine`, plans/os-9075c308.md
D3), and the skip then failed on the harness's own cleanup, `TempDir
RemoveAll cleanup: unlinkat .../001/.git/objects: directory not
empty`. A skipped drill reported as a failure, on a PR that touches
neither the drill nor the fixture, is exactly the flake class
plans/os-c4e8b57a.md removed from the tree: a git repository built
under a `t.TempDir` that a git process can still be writing when the
harness removes it. Tests only. Tier: trivial. Deps: none.

## What the tree actually shows

- **The skip path builds first and asks second.** The drill's first
  three statements are `fixtureRepo(t)` (a repository at three
  commits), `instantiate(t, repo)` (the `.seed` tree and the shim
  copied in and committed) and only then `requireEngine(t, repo)`.
  On a runner without the engine, twelve git processes build a
  repository that the skip abandons the same instant, and the
  cleanup that follows is the one place the race can bite.
- **The engine check needs nothing the fixture has.** `EnginePath`
  reads `scripts/seed` and `.seed/engine.lock` from the repository it
  is handed and resolves the pin against `SEED_ENGINE` or the cache.
  `instantiate` copies both files verbatim from the source tree
  (`../../..`), so the source tree answers the question identically,
  before anything is built.
- **The fixture escaped the hardening guard by its helper's name.**
  os-c4e8b57a's guard (`internal/gitref/fixture_guard_test.go`) holds
  every repository-creating call in `next/**` tests to a
  `hardenGitRepo` on the next lines, matching the shapes
  `exec.Command("git"`, `git(`, `run(` and `gitOut(`. The flywheel
  package's helper is `gitIn`, which none of those match, so
  `fixtureRepo`'s `init` was never held to the property and writes no
  `gc.auto`, `gc.autoDetach` or `receive.autoGC`. The importer package
  uses the same helper name at four sites; all four are hardened.
- **Which process was still writing is not established.** The fixture
  holds about a hundred loose objects, far under `gc.auto`'s default
  threshold, so a detached auto-gc is unlikely on this path, and the
  runner is gone. The plan does not depend on naming it: the skip
  path stops building anything, and the fixture stops being the one
  repository in the tree that can detach a writer.

## Design decisions (binding for this task)

- **D1 — the skip decides before anything is built.** `requireEngine`
  takes no repository: it resolves the engine from the source tree
  at `../../..`, the tree whose shim and lock `instantiate` copies,
  and the drill calls it as its first statement. A runner without
  the engine skips having made no `t.TempDir` and spawned no git.
  After `instantiate`, the drill asserts that the copy resolves the
  engine as well (`EngineAvailable(repo)`), as a `t.Fatalf` rather
  than a skip: the copy is byte-identical, so a difference is a
  broken fixture, not an absent engine, and the drill's claim stays
  about the engine the shim would exec.
- **D2 — the fixture is hardened like every other.** `fixtureRepo`
  calls a package-local `hardenGitRepo(t, repo)` immediately after
  `init --quiet` and before the first object, writing `gc.auto=0`,
  `gc.autoDetach=false` and `receive.autoGC=false` into the
  repository's own config with `git config` (written, never passed
  as `-c`, per os-c4e8b57a D1). The two other drills that build the
  fixture inherit it.
- **D3 — the guard learns the helper's name.** `creates` in
  `fixture_guard_test.go` gains `gitIn(` beside `git(`, `run(` and
  `gitOut(`, so a helper named that way cannot escape the property
  again. The four importer sites it newly matches are already
  hardened; the flywheel site is hardened by D2; `minimumSites` stays
  the floor it is. With D2 reverted the guard names
  `internal/flywheel/flywheel_test.go` at the `init` line, which is
  the mutation the PR shows.
- **D4 — bounds.** No production file changes; no assertion, timing
  or scenario in the drill changes beyond the order of its first
  statements and the added copy check; the skip's reason text is
  unchanged; `TestEngineAvailabilityIsDetected` is untouched; the
  importer's tests are untouched.
