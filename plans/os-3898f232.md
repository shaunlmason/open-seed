# Plan: next Phase 2.1 — admission rule set library (os-3898f232)

Implements [`docs/next-build-plan.md`](../docs/next-build-plan.md) Phase 2
item 1: the validation rule set as a pure library (`internal/admit`).
Design authority: [`SEED-NEXT.md`](../SEED-NEXT.md) Part II (admission
boundary) and the Phase 2 binding default that **one rule set** is
importable by the client (2.2), the `pre-receive` hook (2.3), and later
the forge service (Phase 12) — postures differ in *where* the rules run,
never in *which* rules run. This task builds the composition seam and the
rules that exist so far: signature-vs-governance-root, event shape, halt,
protocol version, classification. Capability rules slot in at Phase 3,
fences at Phase 5, reservations at Phase 7, as added rules, not rework
(the build plan's own wording); the package documents those seams
honestly instead of faking them.

## Steps

1. **The context, built by one replay.** `admit.Context` carries what
   every rule may consult: the verified prefix (count, tip, active
   protocol version from `ledger.Report`), the projected halt state
   (`halt.StateAt`), the resolver (genesis governance root via
   `genesis.Bootstrap` until the Phase 3 keyring projection replaces it),
   and the supported-version set. `admit.ContextAt(store, opts...)`
   builds it with a single `VerifyFromGenesis` replay: admission never
   grows a chain that does not verify, and rules stay pure functions of
   (context, proposed record). Feeding the halt projection from that same
   replay needs one small ledger addition: a `WithObserver` VerifyOption
   whose callback receives each record after it fully verifies (in
   order, exactly once, never past a failure), so context construction
   does not re-scan the store.
2. **The rule type and the set.** `type Rule struct { Name string; Check
   func(*Context, *event.Record) error }`. `Default()` returns the
   ordered Phase 2 set: `halted` (refusal dominates, the #84 review
   ordering), `shape` (event invariants, halt verb schemas via
   `halt.ValidateShape`, and the `system.protocol.upgraded` schema:
   subject `system` and a payload naming a non-empty `to`, extracted to
   `ledger.ValidateUpgradeShape` so the verifier and the admission set
   share one definition — a signed but schema-broken upgrade admitted to
   the chain would wedge every later verification at `bad_payload`),
   `actor` (the proposed signer resolves and the
   signature verifies against the resolved key), `version` (the event
   carries the context's active version, and that version is in the
   supported set), `classification` (`classify.Lint` on the payload,
   pointers preserved). Later phases append rules; nothing here is
   rewritten.
3. **The composition point.** `admit.Check(ctx, rec) error` runs the set
   in order and returns the first refusal wrapped in a typed
   `admit.Refusal{Rule string; Err error}` that `errors.As`/`errors.Is`
   unwraps to the underlying typed error, so the envelope layer keeps its
   exit mapping (halted 7, chain 8, classification 9, version 10) and the
   refusing rule is attributable by name. `admit.Validate(store, opts...)
   gitref.Validate`-shaped adapter: the closure 2.2 hands to
   `AppendLoop` and 2.3 embeds in the hook, both importing this one
   symbol.
4. **Tests** (conformance III.B, the subset that exists): a table of
   hostile drafts where each rule is the one that refuses (halted
   non-lift, malformed lift, unresolvable actor, forged signature, wrong
   version after an upgrade event, unsupported active version,
   classification-hostile payload, an upgrade event missing or emptying
   `to`, an off-system upgrade subject) and a clean draft passes the
   whole set; refusals unwrap to their typed errors; the halted refusal
   dominates a malformed forbidden draft; a synthetic "phase-3 rule"
   appended to the set runs without any change to the default rules
   (the added-not-reworked seam, pinned); `ContextAt` refuses a
   non-verifying store rather than building a context over it.

## Acceptance Criteria

**Boundary set (new, shown working):**

- One `Default()` rule set exists; client and hook postures import it
  unchanged (the adapter is the only composition point) — no posture
  re-derives or forks a rule.
- Every refusal names its rule and unwraps to the underlying typed error;
  exit-code mapping is preserved end to end (asserted through the
  existing envelope constants).
- The halted refusal dominates shape refusals for forbidden drafts,
  matching `halt.Check`'s reviewed ordering.
- `ContextAt` performs exactly one replay and refuses to build over a
  chain that fails verification.
- Appending a new rule requires no edit to existing rules (pinned by
  test).

**Retention set (existing, shown unharmed):**

- `internal/halt`, `internal/classify`, `internal/ledger`,
  `internal/event`, and CLI suites pass unchanged
  (`cd next && go test ./internal/... ./cmd/... -count=1`).
- The repo-wide gate stays green with the ≥90% coverage gate
  (`make check`).
