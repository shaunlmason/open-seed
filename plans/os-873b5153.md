# Plan: the interleaving explorer over reconciliation and racing (os-873b5153)

Implements card os-873b5153, the follow-on `plans/os-07e6e76c.md` D7
named and deferred until that explorer's shape was known (#359 settled
it). Design authority: SEED-NEXT.md §II.8 (done is a verdict AND a
reconciliation across two systems that share no transaction, with
divergence a first-class detected state) and §II.6 racing mode
(duplicate execution tolerated, first verified success settles). No
Part III row changes.

The sibling built a state machine whose alphabet is the append loop's
own steps, walked depth-first over every interleaving for small N with
memoization, properties checked at every state, and its terminal traces
replayed through real clients so the model is evidence about the tree
rather than about itself. This card points that discipline at two more
state spaces.

**The card's central property is wrong as written, and this plan
corrects it.** The card says "every class in `internal/reconcile` must
be reachable by some interleaving". Reading the package, its
seventeen-odd classes split three ways, and only one group is reachable
through admitted history:

- **Fold-derivable** (`reconcile.Subject` over one `SubjectState`):
  `merge_without_verdict`, `chain_skipped`, `unreconciled`,
  `overridden`, `unsealed`. These are reachable by an interleaving of
  admitted events, and they are this card's target.
- **Keyring-verified** (`VerifyVerdicts`, `VerifySeals`,
  `VerifyOverrides`): `verdict_unverified`, `seal_unverified`,
  `override_unverified`. These exist to catch **raw-pushed** history,
  and admission refuses to launder exactly them: `launderedVerdict`
  and `verdictBoundary` in `internal/admit` refuse an admitted
  `merge.requested` or `merge.observed` built on a verdict that never
  passed the verifier boundary. So they are **unreachable through any
  admitted interleaving, by design**, and their unreachability is
  itself the property worth asserting rather than a coverage gap to
  close.
- **Evidence-grade** (`Evidence`, `EvidenceAt`, `Lessons`,
  `ScorecardAt`, `LessonsStale`): `evidence_missing`,
  `attested_divergence`, `target_rewritten`,
  `independence_unverified`, `scorecard_unverified`,
  `lesson_unverified`, `lesson_stale`. These need an artifact store and
  a git repository, which a ledger interleaving does not produce. Out
  of scope, and the plan says so rather than leaving a silent hole.

`run_unsettled` is a fourth case: consumed from `internal/obligation`
rather than derived here, so it is that projection's to reach.

## Design decisions (binding for this task)

- **D1: reuse the sibling's explorer by extracting it, not by copying
  it.** `next/internal/gitref/interleave_test.go` carries a depth-first
  walker with memoization on a state key, a per-state property hook and
  a terminal-state hook. That shape is generic; only the alphabet and
  the properties are not. Extract the walk into
  `next/internal/explore` (non-test, since three packages import it) as
  a small generic driver over an interface a caller implements:
  `Key() string`, `Enabled() []Step`, `Apply(Step) State`,
  `Terminal() bool`. The gitref model moves onto it with its assertions
  byte-identical, which is the regression test that the extraction
  changed nothing. One instrument to keep honest beats three copies
  drifting apart, and the sibling already proved the shape; the cost is
  one new internal package on the trust surface, which is why it stays
  dependency-free and test-only in behavior.
- **D2: the reconciliation alphabet, and the forge as a process.**
  Steps: `verdict(w, pass|fail)`, `request(w)`, `observe(w)`, and the
  forge's own `merge`, `refuse` and `force_push`, each enabled
  independently so the forge moves on its own schedule rather than in
  lockstep with the ledger. The forge is a process with steps, not an
  oracle the model consults: making it an oracle would assume the very
  atomicity §II.8 says does not exist, and the classes this card exists
  to reach (`chain_skipped`, `merge_without_verdict`) are precisely
  what a forge moving on its own produces. Model state: the fold's
  relevant facts for one contract (verdict, requested, merged,
  override, sealed, tier) plus the forge's head and whether it merged.
- **D3: the reconciliation properties, stated in both directions.**
  (P1) *Reachability, fold-derivable only*: each of the five
  fold-derivable classes is produced by at least one terminal state of
  the enumeration. A class nothing can produce is dead code pretending
  to be a guard, and the failure names the class.
  (P2) *Completeness*: every terminal state whose chain is not clean is
  classified by `reconcile.Classify`, and every finding it returns
  carries one of the classes the vocabulary names. An interleaving
  producing an unclassified divergence is a hole in the vocabulary; an
  unknown class string is drift between the classifier and its own
  constants.
  (P3) *Admission closes the laundering path*: for every interleaving
  where a verdict was rendered by a key that fails the verifier
  boundary, no `merge.requested` or `merge.observed` admits. This is
  the honest statement of why the keyring-verified classes are
  unreachable here: they are the raw-push residual, and this property
  asserts the front door is shut rather than asserting the class is
  dead.
  (P4) *No done without an authentic pass or a cited override*: no
  terminal state reaches `done` with neither.
- **D4: the racing alphabet and properties.** Steps: `claim(w)`,
  `submit(w)`, `verdict(w, pass|fail)`, `observe` (the settlement),
  `exit(w, released|parked)`, and the maintenance `reap`. State: the
  declared cap, the active claims by fence, the submissions and
  verdicts by fence, and `RaceSettled`. Properties: the cap is never
  exceeded; exactly one settlement occurs; after settlement a
  settled-out racer's act refuses with `RaceSettledError` while its own
  deliberate exit still admits (the asymmetry `internal/admit`'s
  `race_settled` rule encodes); and the reaper leaves no active claim
  of a settled race, with a packet naming the settlement.
- **D5: replay, and where it stops.** Both models replay their terminal
  traces through `admit.Check` against a real staged ledger, as the
  sibling replays through `Fetch` and `attempt`: every step's outcome
  class asserted by admission's own typed errors
  (`RaceSettledError`, the verdict and chain errors), and the final
  chain's `reconcile.Classify` findings compared to the model's
  prediction, class for class. The forge steps have no ledger
  counterpart to replay, by construction: they are the other system,
  and their effect enters the ledger only as `merge.observed`, which
  the replay does admit. Say this in the test rather than leaving the
  asymmetry to be discovered.
- **D6: two models, one package each, both in the external test
  package.** The reconciliation model lives in
  `next/internal/reconcile` and the racing model in
  `next/internal/maintain`, each as `_test.go` in the `_test` package,
  since both consume `internal/admit` for the replay and `admit`
  imports neither. Where either needs an unexported fixture, the
  `export_test.go` shim from os-21bf939f is the pattern.
- **D7: sizes on the perf-storm split.** The fast gate runs the
  configurations that keep the whole addition under roughly five
  seconds locally, measured and recorded in the test header and in
  `next/docs/decisions.md`; the larger enumerations join the weekly
  `perf-scale.yml` step beside the walker's and the append loop's.
  `.github/**` is a protected path: the task PR's review is the
  decision it requires, with #297, #353 and #359 as precedent.
- **D8: no production surface changes, with one named exception.**
  `internal/explore` is new and is production code by location, though
  nothing outside tests calls it; that is D1's deliberate cost and the
  only such addition. Otherwise, if a model finds a real divergence,
  the fix lands in this task scoped to the smallest production change
  that restores the property, recorded in `next/docs/decisions.md` with
  the trace kept as a named regression. If the enumeration shows a
  fold-derivable class is genuinely unreachable, that is a finding
  about the classifier, not a test to weaken: report it, and let the
  plan's reviewer decide whether the class or the model is wrong.

## Steps

1. Extract the sibling's walker into `next/internal/explore` and move
   the gitref model onto it with its assertions unchanged (D1).
2. Add the reconciliation model and its four properties (D2, D3), with
   the class split from this plan's preamble encoded as three named
   sets so a class added to `internal/reconcile` and to no set fails
   the test.
3. Add the racing model and its properties (D4).
4. Add both replays (D5, D6).
5. Measure, set the fast-gate sizes, and append the scheduled step to
   `.github/workflows/perf-scale.yml` (D7).
6. Update `next/docs/progress.md` and `next/docs/decisions.md` (the
   class split, the sizes, what the enumerations found, and the card's
   corrected property). Append learnings to `memory/LEARNINGS.md`.
7. Receipt, evidence, review.

## Acceptance Criteria

- The gitref model runs on the extracted walker with assertions
  unchanged and stays green.
- The reconciliation enumeration produces every fold-derivable class
  (P1), classifies every unclean terminal state with a known class
  (P2), admits no laundered merge step (P3), and reaches `done` only
  behind an authentic pass or a cited override (P4). The three class
  sets are exhaustive over `internal/reconcile`'s constants: a class in
  none of them fails the test.
- The racing enumeration holds the cap, exactly one settlement, the
  settled-out asymmetry, and the reaper's completeness.
- Both replays drive their traces through `admit.Check` and agree with
  the model on every step's outcome class and on the final findings.
- The fast gate stays inside the measured bound;
  `perf-scale.yml` carries the scheduled sizes.
- `make check` green, coverage gate ≥90% held.
