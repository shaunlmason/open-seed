# os-465e356e — Phase 12 item 1: the compromised-actor drill, the release gate

Build plan Phase 12 item 1. A red-team harness plays the charter's §I.2
adversary against a fixture deployment in **enforced** mode and asserts the
invariant's ceiling clause by clause. The charter calls this drill "the
architecture's definition of done"; the build plan calls it the release gate
and requires it green in CI from here on, and promotion (§5) requires it.

## What the tree actually shows

**The adversary's powers already exist in the tree, separately.** Three
suites already play a hostile lane, and each answers one question:

- the dispatcher's injection suite ([`lanes.md`](../next/spec/lanes.md)) asks
  what a *persuaded* lane can do with its own grants, deriving the reachable
  set from `admit.Affordances` and naming residuals;
- the curator poisoning drill ([`curation.md`](../next/spec/curation.md)) asks
  what constructed evidence can achieve, scripting each poison to a promotion
  attempt and asserting it fails at both ends;
- the trajectory-prefix harness ([`trajectories.md`](../next/spec/trajectories.md))
  asks whether a recorded decision still stands under today's configuration.

None of them asks §I.2's question, which is narrower and harder: with a
**valid key**, a **valid credential** and **arbitrary git**, against a remote
that enforces, what enters authoritative history? Every existing suite drives
the boundary in-process, so each proves what `admit.Check` refuses, never what
a *push* is refused. That gap is this card's subject.

**Nothing in the tree enforces on the server.** `posture` names
`enforced-self-hosted` (the charter's reference deployment: a server-side
receive hook on the ledger ref) and `enforced-forge-hosted`, and
`gitref.ErrRemoteRejected` exists for "a `pre-receive` policy hook declining".
No such hook ships. Every drill that says "raw seam" today means a library
append that skips the rule set, on a remote that would have taken it. So the
fixture this drill needs does not exist, and the drill cannot be written
against a promise.

**The bare-remote fixture does exist** (`bareRemote`, `hardenGitRepo`,
`seedRemoteGenesis` in `cmd/seed`), and the CLI's remote path already pushes
through `gitref` with optimistic retry, so the adversary's transport is
already drilled from the honest side.

## Design decisions (binding for this task)

**D1. This card ships the reference enforced posture: a `pre-receive` hook.**
The drill needs a remote that refuses, and the charter's reference deployment
is "a git server-side receive hook on the ledger ref". `seed hook pre-receive`
reads the hook protocol on stdin (`<old> <new> <ref>` lines), and for the
ledger ref replays every event the push adds through the same
`admit.Check` the CLI runs, over the *old* tip's context, refusing the whole
push on the first refusal with the structured reason on stderr. It refuses
outright: a non-fast-forward update, a deletion, and any push that touches
the ledger ref with a commit whose events do not verify from genesis. The hook
holds no durable state (`§II.2`'s "stateless validator": everything is derived
from the ledger it already has plus the pushed objects), so a replacement
instance rebuilds from the clone. Refused: teaching the hook a second rule
set, or letting it admit what the CLI would refuse — one derivation, two
callers, pinned by a drill that runs the same corpus both ways.

**D2. The adversary is a process, not a mock.** The harness holds a real
enrolled key, a real credential (filesystem write access to the bare remote's
work path is the fixture's stand-in for a forge credential), and runs `git`
directly. It never calls the honest CLI to perform an attack: an attack that
goes through `seed claim take` proves the client refuses, which is not the
claim. Forged events are signed with the compromised key and pushed with
`git push`, so the only thing between the attacker and the ref is the hook.

**D3. The corpus is declarative and derived from the ceiling.** §I.2's ceiling
is eight prohibitions ("cannot claim unauthorized work, approve itself,
rewrite history, alter gates, impersonate another actor, exceed its lease,
cause an invalid state transition to enter authoritative history" and, from
§9, "spend beyond reservation") and four permissions ("can spend only its
reserved budget; modify only its authorized code surface; produce signed lies
attributed to itself; submit work for independent verification").
`next/internal/redteam/testdata/ceiling.json` names all twelve clauses with
the charter's own words; the corpus names, per attack, the clause it attacks
and the refusal it must meet. Coverage is derived from the clause list and
pinned **both ways**: a clause with no attack fails, an attack naming no
clause fails.

**D4. The four permissions are asserted too, and this is not decoration.** A
harness that only asserts refusals passes trivially against a remote that
refuses everything. Each permission is asserted as an admitted push: the
attacker spends inside its reservation, pushes its own code branch, appends a
signed lie *attributed to itself* (a dead end recording something false, which
is evidence, not conclusion), and submits for verification. The drill fails if
any of these is refused.

**D5. What the drill proves is bounded, and the bound is stated.** The hook
proves the enforced-self-hosted posture. Cooperative mode is out of scope by
construction (the charter already names its consequence), and
enforced-forge-hosted is Phase 12 item 2's admission service; the drill's spec
says so, and the residual table carries "the drill's fixture is one posture".
Refused: a drill that runs in cooperative mode and reports green, which would
assert the opposite of what the charter says holds there.

**D6. Residuals are named, not hidden.** Where the adversary succeeds within
the ceiling, the success is a named residual with why, what it can inflict and
what stands in the way, each pinned by a characterization drill asserting the
attack IS admitted — the shape both landed suites use. The starting set: the
signed lie (attribution is not trust), self-directed budget exhaustion inside
its own reservation, refusal-flooding the remote (denial of progress, not of
authority), and the one-posture bound from D5.

**D7. The gate is `make check`, and CI runs it already.** The drill is a Go
test under `next/`, so the existing `check` job runs it; no workflow file
changes. The build plan's "runs in CI from here on" is met by the drill living
where `make check` looks, and by `lanes.md` recording III.O's drill row as met.
Refused: a separate workflow job, which would let the release gate be skipped
by a path the rest of the suite does not take.

## Acceptance Criteria

**Boundary set (new, shown working):**

1. **The hook enforces.** A push whose events all admit is accepted; a push
   carrying one refusable event is refused whole, with the boundary's own
   reason on stderr and nothing written to the ref; a force-update and a
   deletion of the ledger ref are refused outright; a push touching another
   ref is untouched by the hook.
2. **The ceiling, clause by clause.** Every one of the eight prohibitions has
   at least one attack, run by the adversary with its own key and raw git
   against the enforced fixture, and each is refused at the push: an
   unauthorized claim, a self-approval, a history rewrite, a gate
   modification, an impersonation, an over-lease act, an invalid transition,
   and a spend beyond reservation.
3. **The permissions, asserted.** Each of the four is an admitted push under
   the same fixture and the same key.
4. **Coverage both ways.** A clause with no attack fails the drill; an attack
   naming no clause fails it; an empty corpus fails it.
5. **One derivation.** The same corpus run through `admit.Check` in-process
   and through the hook over a real push yields the same verdict for every
   entry.
6. **The residuals** are named in `residuals.json` with why, the inflictable
   consequence and what stands in the way, each pinned by a drill asserting
   the attack is admitted; an unnamed admitted attack fails, and a named one
   the corpus cannot reach fails as stale.
7. **Mutation evidence.** Each must fail a drill: the hook admitting on
   refusal; the hook checking only the first pushed commit; the hook allowing
   a force-update; the hook allowing a deletion; the hook reading the new tip
   instead of the old for its context; the ceiling read from the corpus
   instead of the charter table; the permissions arm dropped; a residual
   dropped; the drill running in cooperative mode.
8. `make check` green with coverage measured **cold**, at least three readings
   above the gate, and the suites pass **unprivileged**.

**Retention set (existing, shown unharmed):**

- The CLI's remote path is unchanged: `gitref`'s optimistic retry, the
  refusal mapping and every existing remote drill pass as before, and the
  honest fixtures that push without a hook keep pushing.
- No new verb, transition row, capability or protocol version; every
  pre-existing chain verifies byte for byte; the projections' builds are
  byte-identical on chains this card does not create.
- The three landed adversarial suites are untouched and still green.
