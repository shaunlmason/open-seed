## What the tree actually shows

- **The contract is public and one adapter implements it.** Package
  `next/executor` (`Adapter`: `Provision`, `Wake`, `Tuple`; `Run`:
  `Workspace`, `Tuple`, `Meter`, `Dispose`) and `LocalWorktree`, the
  detached-git-worktree adapter (`harness: local-worktree/v0`,
  `environment: detached-git-worktree`), which resolves the two fields
  it controls and takes the three it cannot know from the admitted
  `run.started`. `Provision` refuses without an admitted start for
  the fence and refuses `ErrTupleMismatch` with full rollback when
  the resolved tuple differs from the declared one
  (`next/spec/executors.md`, `qualification.md`).
- **`seed run start --adapter` knows one name.** `startAdapter` in
  `next/cmd/seed/run.go` resolves `local-worktree` and refuses every
  other word; the verb fills `harness` and `environment` from the
  adapter's static report and takes `--principal`, `--model` and
  `--tool-policy` from the caller.
- **The spend bracket, disposability and preemption are drilled once,
  through the local adapter**: `TestDisposabilityDrill` (a SIGKILLed
  worker after an admitted sync; the loss window exactly the lines
  after it), `TestGracefulPreemptionDrill` and
  `TestForcePreemptionDrill` (`next/cmd/seed/run_cli_test.go`,
  `preempt_cli_test.go`), `TestRunStartDeclaresTheTupleAndDriftIsOutOfGrant`.
- **The report has no per-adapter surface.** `report.go` names "the
  per-adapter risk-limit surface arrives with 7.3's adapters" and
  carries nothing yet; the doctor says nothing about executors; the
  declaration (`internal/posture`) has no executors block.
- **No coordination path needs inbound connectivity** (§II.9): every
  adapter must keep that — a remote worker pulls.

## Design decisions (binding for this task)

**D1. Three adapters, one public interface, unchanged.** `Container`,
`CloudSession` and `RemoteWorker` implement `executor.Adapter` and
`executor.Run` as `LocalWorktree` does; no method is added to the
public interface (external implementers are not broken). Each resolves
all five tuple fields: `harness` is the adapter's versioned name
(`container/v0`, `cloud-session/v0`, `remote-worker/v0`);
`environment` is what the substrate reports (the image digest, the
session's provider-reported runtime, the worker's enrolled environment
string); `principal`, `model` and `tool_policy` come from the admitted
`run.started` the provision cites and are checked, never invented. A
provision whose substrate resolves anything else refuses
`ErrTupleMismatch` with full rollback, inheriting the local adapter's
check. Refused: a fourth substrate (the ephemeral VM the charter lists
is the cloud session's shape and is not a separate adapter here); a
change to the spend bracket's verbs.

**D2. Every adapter states its budget posture, honestly.** An optional
interface `executor.Described` (`Describe() Description{Name, Harness,
Budget, Reason}`) — optional so the public interface stays what it is
— reports whether the substrate can stop spend synchronously
(`Budget: "enforced"`: local worktree and container, which the
supervisor kills) or cannot (`Budget: "risk-limit"`: cloud session and
remote worker, where a provider or a remote process may spend past the
reservation before the interrupt lands), with the reason in one
sentence. `seed doctor` lists every adapter this build provisions
through with its posture; `report.json` gains `adapters`: per adapter
the runs started under its harness and its budget posture, derived
from the `run.started` tuples the fold holds. Refused: a cloud or
remote adapter claiming enforcement; a report that averages the two
postures.

**D3. Substrate configuration is declared, credentials are named,
never held.** The declaration gains a strict `executors` block:
`container: {"runtime": "docker"|"podman"|"fake", "image": "<ref>"}`,
`cloud: {"endpoint": "<url>", "credential": "<env var name>"}`,
`remote: {"workers": [{"name", "environment"}]}`. A credential is the
NAME of an environment variable the process reads at provision time;
the file never carries a secret and the lint refuses a value that looks
like one (a token-shaped string). `seed run start --adapter
<container|cloud-session|remote-worker>` reads the block; an
undeclared block refuses the adapter by name. Refused: a secret in the
declaration; an adapter that reaches a credential the CLI would not
(the same env var, the same file — nothing more).

**D4. The container adapter runs credential-free in CI.** Provision
creates the local worktree (the same detached worktree the local
adapter builds) and starts a container with it bind-mounted at a
fixed path, through an OCI runtime found on PATH (`docker` or
`podman`, fixed argument vectors, nothing interpolated into a shell);
where no runtime is on PATH the declared `fake` runtime provisions
through `executor/fakeoci`, an in-process implementation of the same
contract (start, inspect for the image digest, stop, remove) whose
drills are the adapter's drills, and the run's `environment` says
`fake-oci:<digest>` so a report never mistakes it for a real image.
The drill records which runtime ran; a runtime absent in CI is a
named reason, never a silent skip. Wake is the documented no-op.
Dispose stops and removes the container and the worktree.

**D5. The cloud session and the remote worker are drilled against
fakes, with their real paths declared.** The cloud adapter opens a
session at the declared endpoint (`POST /sessions` with the packet
digest and the base revision, bearer from the named env var), meters
by polling the session's usage, and disposes by closing it; the
drill runs an in-process fake provider that reports a runtime and
usage. The remote worker adapter never connects to the worker: it
puts the packet in the artifact store, appends the handoff to the
per-fence observation stream as the worker's pickup (the packet
digest, the base, the workspace spec), and the enrolled worker —
an actor of kind `service` whose name matches the declaration — pulls
it from the ledger and the store it already reads; meter lines arrive
on the same stream from the worker; dispose is the worker's own,
recorded as a `disposed` line. The drill runs a fake worker process
that enrolls, pulls, meters and disposes. Refused: inbound
connectivity to any executor; a worker that is not an enrolled actor.

**D6. Disposability and preemption run per adapter.** The existing
disposability, graceful-preemption and force-preemption drills are
parameterized over the adapters (local, container-with-fake, cloud
fake, remote fake) and run for each; the loss window is stated per
adapter (for the risk-limit adapters, the metered usage after the
interrupt that the provider still bills is part of the stated loss).
`run.settled` records each adapter's actuals; the report names the
adapter per run. Mutation evidence: an adapter that invents a tuple
field; a cloud adapter reporting `enforced`; a secret accepted in the
declaration; a provision without the admitted start; an adapter that
reaches the worker inbound; a runtime absent in CI skipped silently.

**D7. Bounds.** No scheduler change (offers, claims and routing are
untouched); no new verbs; the observation stream's line shapes are
unchanged beyond the pickup and disposed lines the remote adapter
appends; `seed-admit`, the plan gate and admission are untouched. The
public interface gains an optional `Described` and nothing else.

## Acceptance Criteria

**Boundary set (new, shown working):**

1. **Three adapters exist on the public interface.** `run start
   --adapter container|cloud-session|remote-worker` provisions through
   each; each resolves all five tuple fields; a resolved tuple that
   differs from the admitted start refuses `ErrTupleMismatch` with
   nothing left behind.
2. **Budget postures are honest and surfaced.** Each adapter describes
   itself as `enforced` or `risk-limit` with a reason; the doctor lists
   them; `report.json`'s `adapters` names the runs per harness and the
   posture; no risk-limit adapter is reported as enforced.
3. **Credentials are named, never held.** The `executors` block is
   strict, a token-shaped value refuses, and an adapter reads only the
   named env var.
4. **CI is credential-free.** The container drill runs through a local
   OCI runtime or the fake with the same contract and says which; the
   cloud and remote drills run against in-process fakes; no silent
   skip.
5. **Disposability and preemption per adapter.** The three drills run
   for every adapter with the loss window stated per adapter; the
   report names the adapter per run.
6. **Mutation evidence.** Each fails a drill: an invented tuple field;
   a cloud adapter claiming enforcement; a secret in the declaration;
   a provision without the admitted start; an inbound connection to a
   worker; a silent skip.
7. `make check` green with coverage measured cold, three readings
   above the gate; no model identifiers in any committed artifact.

**Retention set (existing, shown unharmed):**

- The local worktree adapter is byte-for-byte unchanged in behavior
  (its drills green); the public interface's existing methods are
  unchanged; the spend bracket, admission and the observation line
  shapes existing consumers read are unchanged; every projection is
  byte-identical on chains carrying no run under a new harness.
