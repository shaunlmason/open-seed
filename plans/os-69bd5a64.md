# Plan: linear adapter parity — the jira review corpus applied (os-69bd5a64)

The jira adapter (PR #22) absorbed three review rounds after the linear
adapter (PR #21) merged; every finding that is not Jira-specific applies to
linear too. This card closes that gap in one pass so the two
tracker-backed adapters carry the same guarantees — same claim safety,
same cascade recovery, same envelope contract.

## Steps

1. **Claim safety** (`.seed/backends/linear/bin/seed-backend`):
   - **Post-claim verification**: after its writes, claim re-reads the
     issue and succeeds only if the substrate holds *its* assignee id AND
     *its* `seed:tok:` label — a lost last-write-wins interleave exits 2
     with the real holder instead of returning a dead token while a rival
     strands the card.
   - **Compensation**: a failed state move during claim rolls back the
     assignment and token (when still owned), so a failed claim leaves
     the issue unchanged.
   - **Contention envelope contract**: a held issue emits
     `error: "claim_contention"` with a top-level `holder`; the reviewer
     lockout emits its own `rejected_author` cause.
2. **Cascade recovery**: per-dependent release failures become
   **skip-and-report** — the dependency label is kept, the dependent is
   listed in the envelope's `cascade_skipped`, the rest of the cascade
   continues, and recovery is an operator `unblock` (the
   transition-before-relabel ordering already landed in #21's review
   round; this removes the remaining abort-mid-cascade failure mode).
3. **Envelope + projection parity**:
   - `get` includes `body` (the issue description — `loop.sh` reads
     `.card.body` for the work order); an issue in a workflow state
     outside the convention is refused with remediation by `get` and
     skipped by `list` (never an invalid `unknown` state).
   - `comment`/`attach-evidence` return `comment_id`/`evidence_id`;
     `event-append` honors a `.task` reference inside the event JSON
     before falling back to the audit sink.
   - All failure envelopes and embedded ids are jq-built — caller
     values can never break the JSON.
   - The audit issue carries a `seed:audit` label, is excluded from
     `ready`, and is refused at `claim`.
4. **Declared variance, not a silent gap**: Linear's `issueUpdate`
   replaces the whole `labelIds` array by API design (no atomic
   add/remove operations like Jira's) — the adapter computes from a
   fresh read immediately before each write and the README declares the
   remaining race window explicitly, alongside the existing
   last-write-wins claim variance.
5. **Tests** (`test.sh` + `testdata/fake-linear`), mirroring the jira
   suite: a deterministic race hook in the fake (a rival's later write
   lands after ours; the loser must exit 2 with the winner on record), a
   workflow variant refusing the release edge (cascade skip-and-report
   asserted, entry preserved), body round-trip, `comment_id`, event
   `.task` routing, contention-envelope shape, audit-issue exclusions,
   and no suppressed setup steps (blocked state asserted before every
   cascade).

## Acceptance Criteria

- A lost claim interleave exits 2 `claim_contention` with the actual
  holder; a failed claim leaves the issue unchanged (rollback asserted).
- A refused cascade release leaves the dependency recorded, reports the
  dependent in `cascade_skipped`, and does not abort the terminal verb
  or the rest of the cascade.
- `get` carries `body`; unmapped workflow states are refused/skipped,
  never emitted; `comment_id`/`evidence_id` present; event `.task`
  honored; the audit issue is never claimable work.
- Existing behavior is otherwise unchanged: the full current contract
  test still passes, extended, with no suppressed setup failures.
- Every remaining variance (label-array replacement window) is declared
  in the README.
