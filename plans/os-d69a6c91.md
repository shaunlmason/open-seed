# Plan: next Phase 5.1 — the transition table and lifecycle verbs (os-d69a6c91)

Implements [`docs/next-build-plan.md`](../docs/next-build-plan.md) Phase 5
item 1: "Transition table as data (`next/spec/transitions.json`),
self-validating, loaded by the admission rule set; lifecycle verbs."
Design authority: [`SEED-NEXT.md`](../SEED-NEXT.md) Part II §6
"Lifecycle" (states `backlog`, `ready`, `in_progress`, `review`, `done`,
`blocked`, `cancelled`; **claim is the ready→in_progress transition,
not a state**; every exit from `in_progress` is deliberate — submit,
release, park, reap — and silent abandonment is impossible by
construction) and conformance III.F: "The lifecycle vocabulary and
transition rules are self-validating data enforced at admission; claim
is a transition, not a state." Deps: Phase 3 (merged) and Phase 4
(stack #109/#111/#112 in review; implementation stacks on the stack
tip until it merges). The contract is data, not branching:
hand-written conditionals that re-derive what the table says would be
a design violation.

## Scope decision (binding for this task)

- **Ships now**: the table, its self-validation, the admission rule
  that enforces it, the lifecycle verb vocabulary, the state fold, and
  the two projection derivations the fold unlocks (the contracts
  view's `state` field; the queue's real readiness derivation) —
  exercising Phase 4's derivation-version machinery in anger.
- **Deferred, per the build plan's own items**: claim fences,
  exclusivity, online-only claiming, and contention envelopes (5.2 —
  `claim.taken`'s *legality* lands now, its fence mechanics do not);
  packets and reap obligations (5.3 — `claim.reaped`'s legality lands
  now, what a reap must leave behind does not); the acceptance-spec
  field and spec-gate flag (5.4); plan-gating (5.5). III.F's
  transition-table row is met by this task; the fence, packet, and
  spec-gate rows stay with their items and the exit record will say
  so.
- **Lifecycle legality is admission policy**, exactly like halt,
  classification, and grants (the recorded no-protocol-bump stance,
  decisions 3.1/3.2): admission refuses illegal transitions at
  `seed/1`; verification tolerates them in history (the cooperative
  posture's named consequence), and the projection fold skips them
  **visibly** — each contract entry counts its skipped-illegal events
  in an `anomalies` field, so tolerated history is never silent.
  Exit code: the existing 3 `invalid_transition` (v1-continuity
  default; semantics match exactly), via a typed
  `InvalidTransitionError{Subject, From, Verb}`.
- **Vocabulary (exact verb strings, binding)**: `intent.filed`
  (birth → `backlog`), `contract.promoted` (`backlog`→`ready`),
  `claim.taken` (`ready`→`in_progress`), `work.submitted`
  (`in_progress`→`review`), `claim.released`
  (`in_progress`→`ready`), `work.parked` (`in_progress`→`blocked`),
  `claim.reaped` (`in_progress`→`ready`), `contract.accepted`
  (`review`→`done`), `contract.returned` (`review`→`ready`),
  `contract.blocked` (`ready`→`blocked`), `contract.unblocked`
  (`blocked`→`ready`), `contract.cancelled`
  ({`backlog`,`ready`,`blocked`,`review`}→`cancelled`).
  `contract.cancelled` deliberately has **no** `in_progress` source:
  leaving `in_progress` happens only through the charter's four
  deliberate exits, which is the silent-abandonment impossibility
  made structural. Verbs outside this vocabulary (free work events
  like `progress.milestone`) are untouched by the rule: they attach
  to subjects in any state.

## Steps

1. **The table** (`next/spec/transitions.json`): `schema_version`,
   the state list with `initial` and `terminal` markers, and one row
   per verb `{verb, from: [states] | null, to: state}` (`from: null`
   marks the single birth verb). Mirrored for tests under the spec
   testdata convention only if an engine needs it; the Go loader
   reads the real file (path threaded, embedded for the rule set).
2. **The loader and fold** (`next/internal/transition`):
   `Load`/`Parse` returning `Table`; **self-validation** at parse
   (each failure named): every `from`/`to` names a declared state;
   exactly one birth verb; terminal states have no outgoing rows; no
   duplicate verb; every state reachable from the initial state;
   every non-terminal state reaches a terminal one (no wedge); the
   `in_progress` outgoing set is exactly the four deliberate exits.
   `Table.Check(current, verb)` → next state or
   `InvalidTransitionError`; `Table.IsLifecycleVerb(verb)`;
   `StateAt(records, subject)` folds a subject's lifecycle events to
   (state, anomalies), skipping illegal history without wedging
   (mirror of `halt.StateAt`'s posture).
3. **The admission rule** (`next/internal/admit`): a `lifecycle` rule
   after `grant`, active at `seed/1` (records under `seed/0`
   grandfathered inert, keyring precedent): for a table verb, fold
   the subject's prior lifecycle events and check legality — a birth
   verb on an existing subject refuses, a non-birth verb on an
   unknown subject refuses, an illegal (from, verb) refuses, all as
   `invalid_transition` with subject, current state, and verb named.
   The hook and CLI surfaces inherit the rule through the shared rule
   set; the envelope layer maps the typed error to exit 3.
4. **The projections** (`next/internal/project`): the contracts view
   gains `state` and `anomalies` per entry (derivation bump: contracts
   `Version: "2"`); the queue's derivation becomes the table's ready
   set — `derivation: "transitions/1"`, `ready` listing subjects whose
   folded state is `ready` with `since_position` the position that
   made them ready (queue `Version: "2"`) — retiring
   `QueueDerivationNone` exactly as 4.2's spec promised, and proving
   Phase 4's version-bearing republication machinery on a real
   derivation change.
5. **Spec** (`next/spec/lifecycle.md`, new): the state machine
   (generated-prose caveat: the docs fan-out that generates lifecycle
   prose from the table is a later phase's machinery; until then this
   file quotes the table and the drill pins their agreement), the
   vocabulary, the self-validation invariants, admission-policy
   activation and the cooperative-posture consequence (visible
   anomalies), the deliberate-exit property, and the conformance
   mapping. `projections.md` updates the queue and contracts sections
   (new derivations, versions). `envelope.md`: extend row 3's prose to
   name lifecycle refusals explicitly.
6. **Drills** (library + admission + CLI + projections):
   - *Self-validation*: planted bad tables refuse by name — unknown
     state, two birth verbs, terminal with an outgoing row,
     unreachable state, wedged state, an `in_progress` exit set that
     is not exactly the four deliberate exits; the real file loads
     clean and the spec prose agrees with the table (parsed, not
     duplicated).
   - *Legality end-to-end*: the full happy path
     (filed→promoted→claimed→submitted→accepted) admits through the
     rule set, the seed-admit hook, and the CLI append; illegal jumps
     (`claim.taken` on `backlog`, `contract.accepted` on
     `in_progress`, birth on an existing subject, non-birth on a
     fresh subject) refuse exit 3 naming subject, state, and verb.
   - *Deliberate exits*: `contract.cancelled` on an `in_progress`
     subject refuses structurally; release/park/reap/submit all admit
     and land where the table says.
   - *Tolerant fold*: a raw-git chain carrying an illegal transition
     verifies (admission policy, not chain validity), the contracts
     view reports the subject's `anomalies` count, and the folded
     state ignores the illegal event.
   - *Projections*: the queue lists exactly the ready subjects with
     correct `since_position` on populated and root-only fixtures;
     the derivation bump republishes under new build ids at an
     unchanged tip (the #109 machinery drilled on its first real
     consumer); the contracts `state` field matches the fold,
     fixture by fixture.
   - *Vocabulary boundary*: free work verbs on subjects in every
     state still admit and appear in contract streams untouched.

  planted invariant violation refuses with a named failure; the
