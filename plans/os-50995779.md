# Plan: GitHub Issues one-way mirror (os-50995779)

Render card state to labeled GitHub issues for human visibility. Per the
design (D1, authoritative over the §7.3 shorthand): **GitHub Issues is not a
backend — it is a mirror component**: cards are authoritative, the export
direction always wins, and human label edits are only ever read back as
*requests* (a dispatcher concern, out of scope here).

## Steps

1. **Engine — `seed mirror plan`** (open-seed-engine): a pure, read-only
   computation. Inputs: all cards (state ref) and the mapping file
   `mirror/map.json` on the state ref (`{card-id: issue-number}`). Output:
   one JSON envelope with an `actions` array — `create` (new card, no
   mapped issue), `update` (labels/title/state drifted), `close`
   (done → closed as completed, cancelled → closed as not-planned) — each
   carrying the desired title (the card title verbatim), labels, and a
   hidden `<!-- seed-mirror: <card-id> -->` body marker (D7 provenance).
   Label mapping (D1, normative): ready→`seed:ready`,
   in_progress→`seed:in_progress`, review→`seed:review`, done→`seed:done`,
   blocked→`seed:blocked`; backlog = no state label; issue bodies carry the
   card body fenced as data. Idempotent: a card whose issue already matches
   produces no action.
2. **Engine — `seed mirror record <card-id> --issue N`** (operator
   credential): writes the mapping entry to `mirror/map.json` on the state
   ref, one commit + run-log event per the write rules (§7.2).
3. **Template — maintenance step**: a new gated step in
   `seed-maintenance.yml` (after close, before lint) running only when
   `[mirror] enabled = true` in `.seed/config.toml`: `seed mirror plan`,
   apply each action via `gh issue create/edit/close`, then
   `seed mirror record` for creates. All card-state authority stays with
   the port; the step only renders (the inspirations/06 erratum's reading).
4. **Config + docs**: `[mirror] enabled = false` shipped default in
   config.toml; handbook §5/§6 note (what the mirror is, what it is not —
   one-way, requests-only feedback); mirror labels documented.
5. **Tests** (engine): plan computation over fixture cards + map — new card
   → create with correct labels/marker; state change → update; done and
   cancelled → close with the right reason; unchanged → no action;
   record round-trip writes the map and appends the event.

## File Scope

- Engine repo: `internal/mirror/` (new), `cmd/seed/`
- Template: `.github/workflows/seed-maintenance.yml`, `.seed/config.toml`,
  `docs/handbook.md`

## Acceptance Criteria

- `seed mirror plan` is deterministic and idempotent over fixtures; every
  card maps to exactly the D1 label set; done/cancelled close with
  completed/not-planned respectively; backlog carries no state label.
- `seed mirror record` writes are one-commit-per-verb with run-log events,
  operator-gated.
- With `enabled = false` (the default), the maintenance step is a no-op —
  a fresh template pays nothing.
- Cards remain authoritative: nothing in the engine or workflow reads issue
  state back into cards.

## Validation Commands

- `sh scripts/validate.sh`
- `scripts/seed mirror plan --json > /dev/null`
- `grep -q "mirror" .github/workflows/seed-maintenance.yml`
