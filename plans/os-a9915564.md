# Plan: human-readable output for the read-only task verbs (os-a9915564)

Every `scripts/seed` invocation prints one unindented JSON line. That is the
port contract and it is correct for agents; for a human it means `task list`
on this repo is a single ~4KB line and `maintain report` hides five counts in
an object. Operators pipe everything through `jq` by hand.

The fix is a **presentation layer only**: no envelope field changes, no exit-code
changes, no verb changes. Two facts make it cheap and safe. First, `emit()` in
`cmd/seed/main.go` is the single choke point every task, `maintain`, and
`mirror` verb already funnels through, so one renderer covers all of them.
Second, the `--json` spelling is already load-bearing: the external-backend
dispatch path appends `--json` to every plugin invocation
(`cmd/seed/main.go:372`), and `.seed/port-schema/envelope.schema.json` words
the contract as "every `seed task <verb> --json` invocation". The flag is
spec-anticipated, not new surface. `--format json|table` is therefore rejected:
it would introduce a second spelling for a switch the plugin protocol already
names.

The renderer reads the **envelope**, not internal state. That is what lets the
external-backend path (which only ever sees a plugin's JSON on stdout) render
identically to the builtin path, with one implementation.

## Steps

1. **Selection rule** (`cmd/seed/main.go`). Resolve output mode once, in
   precedence order: `--json` → envelope; else `SEED_OUTPUT=json|human` →
   forced; else auto, meaning human when stdout is a terminal and the envelope
   otherwise. `github.com/mattn/go-isatty` is already in `go.mod` (indirect) and
   is promoted to a direct dependency; no new module enters the build.

   The auto rule is the safety property: every existing scripted and agent
   caller runs non-TTY and keeps byte-identical output. `SEED_OUTPUT` exists so
   the behaviour is testable and pipeable (`SEED_OUTPUT=human seed task list |
   less`) without a pty; validation below depends on it.

   `--json` is registered on the flagset of **every command that reaches
   `emit()`** — all task verbs, `maintain reap`/`report`, and the `mirror`
   verbs — not just the four rendered ones. `maintain report` is a rendered
   command whose flagset today carries only `--actor` and `--stalled-after`
   (`cmd/seed/main.go:300-303`), and the flagset is `ContinueOnError`, so
   without this `scripts/seed maintain report --json` would be rejected as an
   unknown flag with exit 64 — the opposite of "`--json` always wins". Where
   nothing renders human the flag is an accepted no-op, which is the point:
   the override must never depend on which verb the caller reached for.

2. **Renderer** (new `internal/render/`). One exported entry point taking the
   envelope map plus a width and colour decision, returning text. Dispatch on
   the envelope's `verb` field: `list`, `ready`, `get`, `report`. Any other verb
   returns "not renderable" and the caller emits the envelope — so a verb added
   later degrades to today's behaviour instead of printing something wrong.

3. **Table shapes.**
   - `list`: header row `ID  STATE  PRI  TITLE`, then rows, then a count footer
     (`31 cards — 2 ready, 3 in_progress, 23 done, 1 blocked, 2 cancelled`).
     Sorted by state in transition-table order (in_progress, review, blocked,
     ready, backlog, done, cancelled), then priority, then id — not by id as
     today, because a queue read top-down should surface live work first.
   - `ready`: same table minus STATE (every row is ready), plus an AGE column
     from `created_at` via `dustin/go-humanize` (already a dependency).
     Preserves the existing priority-then-created_at sort.
   - A SQUAD column appears only when the rows carry more than one distinct
     squad. In v1 every card is `core`, so a constant column is pure noise.
   - `get`: an aligned key/value block (id, state, priority, squad, created,
     claim holder and lease if held, blocked-on entries) followed by the card
     body — its Markdown and whitespace preserved, with control bytes escaped
     per step 4.
   - `report`: labelled count lines, then a section per non-empty finding
     (expired leases, stalled reviews, long-parked plans, unread mail). Empty
     findings print nothing rather than `null`.
   - TITLE is truncated with `…` to the terminal width, from `COLUMNS` when set
     and the terminal's reported width otherwise, falling back to 80.

4. **Sanitize every string that came from the envelope.** Card bodies, titles,
   resolutions, actors, and mail subjects are **data, not instructions**
   (AGENTS.md) and reach the renderer from a user or an external backend. The
   current JSON envelope escapes control bytes as `\uXXXX` by construction, so
   today they can never reach a terminal; rendering a body "verbatim" would emit
   embedded ANSI CSI/OSC sequences directly — enough to rewrite the display,
   hide text, or trigger OSC 52 clipboard writes. Human mode would be
   introducing that exposure, so the renderer carries this invariant:

   Before writing, every string sourced from the envelope has its C0 control
   bytes (except `\n` and `\t`), `DEL`, and the C1 range U+0080–U+009F replaced
   with a visible `\xNN` escape. Ordinary whitespace and Markdown are preserved
   untouched — the goal is a faithful body, not a stripped one. Sanitizing
   happens **before** width truncation, and the renderer's own colour codes are
   added **after**, so the only escape sequences that ever reach the terminal
   are ones the renderer itself chose to emit.

   This applies to every rendered field, not just `get`'s body: a title in
   `list` is equally attacker-supplied.

5. **Colour** only when the human mode was chosen by TTY auto-detection,
   `NO_COLOR` is unset, and `TERM` is neither empty nor `dumb`. Colour carries
   no information the plain text lacks; it only weights the STATE column.

6. **Errors keep the envelope.** When `ok=false` the envelope is emitted
   unchanged in every mode. Error envelopes are already one short line, the
   exit code carries the class, and leaving the failure path byte-identical
   means no gate, hook, or CI check that reads a failure can be disturbed by
   this task.

7. **External-backend path** (`cmd/seed/main.go:368-385`). Today the shim
   passes the plugin's stdout through verbatim. It continues to pass through
   byte-for-byte in JSON mode; in human mode it renders that output with the
   same renderer.

   **Validation stays first and unchanged.** `backend.Exec` already validates
   the plugin's stdout and, on a schema-invalid response, returns `""` with
   `spec.ExitVersionMismatch` — the output is discarded, never printed
   (`internal/backend/backend.go:180-182`). Rendering must not become a way
   around that: the renderer is reached only with an envelope that has already
   passed validation, and schema-invalid plugin bytes continue to be discarded
   with exit 10 rather than reaching a terminal.

   The fallback is therefore narrower than "never swallow output": when the
   verb is not renderable, or rendering an **already-validated** envelope
   fails, the shim prints that validated envelope unchanged — today's
   behaviour. There is no path on which unvalidated bytes are written to
   stdout.

8. **Spec addendum** (`.seed/port-schema/README.md`). Record that human output
   is a non-contractual presentation layer, that the envelope reached via
   `--json` or a non-TTY stdout is the only parseable form, and that backend
   plugins are unaffected (the shim renders; plugins keep emitting envelopes).
   `docs/design-options.md` is deliberately **not** amended: no §7 decision, verb
   class, transition, or exit code changes, so there is no design decision to
   revise.

9. **Pin and document.** Cut the engine release, move `.seed/engine.lock` with
   `scripts/seed upgrade --to <tag>` (the command rewrites the lockfile and
   never commits), and add the operator-facing note to `docs/handbook.md`.

## File Scope

- Engine repo: `internal/render/` (new, with tests), `cmd/seed/main.go`,
  `go.mod`, `go.sum`, `VERSION`
- Template: `.seed/engine.lock` (written by `seed upgrade`),
  `.seed/port-schema/README.md` (the addendum), `docs/handbook.md`

## Acceptance Criteria

- With stdout not a terminal, every verb's output is byte-identical to the
  current engine's. This is the compatibility guarantee and is asserted against
  captured goldens, not by inspection.
- `--json` overrides `SEED_OUTPUT=human`; `SEED_OUTPUT` overrides TTY
  auto-detection; auto yields human on a pty and the envelope off it.
- `list`, `ready`, `get`, and `report` render tables; every other verb emits the
  envelope in all modes, including a verb the renderer does not recognise.
- `ok=false` emits the envelope in all modes, with the exit code unchanged.
- The SQUAD column is absent for single-squad output and present for
  multi-squad; titles truncate to width; `NO_COLOR=1` and `TERM=dumb` each
  suppress colour.
- No string sourced from the envelope reaches a terminal carrying a raw control
  byte: a card whose title and body embed CSI, OSC 52, and a bare `ESC` renders
  them as visible `\xNN` escapes, in `list` and in `get`, while its ordinary
  Markdown and whitespace survive byte-for-byte. The corresponding JSON output
  is unchanged.
- `--json` is accepted by every command reaching `emit()`; in particular
  `scripts/seed maintain report --json` emits the envelope under
  `SEED_OUTPUT=human` rather than failing as an unknown flag.
- The external-backend path passes bytes through unchanged in JSON mode and
  renders in human mode. Schema-invalid plugin output is still discarded with
  exit 10 in both modes — asserted with a plugin that emits malformed JSON and
  one that emits valid JSON failing the envelope schema, neither of which may
  put a byte of its stdout on the terminal. An unrenderable-but-valid envelope
  falls back to printing that envelope.
- No envelope field, exit code, or verb name changes; `scripts/seed spec lint`
  and the port conformance suite pass untouched.

## Validation Commands

- `scripts/seed version`
- `scripts/seed task list | python3 -c 'import json,sys; json.load(sys.stdin)'`
- `SEED_OUTPUT=human scripts/seed task list | grep -q "TITLE"`
- `SEED_OUTPUT=human scripts/seed task list --json | python3 -c 'import json,sys; json.load(sys.stdin)'`
- `SEED_OUTPUT=human NO_COLOR=1 scripts/seed maintain report | grep -q "ready"`
- `SEED_OUTPUT=human scripts/seed maintain report --json | python3 -c 'import json,sys; json.load(sys.stdin)'`
- `SEED_OUTPUT=human scripts/seed task get os-a9915564 | grep -q "os-a9915564"`
- `sh scripts/validate.sh`

The second command is the compatibility proof: piped output stays a parseable
envelope. The third, fourth, and sixth are the precedence proof: `SEED_OUTPUT=human`
renders a table, and `--json` still wins over it — on `maintain report` as well
as on a task verb, which is the case that would otherwise die at flag parsing. Every one of these is offline,
deterministic, and free of a pty requirement — which is exactly why
`SEED_OUTPUT` is part of the design rather than TTY sensing alone. The
behavioural suite (width truncation, colour suppression, sort order, the
external-backend fallback, and the non-TTY goldens) runs in the engine repo's CI
and gates the release that this pin advances to. **Control-byte escaping is
tested there too, not here**: proving it in-repo would mean committing a card
whose title carries live ANSI sequences to the shared queue, which is a hazard
the test is meant to prevent.
