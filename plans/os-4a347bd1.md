# Plan: seed upgrade — move the engine pin against tagged releases (os-4a347bd1)

R8's promised command, currently a hand edit: upgrading the engine means
manually rewriting `.seed/engine.lock` with a version and six checksums
copied off a release page. `seed upgrade` makes that one verified command —
resolve the target release, fetch and cross-check its checksums, rewrite
the lockfile — while keeping the human gate exactly where it is: the
command **never commits or pushes**; `engine.lock` is control surface and
lands only through a reviewed PR, which the command's output walks you
through.

## Steps

1. **Release resolution** (engine, `internal/upgrade`): the target is
   `--to vX.Y.Z` when given, otherwise the repo's latest release, resolved
   without any API token via the `releases/latest` redirect (GitHub
   answers with a `Location` header naming the tag). The engine repo comes
   from the lockfile's `repo` line — never hardcoded. A base-URL override
   (`SEED_UPGRADE_BASE_URL`) exists solely so tests run against a local
   fake; it is not a user-facing feature.
2. **Checksum fetch + validation**: download `checksums.txt` for the
   target tag over TLS (Go's net/http, standard roots — the same trust
   the bootstrap shim already places in the release host). Parse the six
   platform sums (`seed_<ver>_<os>_<arch>`); a missing platform is a hard
   refusal (the cross-compile matrix is a release invariant, and a
   partial lockfile would strand that platform's users), and each sum
   must be 64 hex chars.
3. **Lockfile rewrite**: update `version` and the six `sha256_*` lines in
   `.seed/engine.lock` **preserving everything else byte-for-byte**
   (comments, `repo`, any `vendor` line). Refuse a downgrade unless the
   target was named explicitly with `--to` (rollback is legitimate;
   silent downgrade is not). `--check` compares current vs target and
   reports `up_to_date` without writing anything.
4. **The human gate, stated by the tool**: on success the command prints
   the exact follow-up — diff the lock, run the shim once so the new
   binary is fetched and hash-verified locally, commit on a branch, open
   the reviewed PR (control surface, owner review). It also surfaces the
   release URL so the reviewer reads the release notes. Attestation
   verification (`gh attestation verify`, design §7.5's stricter mode)
   is documented in the output as an optional manual step — depending on
   an authenticated `gh` from inside the engine is out of scope.
5. **Tests** (engine): an `httptest` fake serving the redirect and
   checksums — latest-resolution, explicit `--to`, lockfile rewrite
   preserving comments/vendor lines, downgrade refusal without `--to`,
   missing-platform refusal, malformed-sum refusal, `--check` both ways.
   No test touches the network.
6. **Release + pin + docs**: cut the engine release carrying the command;
   template bumps `.seed/engine.lock` to it (eating the dogfood: this
   bump is itself performed with `seed upgrade`) and handbook §6's
   "Upgrading the engine" bullet becomes the two-command story
   (`scripts/seed upgrade`, then the reviewed PR).

## File Scope

- Engine repo: `internal/upgrade/` (new), `cmd/seed/`, `VERSION`
- Template: `.seed/engine.lock` (the new release pin — written by the
  command itself), `docs/handbook.md` (§6 upgrade bullet)

## Acceptance Criteria

- `seed upgrade --check` reports current vs latest and `up_to_date`
  correctly against the fake; `seed upgrade` rewrites only the `version`
  and `sha256_*` lines, byte-preserving the rest of the lockfile.
- A downgrade without explicit `--to` is refused; with `--to` it
  proceeds (rollback path).
- A checksums file missing any of the six platforms, or carrying a
  malformed sum, is a hard refusal — no partial lockfile is ever
  written.
- The command performs no git operations; its output names the reviewed-
  PR follow-up and the release URL.
- The template's engine pin advances to the release carrying the
  command, and the shim fetch-verifies it (hash match) locally.

## Validation Commands

- `scripts/seed version`
- `grep -q "seed upgrade" docs/handbook.md`
- `sh scripts/validate.sh`
