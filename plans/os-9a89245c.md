# Plan: next — close the key-file TOCTOU by checking at the signing site (os-9a89245c)

Deferred from the review of #196 ([that
thread](https://github.com/shaunlmason/open-seed/pull/196#discussion_r3906512204)),
verified real there and carded rather than fixed, because choosing a
shape from a P2 comment on a fourth review round is how a scope guard
stops meaning anything. #196 has merged; this card takes it properly.

## The window

`internal/loop` re-derives its actor by fingerprinting the key file
before every act (`actorOf` → `checkIdentity`). The act then crosses the
CLI seam as `--key <path>`: `loopdrive.go` enters `run()`, which reaches
`loopSigner` (`next/cmd/seed/loop.go`) and **reopens the same path
independently**. An atomic replacement landing between those two reads
is observed by exactly one of them. The check is time-of-check, the
signature is time-of-use, and they can disagree.

Severity, stated so the card is not oversold: the window is microseconds
between two reads in the same process and needs a `rename(2)` landing
inside it. The outcome is bounded by the fence rule
(`next/internal/admit/admit.go`): a holder-signed event is admitted only
from the holder, so a cross-identity **work** act still refuses at the
boundary. What the race defeats is the loop's ability to *diagnose* a
rotation cleanly — it reports "the signing key changed" for one act and
silently signs as the new identity for another. That is why it is P2.

## Design decisions (binding for this task)

- **D1 — move the check to the signing site; do not try to make two
  reads atomic.** `loopSigner` gains an expected fingerprint and refuses
  a key that does not match it. Check and signature then observe **the
  same bytes from the same read**, which is the actual defect; nothing
  needs to be atomic across the seam because there is no longer a second
  opinion to disagree with.

  The two shapes named in the review thread are both **rejected**, and
  recorded here so they are not re-litigated:

  | shape | why not |
  | --- | --- |
  | widen the loop verbs to take key **material** (stdin or an inherited fd) | changes a protocol surface seven verbs share, and a material-bearing seam is a strictly larger security surface than a path-bearing one, to buy a property a fingerprint comparison already buys |
  | have the Driver copy the key to a private path it owns | puts private key material in a second place on disk, which `plans/os-eb35672a.md` already argued against for this loop |

  A fingerprint is **public** — it is the `actor` field of every record
  in the chain — so passing it as an argument leaks nothing and needs no
  new confidentiality story.

- **D2 — the flag is `--as <fingerprint>`, optional at the seam and
  always passed by the loop.** Optional, because the loop verbs are also
  reachable by hand and an operator acting once has no loop to race
  with; requiring it would break that use to guard a hazard it does not
  have. Always passed by `internal/loop`, because the loop is exactly
  the caller that does.

  "Optional but always passed" is a rule an implementer can forget, so
  it is drilled directly: a test asserts **every** act the Driver emits
  carries `--as`, and it fails if a future act is added without one.

- **D3 — the refusal is `usage` (exit 2), the code `loopSigner` already
  returns.** A mismatched key is a caller error at the seam, not a chain
  or admission fact, and it never reaches the boundary. No new exit
  code, consistent with the loop verbs' "no new authority, no new
  codes" posture in `next/spec/loop-verbs.md`.

- **D4 — the loop's own pre-act `checkIdentity` STAYS.** It is now the
  fast local guard and no longer the only one, and it is what produces
  the `ErrKeyRotated` refusal the loop reasons about (the strand path,
  `plans/os-eb35672a.md`). Deleting it because "the CLI checks now"
  would turn a diagnosable stop into an exit-2 usage error the loop
  cannot distinguish from a malformed invocation, and would drop the
  pre-poll check with it, reopening #195's finding. Recorded because
  this is exactly the kind of "the other check covers it" reasoning that
  has cost this cycle three separate regressions.

- **D5 — the drill forces the interleaving; it does not race for it.**
  A race reproduced by timing passes green on a slower runner. The
  window is entered deterministically by driving the **real** CLI from
  `cmd/seed`'s e2e harness through a `loop.Verbs` wrapper that rotates
  the key file *after* the loop's `checkIdentity` has run and *before*
  it delegates to `loopVerbs{}` — the seam between them is precisely the
  window, so the drill sits in it by construction rather than by luck.

- **D6 — scope guard.** No change to what the loop verbs do, to
  admission, or to the fence rule. `internal/loop` gains no capability:
  it passes one more argument. No new verb, no new projection.

## Steps

## Acceptance Criteria

1. `loopSigner` refuses when `--as` names a fingerprint the key does not
   have, exits 2 `usage`, and the message names both fingerprints. A
   drill asserts the text, because a refusal that does not say which key
   it got is one an operator cannot act on.
2. An empty or absent `--as` performs no check and the verb behaves
   exactly as today, asserted so the flag stays optional at the seam.
3. **The interleaving drill**: the key is replaced between the loop's
   `checkIdentity` and the CLI's read, and the act **refuses at the CLI**
   rather than being signed by the new key. Deterministic — no sleep, no
   retry, no timing assumption.
4. **The mutation**: deleting the fingerprint comparison in `loopSigner`
   makes criterion 3's drill fail. This is the acceptance evidence, not
   a green suite.
5. Every act `internal/loop` emits carries `--as`, asserted over the
   act catalog rather than a hand-listed subset, so an act added later
   without one fails.
6. The loop's own `ErrKeyRotated` path is unchanged: the existing
   rotation drills (mid-work and idle-driver) still pass, and deleting
   either `checkIdentity` still fails its drill. D4 is thereby enforced
   rather than asserted.
7. `make check` green with coverage measured **cold**, at least three
   readings above the gate, and the suites pass unprivileged under
   `setpriv --reuid=65534`.

## A risk worth naming now

The honest limit: this closes the gap between the loop's check and the
signature, **not** every conceivable one. A key replaced between
`loopSigner`'s `os.ReadFile` and the `ed25519.Sign` call inside the same
function is not a window at all — the bytes are already in memory — so
the fix is complete for the seam it covers. What it cannot cover is a
caller that does not pass `--as`, which is D2's deliberate cost, and
criterion 5 is the whole defence.

The way this could still be wrong: if a future act is added on a path
that does not go through `actGated`, criterion 5's catalog sweep would
not see it. That is why the sweep is written over the act catalog rather
than over the calls, and why D6 forbids widening the loop in this card —
a second emit path is a change that should fail this plan, not slip
under it.
