# Plan: dispatch + pr-review lane activation readiness (os-70028620)

The seed-dispatch and pr-review workflows ship in-tree and inert
(§139 — v1 posture), but the behavior they describe has never been
exercised: the dispatcher turning issue-label edits into refusable
port calls, `cmd:*` one-shot labels with `by:agent` provenance, and
the reviewer-agent lane joining the D4.5 identity check under its own
app identity. Activation is secrets configuration — an owner act this
card cannot perform — so the deliverable splits honestly: everything
mechanizable lands here (workflow audit, routing logic made
deterministic and testable, the runbook, a scripted live checklist),
and the flip itself is the runbook's final page, executed by the
owner with evidence attached to this card.

## Steps

1. **Workflow audit + drift fix**: reconcile both workflows against
   the current `anthropics/claude-code-action@v1` surface (inputs,
   permissions, trigger gating by write access) and against §139's
   commitments: per-command Bash allowlists, branch-not-PR default,
   `[ai]` title prefixes, `<!-- seed-workflow-id -->` markers, sticky
   progress comments. Anything drifted is fixed; anything the action
   no longer supports is re-declared in the workflow header.
2. **Deterministic dispatcher core**: the label-routing logic
   (`cmd:*` label observed → validate actor's write access → map to a
   `seed task <verb>` invocation → remove the one-shot label → apply
   `by:agent` provenance → sticky comment) moves out of inline
   workflow YAML into `scripts/seed-dispatch-route` (POSIX sh + jq,
   event JSON on stdin, port commands on stdout — **print, don't
   execute**, so the workflow applies them and the script stays
   testable offline). A fake-event contract test drives it in
   validate.sh: label events for each cmd, an unauthorized actor
   refused, an unknown cmd ignored, mirror label edits treated as
   requests (never direct state writes — the §141 port rule).
3. **Reviewer-lane conformance**: pr-review's gate obligations are
   asserted where they ground — the D4.5 identity check in `seed
   receipt verify` already requires reviewer ≠ implementer; a test
   documents that a review by the workflow's app identity satisfies
   it and a self-review fails. The workflow posts its verdict as a
   real PR review (server-attributed), never a comment. Because the
   identity check reads reviews at verify time, the verify workflow
   gains a `pull_request_review` trigger — a review posted after the
   last push re-runs verify, so the gate's answer is never stale
   (without it, a PR whose verify ran pre-review stays red until an
   unrelated push).
4. **Activation runbook** (handbook §"Activating the agent lanes"):
   the exact secrets (`ANTHROPIC_API_KEY`, the app identity for
   pr-review), the config delta — the reviewer app's identity added
   to `[operators].actors` in `.seed/config.toml`, since the lane
   acts through operator verbs and the roster is what authorizes it —
   repo settings deltas (the reviewer app in branch protection once
   L3 is wanted), the L2→L3 guardrails change, the
   solo-mode caveat (§115: agents need a non-admin machine identity
   before L3 means anything), and a **live checklist**: five
   dispatcher exercises and one reviewed PR to run on the repo after
   flipping secrets, each with its expected artifact. The owner runs
   it; the dispatch-run URLs become this card's evidence.
5. **Explicitly out of scope**: flipping the secrets, granting the
   app identity, and the live exercises themselves — owner acts,
   recorded on the card via the runbook's checklist.

## File Scope

- Template: `.github/workflows/seed-dispatch.yml`,
  `.github/workflows/pr-review.yml`,
  `.github/workflows/check-validate.yml` (pull_request_review
  trigger for verify), `scripts/seed-dispatch-route`
  (new), `scripts/validate.sh` (routing contract test),
  `.seed/agents/dispatcher.md` (routing table kept in sync),
  `docs/handbook.md` (runbook)

## Acceptance Criteria

- The dispatcher routing logic is a testable script: authorized
  `cmd:*` events map to correct port invocations with label removal +
  provenance; unauthorized actors and unknown commands are refused/
  ignored; mirror label edits never become direct state writes.
- Both workflows match the audited action surface and §139's
  conventions, and stay inert without secrets (a no-secret run
  exits cleanly, doing nothing).
- The runbook covers secrets, the reviewer app's
  `[operators].actors` roster entry, settings, tier change,
  solo-mode caveat, and the live checklist with expected artifacts;
  verify re-runs on posted reviews.
- validate.sh fails on a routing regression; no live credentials are
  required by any CI check.

## Validation Commands

- `test -x scripts/seed-dispatch-route`
- `grep -qi "Activating the agent lanes" docs/handbook.md`
