# Plan: next Phase 1.7 — CLI: seed ledger verify / append / show (os-89412090)

Implements [`docs/next-build-plan.md`](../docs/next-build-plan.md) Phase 1
item 7: the envelope-emitting ledger verbs. Design authority:
[`SEED-NEXT.md`](../SEED-NEXT.md) Part II §1 ("the entire chain verifies
from genesis with one command") and §II.10 (every verb response is a
position-stamped envelope); builds on `internal/ledger`, `internal/genesis`,
and `internal/event`. Conformance: III.A (one-command verification) and
III.I (versioned envelopes, meaningful exit codes).

## Steps

1. **`seed ledger verify --ledger <dir> [--supported <v>,...]`**: runs
   `VerifyFromGenesis` with the genesis-bootstrap resolver (parse position
   0 as `system.genesis`, build the root keyring from its payload; a chain
   not starting with a genesis refuses distinctly). Success envelope
   carries `{count, tip}` and stamps `position`. Failures map to exit
   codes: version reasons (`version_mismatch`, `version_unsupported`) →
   exit 10; every other chain failure → **exit 8, `chain_invalid`**,
   allocated in `next/spec/envelope.md` by its lowest-unused rule (8 is
   next after halt's 7), with the failure's reason, position, and detail
   in the structured error.
2. **`seed ledger append --ledger <dir> --key <priv> --verb <v>
   --subject <s> --payload <json>`** (dev tool, marked as such in its
   refusals): builds the event at the current tip, signs, appends via the
   store (signature verified against the genesis-bootstrap resolver),
   stamps the new position. Payloads run the classification lint first;
   violations refuse with the lint's pointers in the error detail (the
   classify seam exercised end to end ahead of Phase 2).
3. **`seed ledger show --ledger <dir> [--position <n>]`**: read-only;
   without `--position` renders `{count, tip, head}`; with it, the record
   at that derived ordinal. Never writes; stamps `position`.
4. **Tests** (CLI-level, driving `run()`): init → append → verify → show
   round trip on a temp ledger; verify exit 8 with reason/position on a
   corrupted copy; verify exit 10 on an unsupported-version chain; append
   refusing a classification-hostile payload with pointers; append/show
   usage refusals (missing flags, extra operands) at 64; every response
   parses as a v0 envelope.

## Acceptance Criteria

**Boundary set (new, shown working):**

- One command verifies the whole chain from genesis and reports
  `{count, tip}`; corrupted chains exit 8 with the reason and position;
  version troubles exit 10; all as structured envelopes.
- `append` signs at the current tip, lints payloads before writing
  (hostile payloads refuse with pointers), and stamps the new position;
  `show` never writes.
- Exit 8 (`chain_invalid`) is allocated in the spec table and mirrored by
  a tested constant.

**Retention set (existing, shown unharmed):**

- Every `next/internal` package present on main at implementation time,
  and the existing CLI verbs, pass unchanged
  (`cd next && go test ./internal/... ./cmd/... -count=1`).
- The repo-wide gate stays green with the ≥90% coverage gate
  (`make check`).
