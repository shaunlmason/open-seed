# Plan: next — the enforced hook reads the declaration at the default branch's tip (os-0f924157)

Review finding on #323 (os-b5051f2e): the enforced self-hosted
posture's server-side boundary never exercised its guardrails.
`seed-admit`'s ledger half builds every admission context with
`admit.ContextOver(records[:i])` and no declaration
(`next/cmd/seed-admit/main.go` `admitUpdate`), and the installed
pre-receive script passes no environment but `SEED_ADMIT_REF` and
`SEED_PUSHER` (`next/internal/simulate/hook.go`), so the ceiling and
the other declaration-driven policy rules are no-ops exactly at the
posture that exists to enforce them. The code-ref half already parses
`seed.json` from the default branch's tip for the protected surface
(`coderef.go` `loadCodeRefContext`) and never hands it to the ledger
half; `seed-admit serve` shares the gap because its proposal dry-run
calls the same `admitUpdate`. `next/spec/postures.md` already says the
hook reads the declaration from the default branch's tip, and
`plans/os-0d4f2af3.md` AC3 promised the ceiling refuses at the hook —
nothing drills it, and #323's reworded `simulation.md` paragraph says
the hook reads no declaration *today*. This card closes the gap, at
the enforced boundary, and drills it. Tier: standard. The change is to
`cmd/seed-admit`, the protected surface — the reason this is a
standalone card and not a widening of #323 (whose plan binds
"Nothing else").

## What the tree actually shows

- **The read is already built for the code half.**
  `loadCodeRefContext` resolves the default branch (`git symbolic-ref
  HEAD`), its tip (`rev-parse --verify <branch>^{commit}`), and reads
  `<tip>:seed.json` via `git show`, parsing it into a
  `*posture.Config`; an unparseable file is kept as `declarationErr`
  and makes every agent code push refuse. Nothing reuses that for
  admission.
- **The seam is one option.** `admit.ContextOver` already accepts
  `...Option` including `admit.WithDeclaration`
  (`next/internal/admit/admit.go`), so the ledger half needs the
  config at the right tip, not a new constructor.
- **`serve` is covered for free.** `serve.go`'s proposal dry-run runs
  the hook's own `admitUpdate` against a local mirror; fixing
  `admitUpdate` fixes both the hook and the service.
- **The simulate deployment writes the declaration beside the remote,
  never into the repository.** `simulate/deploy.go` writes
  `<dir>/seed.json` next to the bare remote for the cooperative client
  (`--config`); the remote's default branch is the ledger ref's
  history only. Under the fix the hook reads a repository that carries
  no declaration, so the deployment must commit `seed.json` on the
  default branch (the redteam fixture already does exactly this:
  `stageCode` commits the declaration + a few files as the first commit).
- **The redteam one-derivation test compares the hook against
  `admit.Check` in-process** over the same judged prefix
  (`redteam_test.go` `TestOneDerivationLedgerAgrees`), calling
  `admit.ContextOver(o.Before)` with no options. The fixture's
  committed declaration is `{posture, protected}` only — no
  guardrails — so once the hook reads it, both sides need the same
  config to keep the invariant true.
- **The service's mirror never carries the default branch.**
  `serve.go`'s `judge` materializes the ledger into a private bare
  mirror and runs the hook's own `admitUpdate` over it, but
  `gitref.Client.Fetch` fetches only the guarded ref into
  `refs/seed/fetched`; the mirror's HEAD is unborn, so a
  `loadDeclaration` wired into `admitUpdate` reads nothing there
  unless the mirror fetches the deployment's default branch first.
  "Serve inherits the fix by construction" is false as written; it
  needs its own fetch. The redteam fixture files every contract at
  `trivial` (`stageLedger`), so a `trivial` ceiling plus the
  in-process option alone would exercise no above-ceiling case in the
  corpus.

## Design decisions (binding for this task)

- **D1 — the declaration is read from the default branch's tip, as the
  code half reads it, by one shared read.** A `loadDeclaration(gitDir)`
  helper next to `loadCodeRefContext` resolves the HEAD symref, the
  default branch's tip, and `<tip>:<posture.DeclarationPath>` via
  `git show` — the same three git invocations, one owner.
  `admitUpdate` reads it once per push (not per record) and passes
  `admit.WithDeclaration(cfg)` into `admit.ContextOver` for every
  context it builds. Reading the pre-push tip is the whole posture:
  the declaration is deployment state that the ledger may not rewrite
  under itself, so a push that both changes the declaration and rides
  it is judged against the declaration that stood before the push —
  the code half's existing rule ("a push that carries both is judged
  on the code side against admitted standing").
- **D2 — the ledger half fails closed on a declaration that does not
  parse.** No file, or an unborn default branch: no declaration, the
  hook as today (genesis and a fresh remote are unaffected). File
  present but unparseable: the ledger half refuses the push, the code
  half's own message already refusing it for code refs ("agent pushes
  refuse until an operator repairs it") — one broken declaration cannot
  split the boundary into two.
- **D3 — `serve` reads the same declaration the hook reads, after an
  explicit fetch.** The service's private mirror carries no default
  branch: `gitref.Client.Fetch` fetches only the guarded ref, its HEAD
  is unborn, and `loadDeclaration` over it would return nothing. The
  fix is at the one call site in `judge`: before `admitUpdate`, fetch
  the deployment's default branch into the mirror (the remote's HEAD
  symref resolved at the remote, one `git fetch`), so the mirror's
  `loadDeclaration` reads the same tip, the same way, as the hook. No
  second read path, no `serve`-only option; a serve test proposes an
  above-ceiling claim and reads the boundary's ceiling refusal, and an
  at-ceiling proposal the boundary admits.
- **D4 — the drills, at the enforced boundary.**
  1. `cmd/seed-admit`: a raw-git `claim.taken` by an agent-kind key on
     a contract above its squad's ceiling lands at the hooked remote —
     the push is refused with the ceiling's message, ref unmoved. The
     SAME claim through the cooperative seam under `--config` self-
     refuses at the client with the same rule, before any push — the
     invariant the postures hold, that the postures differ only in
     WHERE the rule runs — and the at-or-below-ceiling claim is the
     control that admits at the hook. The deployment fixture gains a
     committed default branch carrying the declaration (the
     simulate-side analogue of the redteam `stageCode`), so the hook
     has something to read.
  2. `redteam`: the fixture's declaration gains the same guardrail
     block the simulate fixture carries (core squad's agents ceilinged
     at `trivial`, the lanes as teams), the fixture files one ready
     contract at the tier above the ceiling, and the corpus gains the
     adversary's raw `claim.taken` on it: refused at the hook with the
     ceiling's message, a non-primary negative under the `claim`
     clause beside the existing contention primary. With the guardrail
     live and the in-process side of
     `TestOneDerivationLedgerAgrees` given the same `*posture.Config`
     through `admit.WithDeclaration`, that entry's in-process verdict
     agrees (both refuse, same rule) and every existing entry keeps
     its verdict, because its contracts stay at or under the ceiling.
  3. `simulate`: the deployment commits its declaration on the
     default branch beside writing it beside the remote, and a raw
     above-ceiling push drill runs against the installed hook (the
     posture's own end-to-end story, the #323 reproduction
     inverting: the raw push now refuses at the boundary).
- **D5 — the spec paragraphs land.** `simulation.md`'s hedge
  ("the hook reads no declaration today… is card os-0f924157's") is
  tightened back to the affirmative: the hook reads the declaration
  at the default branch's tip as `postures.md` says, and `declared`
  states what the audit, the client, and the hook each read.
  `postures.md`'s hook paragraph gains the parse-failure refusal
  (D2) in one sentence. Nothing else in the spec moves; the ceiling
  rule itself is unchanged.

## Acceptance Criteria

**Boundary set (new, shown working):**

1. **The ceiling refuses at the enforced boundary, in all three
   places.** A raw-git `claim.taken` by an agent-kind key on a
   contract above its squad's ceiling is refused at the hook with the
   ceiling's message and the ref unmoved (cmd/seed-admit drill,
   redteam corpus entry, simulate end-to-end); the same claim through
   the cooperative seam under `--config` self-refuses at the client
   before the push, and the at-or-below-ceiling control admits at the
   hook.
2. **A broken declaration splits the boundary into no halves.** A
   `seed.json` on the default branch's tip that does not parse refuses
   the ledger push and the code push alike, naming the file; a fresh
   remote with no declaration and an empty-ledger genesis behave as
   today.
3. **`serve` judges what the hook would.** After the explicit
   default-branch fetch (D3), the service's proposal dry-run refuses
   the same above-ceiling claim its hook would, and admits an
   at-ceiling proposal.
4. **The spec says the hook reads the declaration.**
   `simulation.md`'s "reads no declaration today" hedge is tightened
   to the affirmative; `postures.md` names the parse-failure refusal.

**Retention set (existing, shown unharmed):**

  `TestCoverageBothWays` and the kill-and-replace drill pass with the
  guardrail active (no verdict changes except the ceiling's).
