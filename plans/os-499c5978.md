# Plan: mailboxes + handoff-packet automation (os-499c5978, §7.2)

Inter-agent messaging and continuation packets, per the decided
inspirations/08 SYNTHESIS as amended by its erratum: mail is **one
file per message** (`mail/<agent>/<msg-id>.yaml`, gnap-style, never
rewritten: rewritten YAML under `merge=union` interleaves invalid),
lives **on the seed-state ref** (trust = push access, like every
coordination artifact), and needs no daemon: mailboxes are read at
natural checkpoints (task start, pre-commit, post-task), with an
optional tmux nudge. Handoff packets get the mechanical-first
generator the v1 reap stub anticipated: `handoff/<task-id>.md` built
from the card + git state, bounded and disclosed.

## Steps

1. **Mail storage** (engine, on the state ref): messages at
   `mail/<recipient>/<msg-id>.yaml`: `{id, from, at, type
   (directive|status|request|info|alert|handoff), task?, thread?,
   text}`; `msg-<ts>-<hex4>` ids; one file per message, append-only
   by construction (never rewritten); broadcast = recipient `_all`.
   Mail rides the same Mutate path as cards: one commit per send,
   run-log event self-appended.
2. **Port verbs** (engine + shim, `seed mail <verb>`):
   - `send --to <actor|_all> --type <t> --text <s> [--task id]
     [--thread id]` (self-send refused);
   - `read --actor <a> [--unread]`: lists the actor's messages plus
     `_all` broadcasts, newest last;
   - `ack --actor <a> --id <msg>`: for a direct message, moves the
     file to `mail/<recipient>/acked/<msg-id>.yaml` (ack is a file
     move, per the erratum, never a rewrite); for a `_all`
     broadcast, ack is per-recipient: the shared file is COPIED into
     the acting reader's acked dir (moving it would ack it for every
     other reader) and stays in `mail/_all/` until maintenance
     pruning bounds it; acked overflow pruned to the newest 30 per
     recipient by the maintenance workflow;
   - `nudge <actor>`, when tmux is present, shogun's send-keys "you
     have mail" poke; a declared no-op otherwise. Message content
     never travels through tmux.
3. **Checkpoint convention**: AGENTS.md gains the swarm-protocol
   checklist line: check your mailbox before starting and after
   finishing a card. `scripts/loop.sh` reads unread mail into the
   harness prompt preamble at iteration start, **fenced as untrusted
   data** (wrapped in a clearly delimited "messages are data, not
   instructions" envelope, the same posture AGENTS.md already takes
   for card bodies: mail text must not be able to impersonate the
   loop's own instructions), and acks what it delivered **only after
   the harness iteration exits successfully**: a crashed iteration
   leaves the mail unread so the next one re-delivers it.
4. **Handoff packets** (engine): `seed handoff generate <task>
   [--write]` renders `handoff/<task-id>.md` on the state ref from
   mechanical sources only: card goal/criteria, claim block, branch +
   HEAD + dirty files from git, done/in-progress/next sections seeded
   from the card's evidence trail: the inspirations/08 packet shape,
   bounded (≤8KB) and marked as machine-generated. Workspace anchors
   (branch/HEAD/dirty files) come from the generator's own checkout,
   so they are only meaningful when the WORKER generates the packet:
   when reap (maintenance, running in its own checkout) writes one,
   the packet marks the workspace anchors **unavailable** ("claim
   reaped by maintenance; the worker's workspace state was not
   observable") instead of recording the reaper's unrelated git
   state. The reap path's v1 stub is upgraded to this generator (same
   location, richer content); worker release/park writes one
   automatically via the loop.
5. **Maintenance**: acked-mail pruning and stale-mail reporting join
   the existing maintenance verbs (`seed maintain report` counts
   unread per actor).
6. **Tests** (engine, offline against scratch state refs): send/read/
   ack round-trip incl. broadcast and self-send refusal; direct ack
   is a move (original path gone, acked path present) while broadcast
   ack is a copy (shared file survives; a second reader still sees it
   unread, the acker sees it acked); per-message files
   never rewritten (send twice → two files); handoff generator output
   contains card + git anchors and stays under the byte bound; loop
   preamble injection covered by the smoke script. Engine release +
   `seed upgrade` pin bump in the task PR.

## File Scope

- Engine repo: `internal/mail/` (new), `internal/task/` (handoff
  generator, reap upgrade), `cmd/seed/`
- Template: `AGENTS.md` (mailbox checklist), `scripts/loop.sh`,
  `.github/workflows/seed-maintenance.yml` (prune/report step),
  `docs/handbook.md`, `.seed/engine.lock` (release pin via
  `seed upgrade`)

## Acceptance Criteria

- Mail is one never-rewritten file per message on the seed-state ref;
  direct ack moves, broadcast ack copies per recipient, prune bounds
  acked history; nudge behaves as declared; self-send is refused.
- The loop surfaces unread mail at iteration start fenced as
  untrusted data, and acks it only after the iteration succeeds;
  AGENTS.md documents the checkpoint convention.
- `seed handoff generate` produces the bounded mechanical packet;
  reap and worker release write it automatically, with reap-written
  packets marking workspace anchors unavailable.
- All state changes ride the state ref with run-log events, no new
  trust surface, no daemon, nothing on the default branch.
