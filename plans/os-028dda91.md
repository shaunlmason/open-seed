# Plan: next Phase 2.5 — admission drills (os-028dda91)

Implements [`docs/next-build-plan.md`](../docs/next-build-plan.md) Phase 2
item 5 and closes the Phase 2 exit: the raw-git adversary drill under
enforced posture, the kill-and-replace statelessness drill, and both
postures selectable in fixtures. Design authority:
[`SEED-NEXT.md`](../SEED-NEXT.md) Part II "Postures" and conformance
III.B (validator as sole writer; statelessness; the cooperative
consequence made observable, not just printed). 2.3's hook tests already
refuse individual hostile pushes; this task turns them into the
charter's named drills and adds the deployment fixture both later phases
and Phase 12's compromised-actor drill will reuse.

## Steps

1. **The deployment fixture.** A test helper (`next/cmd/seed-admit`
   test scope, exported to the package's tests only) that stands up a
   deployment at a declared posture: `enforced-self-hosted` (bare remote
   + installed hook + posture file) or `cooperative` (bare remote, no
   hook, posture file) — the "both postures selectable in fixtures"
   exit criterion, wired through `internal/posture` so fixtures and
   production read the same declaration.
2. **The raw-git adversary drill, per posture.** One drill runs the
   same adversary suite against both fixtures and asserts the posture
   difference the charter names: under enforced, every invalid raw push
   refuses and the ref never moves; under cooperative, the same raw
   pushes **land** (the named consequence, made observable) while the
   cooperative client itself still refuses them locally — the
   self-validation half of the posture. The drill's assertion message
   quotes the consequence constant, tying the observed behavior to the
   declared stance.
3. **The kill-and-replace drill.** Stand up an enforced deployment,
   admit a few events, then destroy the host: rebuild the replacement
   from a fresh bare clone of the guarded repository (`git clone
   --mirror`, so only replicated Git data — refs and objects — crosses
   over, never repo-local config, hooks, caches, or any other host
   state), install a freshly built hook binary there, and re-run the
   full refusal suite plus a valid append and a from-genesis
   verification. Every decision must be identical:
   the hook rebuilds all context from the repository it guards, so
   replacing the host loses nothing (conformance III.B statelessness).
4. **Phase 2 exit bookkeeping.** `next/docs/progress.md` records the
   Phase 2 exit with the drill evidence, mirroring the Phase 1 exit
   paragraph, and points the frontier at Phase 3 (identity and grants).
