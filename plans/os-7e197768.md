# Plan: next Phase 9 item 5 part (c) — loop verbs (os-7e197768)

Implements the third part of `docs/next-build-plan.md` Phase 9 item 5,
split from `os-52d5da3f` for reviewability. Parts (a) and (b) landed
in #171: obligations are derived, and `seed situation` answers *what
is true for me now* — including the active fence a lane would
otherwise dig out of a projection. This part closes the loop: the
**acts** a lane takes.

**The gap.** Today a lane acts through the raw protocol seam:
`ledger append --verb claim.released --payload '{"fence":"12",
"packet":{…four parts…}}'`, with the fence read by hand, the packet
hand-built, the reservation id looked up, the base range assembled
from git. Worse, that path performs **no admission pre-flight**: it
signs, previews only actor events against the keyring, and appends,
so a lane learns its act was illegal from a chain-level refusal
rather than from the boundary that would have explained it.

## Design decisions (binding for this task)

- **D1 — the surface is `<noun> <verb>`, matching what exists, and
  it reaches the AUTHORITATIVE ledger.** `seed offer publish`, `seed
  verdict render`, `seed seal create`, `seed budget status` establish
  the shape, with flags rather than positionals. The loop verbs
  follow it: `claim take|release|park`, `submission make`, `budget
  reserve|settle|release`, one spelling per act, no aliases. Each
  takes `--ledger` **xor** `--remote` (with `--ref` and `--state`),
  exactly as `ledger append` does and through the same client
  machinery, because a lane in any real posture works against a
  remote ref rather than a local directory. **`claim take` is
  remote-only** (review finding on this PR): `Table.Exclusive` marks
  `claim.taken` alone, and the CLI already refuses exclusive verbs on
  the local path with exit 2 — exclusivity is granted at the push
  round-trip, so two offline actors claiming one contract have
  claimed nothing. The verb refuses `--ledger` with that same reason
  rather than inventing a second explanation.
- **D2 — the first set is the worker spine, and nothing else.**
  Exactly seven verbs, chosen because together they close
  poll → claim → work → meter → submit → deliberate exit, the loop
  Phase 9 item 1 will make a lane run: `claim take`, `claim
  release`, `claim park`, `submission make`, `budget reserve`,
  `budget settle`, `budget release`. Filing and specification stay
  operator acts on the raw seam for now; the verdict, offer and seal
  surfaces already exist. Extending the set is a later card, so this
  one stays reviewable.
- **D3 — derive every argument the system can derive.** The fence
  comes from the active claim window in the fold (never a flag): a
  holder-signed event citing anything else is refused anyway, so
  asking for it only invites the error. The reservation id for
  `budget settle` / `budget release` comes from the single open valid
  reservation in the shared budget view; **more than one open
  reservation is a refusal that names them**, never a silent choice.
  On the remote path both derivations read the **materialized remote
  tip**, not a local copy: a fence or reservation derived from a
  stale local view would be exactly wrong under the contention that
  makes claiming online-only, so the derivation and the pre-flight
  share one authoritative view.
  `--amount` and `--actuals` stay caller-supplied (they are
  judgments, not derivations). Where a derivation is impossible the
  refusal says which fact is missing and what would establish it.
- **D4 — refuse before signing, and say what IS legal.** Each verb
  drafts its record, runs the **same `admit.Check`** admission
  enforces, and on refusal renders the boundary's own error **plus
  the caller's current affordances on that subject** — machinery
  that already exists (`admit.Affordances`), now used to answer "then
  what may I do?" in the same breath as "not that". Nothing is
  appended on refusal and nothing is signed into the chain. This is
  the teaching-refusal principle made concrete, and it is the reason
  these verbs are not sugar: the raw seam cannot do it, because it
  does not consult the boundary at all.
- **D5 — the packet is validated before it is signed.** Exit and
  submission verbs take `--packet <file>` (JSON) and check the
  four-part shape (`next/spec/packets.md`) at the door, naming the
  missing or malformed part. `--base` may be omitted when `--repo` is
  given and the range is derivable; otherwise the refusal says so.
  A packet that fails its shape never becomes a signed record.
- **D6 — every verb keeps the envelope contract.** Position stamp,
  affordances, budget block, and the attempts journal at these
  admission-boundary seams (`refusals.md`), through the existing
  shared helpers — no new envelope shape, no new journal kind. The
  success envelope stays terse: teaching text lives in refusals only.
- **D7 — scope guard.** No new authority, no orchestration, no
  retry loops, no state kept outside the ledger. `ledger append`
  remains the raw seam, unchanged, so nothing that works today
  breaks. Discharging an obligation is a *consequence* of these
  verbs, not a new concept: the obligations projection already names
  which verb discharges what, and the drills assert the pairing
  rather than the verbs re-deriving it.

## Steps

1. `cmd/seed/loop.go`: the shared pre-flight — build the admission
   context, derive fence and reservation, draft, `admit.Check`, and
   on refusal render the boundary error plus affordances; on success
   append, stamp, journal.
2. The seven verbs per D1–D3, wired into the main switch.
3. Packet validation per D5, reusing the existing packet shape check.
4. CLI drills: each verb's happy path with the derived argument
   absent from the flags; the refusal path showing the boundary's
   error **and** a non-empty affordance list; the multi-reservation
   refusal naming the candidates; a malformed packet refused before
   signing (asserted by the chain not growing).
5. Obligation drills, split by what each verb actually does (review
   finding on this PR: `claim take` CREATES `claim.held` and `budget
   reserve` CREATES `budget.open`; neither appears in any
   `discharged_by` set, so a blanket "the obligation is gone" check
   would assert the opposite of the projection's semantics).
   **Creation**: after `claim take` the holder's `claim.held` stands
   in `seed situation`; after `budget reserve`, `budget.open` does.
   **Discharge**: `claim release` and `claim park` clear
   `claim.held`; `budget settle` and `budget release` clear
   `budget.open`; `submission make` clears `claim.held` **and**
   raises `submission.pending` for the verifier lane, so it is
   asserted as both, per the projection rather than a rule of thumb.
6. `next/spec/loop-verbs.md`: the surface, what each verb derives,
   the pre-flight contract, and the deliberate absences; referenced
   from `envelope.md` and `obligations.md`.
7. `next/docs/progress.md`, `next/docs/decisions.md`, memory if the
   build teaches anything durable; receipt; evidence; review.

## Acceptance Criteria

1. The seven verbs exist under `<noun> <verb>`, each accepting
   `--ledger` xor `--remote` (with `--ref`/`--state`) through the
   existing client machinery, with `claim take` remote-only and
   refusing `--ledger` for the online-only reason the CLI already
   gives; no fence flag anywhere, and no reservation flag where
   exactly one is open.
2. Every verb pre-flights through `admit.Check` and appends nothing
   on refusal; the refusal envelope carries the boundary's error and
   the caller's affordances on that subject.
3. More than one open reservation refuses naming the candidates
   rather than choosing.
4. A malformed packet is refused before signing, asserted by the
   chain not growing.
5. Each verb is paired with what the projection says it does —
   creation for `claim take` and `budget reserve`, discharge for the
   exits and the closes, both for `submission make` — asserted end to
   end through `seed situation`, never as a blanket discharge rule.
6. `ledger append` is unchanged; the envelope and journal contracts
   are unchanged.
7. `make check` green, coverage gate ≥90% held.
