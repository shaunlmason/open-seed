# Plan: next Phase 8.1 — affordance envelope (os-f5551001)

Implements `docs/next-build-plan.md` Phase 8 item 1: the envelope's
`affordances` computed from the same `internal/admit` rule set
admission enforces, with `position`, the budget block, structured
errors, and exit codes per spec. Design authority: SEED-NEXT.md
§II.10 ("the result, plus the verbs currently legal for this actor
on this subject, computed from the same spec and rules admission
enforces — one rule set, two consumers, zero drift by construction …
carry the ledger position they were computed at"), charter III.I
rows 1–2, and the Phase 7 exit, which routes the envelope budget
block here. Much of the shape already exists
(`next/internal/envelope`: version `seed-envelope/0`, structured
`Error`, the exit-code table, position stamping, and the
PLACEHOLDER fields `Affordances []string` — always empty — and
`Budget *Budget` — always nil): this task fills the two
placeholders. Item 2's regression-class harness and item 3's
refusal-rate metric are the phase's next cards; this task lands the
computation and its first pinning drills.

## Design decisions (binding for this task)

- **D1 — affordances are computed by probing the real rule set,
  never by a parallel legality derivation.** The admission matrices
  already draft SIGNED records and run `admit.Check` on them
  without appending; the affordance computation is exactly that,
  made a library surface: `admit.Affordances(ctx, key
  ed25519.PrivateKey, subject) []string` drafts one probe record
  per catalog verb (the keyring spec-table verbs plus the
  ungoverned active-standing verbs) with a minimal payload
  synthesized from the live context, SIGNS each probe with the
  caller's key (the pipeline's actor rule resolves the public key
  and verifies the record signature — review finding on this PR: a
  fingerprint-only API cannot satisfy it, and exempting the
  signature rule would fork the rule set), runs the SAME `Check`
  pipeline end to end, and lists the verb iff the probe admits.
  One rule set, two consumers, zero exceptions, zero drift by
  construction: the only new data is the probe-payload table
  (verb → template filled from the context — the active claim
  fence, an open valid reservation's position, the standing pass
  verdict, a minimal four-part packet with the zero-length base
  range), which is payload SYNTHESIS, not legality logic.
  **Every catalog verb has a template, pinned by a completeness
  test** that iterates the catalog and fails on any verb without a
  synthesizer (review finding on this PR: under-listing a legal
  verb leaves an agent without its valid next move and is as
  non-conformant as over-listing) — so a verb absent from an
  envelope always means the probe was refused at this position,
  never that synthesis was skipped. Over-listing remains III.I
  row 2's bug class, which is why the probe runs the enforcing
  rules and not an approximation. Ed25519 signing is cheap; a few
  dozen probe signatures per response cost microseconds.
- **D2 — the budget block fills from the one shared derivation.**
  `envelope.Budget{Reserved, Remaining}` populates from
  `admit.BudgetViewAt` at the response's context — `reserved` the
  sum of open valid reservation amounts, `remaining` the derived
  remaining, both decimal strings (7.2's saturating arithmetic) —
  on subjects carrying budget facts; subjects without stay `null`
  (the schema-stable back-compat the spec already promises).
- **D3 — every appending command stamps them.** Affordances and
  the budget block need ledger + signing key + subject, and EVERY
  command that signs and appends a record has all three (review
  finding on this PR: scoping to `ledger append` alone would leave
  `offer publish`, `verdict render`, `seal create`, and the other
  specialized append paths violating the charter's "every verb
  response"). One shared helper — `stampAffordances(env, store,
  key, subject)` — is called from every append path's response,
  success and refusal alike, with the context the post-append tip
  (matching the stamped position); the implementation enumerates
  the append-path commands by their common signing seam rather
  than hand-listing call sites, so a future verb surface inherits
  the stamp. `seed budget status` gains an optional `--key <path>`
  (a fingerprint alone cannot sign probes): with it the response
  stamps affordances beside the budget block it already derives;
  without it, affordances stay `[]` (a read surface must not guess
  an identity). Responses genuinely lacking a
  ledger+key+subject context (`version`, `doctor`, `init`, list
  surfaces without a key) keep `[]`/`null` exactly as today — the
  spec's "subjectless verbs carry an empty list" sentence
  generalizes to that rule.
- **D4 — refusals stamp affordances too.** A refused append still
  computes affordances for its actor/subject at the refusal's
  context (the tip that refused it): the refusal plus the list of
  what IS legal is the affordance envelope's whole point (a rising
  refusal rate signals an affordance gap; the worker's next legal
  move should be in hand). Computation failures degrade to `[]`,
  never to a failed response: affordances are advisory, and their
  computation must not break the verb.
- **D5 — the drills pin listed-iff-admits, both directions.**
  A library drill walks a fixture through the lifecycle (ready →
  claimed → reserved → started → review → done) asserting at each
  position that (a) every listed verb's probe admits, (b) a
  curated set of known-illegal verbs is absent (claim.taken on an
  in_progress subject, run.started without an open reservation,
  verdict.rendered by a non-verifier, a second run.interrupted on
  the fence), and (c) the completeness half: each catalog verb is
  listed at least once across the walk, at a position where it is
  legal for the walked actor — so no verb can silently fall out of
  the table. The template-completeness test iterates the catalog
  and fails on any verb without a synthesizer. A CLI drill asserts
  append responses carry the stamped affordances and budget block
  (and `[]`/`null` where D3 says so), on a specialized append path
  (verdict render) as well as ledger append. The full property harness — every listed verb refused
  at admission at the same position is a test failure as a CLASS —
  is item 2's card; these drills are its seed corpus.

## Steps

1. **Probe table + computation** (`next/internal/admit`): the verb
   catalog (from the keyring spec rows + ungoverned verbs), a
   probe-payload synthesizer for EVERY catalog verb reading the
   live context/fold (completeness pinned by test), and
   `Affordances(ctx, key, subject) []string` signing each probe
   with the caller's key and running the real `Check` end to end.
   Sorted, deduplicated output for schema stability.
2. **Budget block helper**: derive `{reserved, remaining}` strings
   from `BudgetViewAt` beside the existing `seed budget status`
   numbers (shared, not duplicated).
3. **CLI stamping** (`next/cmd/seed`): every append-path command
   (ledger append, offer publish, verdict render, seal create, and
   the rest of the signing seam), success and refusal paths, plus
   `budget status --key`, per D3/D4; a small shared
   `stampAffordances(env, store, key, subject)` that degrades to
   `[]` on computation failure.
4. **Spec**: `next/spec/envelope.md` — the affordances sentence
   gains the D3 context rule and the D4 refusal posture; the
   budget-block sentence drops its "until budgets land" tense and
   documents the two fields' derivation.
5. **Drills**: the D5 library walk in `internal/admit`
   (`affordances_test.go`) and the CLI stamp assertions beside the
   existing append tests; `make check` green with cleaned caches at
   the 90% gate.
6. **Docs**: decision-log entry; `next/docs/progress.md` Phase 8
   ledger opens (8.1 row in review, frontier updated).

## Acceptance Criteria

1. `admit.Affordances` exists, signs each probe with the caller's
   key, computes by drafting through the FULL enforcing `Check`
   pipeline (signature rule included; no parallel legality logic,
   no exempted rules), and returns a sorted stable list.
2. Every append-path response — ledger append, offer publish,
   verdict render, seal create, and the rest of the signing seam;
   success and refusal — carries affordances for the signing
   actor/subject at the stamped position, and the budget block on
   budget-active subjects; `seed budget status --key` likewise;
   responses without a ledger+key+subject context are
   byte-identical to today (`[]`/`null`).
3. The D5 drills pass both directions: listed probes admit at the
   same position, the curated illegal set is never listed, every
   catalog verb is listed somewhere legal across the walk, the
   template-completeness test covers the whole catalog, and
   stamping degrades to `[]` on computation failure rather than
   failing the verb.
4. `next/spec/envelope.md` documents the context rule, the refusal
   posture, and the budget derivation.
5. `make check` green from the repo root with cleaned caches;
   coverage at or above the 90% gate.
