# Plan: next Phase 2.4 — posture declaration and seed doctor (os-3c72f93f)

Implements [`docs/next-build-plan.md`](../docs/next-build-plan.md) Phase 2
item 4: posture declaration in config, and `seed doctor` stating the
posture — for cooperative, printing the named consequence verbatim.
Design authority: [`SEED-NEXT.md`](../SEED-NEXT.md) Part II "Postures":
every deployment MUST declare which of the three named deployments it
runs, and cooperative is "a declared mode with a named consequence …
the preflight tool and README MUST say so in plain words". The doctor is
that preflight tool. Conformance: the III checklist item "every
deployment declares its posture; cooperative mode's consequences are
stated by the preflight tool".

## Steps

1. **The posture library.** `next/internal/posture`: the three charter
   postures as typed constants (`enforced-self-hosted`,
   `enforced-forge-hosted`, `cooperative`), `Load(path)` reading a
   strict JSON declaration `{"posture": "<name>"}` (unknown fields and
   unknown postures refuse; the file is deployment/client state, never
   ledger content — the guarded ref's tree stays HEAD + segments only),
   and the charter's named consequence as one exported constant, worded
   from the charter's own posture section: no server-side enforcement,
   every writer self-validates, the security invariant (SEED-NEXT.md
   §I.2) does not hold, and protocol rules are advisory against a
   hostile credential. One copy of the sentence; the doctor and any
   future README generator quote it, never re-derive it.
2. **The doctor verb.** `seed doctor --config <path>` (default
   `seed.json` in the working directory): reports the declared posture
   in the envelope result (`posture`, `enforced` boolean) and, for
   cooperative, carries the consequence string verbatim in both the
   result and the human-readable message. A missing declaration refuses
   at exit 4 `not_found` with the charter's MUST-declare wording. A
   malformed file or unknown posture is a new refusal condition, not an
   illegal transition (exit 3 is reserved by `next/spec/envelope.md` for
   transitions absent from the spec tables), so allocate **exit 13
   `posture_invalid`** per the spec's lowest-unused rule: the spec-table
   row, the mirroring `next/internal/envelope` constant, and its
   spec-mirror test land in this task before the doctor emits the code,
   and the refusal message names the valid postures. `enforced-forge-hosted`
   reports honestly that its admission service lands in Phase 12
   (docs/next-build-plan.md), so declaring it today names the gap
   instead of implying enforcement that does not exist yet.
3. **Tests** (CLI-level through `run()`, plus library): each posture
   round-trips through `Load` and the doctor; the cooperative envelope
   carries the consequence **verbatim** (exact-string assertion against
   the exported constant, plus key-phrase assertions so a reworded
   constant cannot silently pass); missing config exits 4; unknown
   posture and unknown fields exit 13; the forge-hosted result names the
   Phase 12 gap; strict parsing refuses trailing data.
