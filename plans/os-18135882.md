## Steps

1. **`main` branch protection** — required checks `[check, verify]` strict,
   required conversation resolution, CODEOWNERS review plus one approving
   review, stale reviews dismissed, no force-push, no branch deletion,
   `enforce_admins=false` — CI is mandatory for every non-admin contributor,
   and repository admins deliberately retain a manual-merge escape hatch
   (they can bypass the required checks; the tradeoff is accepted so a
   wedged state ref can always be recovered by hand).
2. **Ruleset `seed-state: no force-push, no delete`** — on
   `refs/heads/seed-state`: `deletion` + `non_fast_forward` only; ordinary
   fast-forward pushes by seed actors still allowed (the state ref must keep
   working), but history rewriting and branch deletion are refused.
3. **Ruleset `seed-anchor tags: create-only`** — on
   `refs/tags/seed-anchor/*`: `deletion` + `non_fast_forward` + `update`
   (an anchor, once minted by the maintenance lane, can never be moved or
   deleted).
4. **Ruleset `release tags: immutable`** — on `refs/tags/v*`: same
   create-only profile, extending the seed-anchor protections to release
   tags per handbook §1.
