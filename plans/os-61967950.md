# Plan: builtin backends emit comment_id/evidence_id (os-61967950)

`verbs.json` declares `comment_id` (comment) and `evidence_id`
(attach-evidence) as required verb outputs, and `envelope.schema.json`
admits them since os-69bd5a64 — but the engine's builtin task service
(behind both `filecards` and `fastcards`) appends comment and evidence
text into the card body and returns neither id. The tracker adapters
(Jira, Linear) conform; the builtins are the only backends out of
conformance with their own port declaration. Small, engine-only fix.

## Steps

1. **Mint ids in the builtin service** (engine,
   `internal/task/task.go`): the shared Comment/AttachEvidence path
   mints a stable id per record — `cm-<hash8>` / `ev-<hash8>` derived
   from task id + timestamp + a counter — stamps it into the appended
   card-body section header (so the id is resolvable by reading the
   card), and returns it in the envelope as `comment_id` /
   `evidence_id`. Both builtins share the service, so filecards and
   fastcards conform together.
2. **Spec-driven port conformance** (engine): the conformance check is
   derived from the checked-in verb specification, not hard-coded — a
   table-driven suite reads `verbs.json`, extracts each verb's declared
   output fields, runs the verb against BOTH builtin stores, and fails
   on any declared output missing from the envelope (comment_id and
   evidence_id today; any future declared output automatically). This
   closes the drift class that let verbs.json require outputs the
   builtins omitted. Service-level tests (ids nonempty, id
   round-trips into the card body) remain as supplemental coverage.
3. **Template smoke asserts it end-to-end**: `scripts/smoke-loop.sh`
   gains one assertion — a `seed task comment` and a
   `seed task attach-evidence` during the smoke lifecycle must return
   nonempty `comment_id`/`evidence_id` (jq probe), so a regression
   fails `make smoke` in any instantiation.
4. **Engine release + pin bump** via `scripts/seed upgrade`, carried in
   this card's task PR.

## File Scope

- Engine repo: `internal/task/`
- Template: `scripts/smoke-loop.sh`, `.seed/engine.lock` (the new
  release pin, moved by `seed upgrade`)

## Acceptance Criteria

- `seed task comment` and `seed task attach-evidence` on the filecards
  AND fastcards backends return nonempty `comment_id`/`evidence_id`,
  and the id appears in the card body's appended section.
- The engine test suite fails if either builtin omits either id.
- `make smoke` asserts both ids in the live lifecycle.
- No behavior change to the tracker adapters or the envelope schema
  (both already conform).

## Validation Commands

- `make smoke`
- `sh scripts/validate.sh`
