# Plan: engine: resolve latest release via api.github.com with optional token (private-fork fallback) (os-a353ef17)

`seed upgrade` and `seed template upgrade` resolve the target release by
following the HTML `/releases/latest` redirect
(open-seed-engine `internal/upgrade/upgrade.go:207` `resolveLatest`, shared
by `seed upgrade` (`upgrade.go:279`) and `seed template upgrade`
(`internal/template/template.go:236` via `upgrade.ResolveLatest`). That
endpoint 404s for a private repo even with a Bearer token, because
github.com HTML does not honor token auth the way api.github.com does.
open-seed is public today, but anyone running open-seed from a private fork
hits `template_host_unreachable` regardless of credentials.

Origin: os-0f76f772 closed with the engine-side fallback "a separate
open-seed-engine change, out of scope for this repo"; the original gap card
os-bb20001f was cancelled when the repo went public without resolving this;
no open issue exists in open-seed-engine (verified 2026-08-24).

Cross-repo: the change lands in **open-seed-engine** (the Go engine), but the
plan file and the task card live in this (template) repo, mirroring
os-488323ec (the engine-side change carries no local task PR of its own and

## Where the change lands (open-seed-engine)

- `internal/upgrade/upgrade.go`:
  - Add `Token string` to `Options` and to the shared helper signature
    (`ResolveLatest`). Read from a single env var (below) at the CLI call
    sites; keep the helper pure so tests can pass it explicitly.
   - Make `resolveLatest` two-pass:
     1. **API pass** (only when a token is present AND the base is GitHub
        — the default base, or one whose host is a GitHub host, or an
        explicitly configured loopback test base). `GET
        <apiBase>/repos/<repo>/releases/latest` with
        `Authorization: Bearer <token>` and
        `Accept: application/vnd.github+json`. `apiBase` is derived from a new
        `SEED_API_BASE_URL` env var (injected so the test can point the API
        pass at its loopback `httptest` server independently of the HTML
        base), else `https://api.github.com`. On a 200, read `tag_name` from
        the JSON body (small struct
        `struct{ TagName string \`json:"tag_name"\` }`); validate it is a
        non-empty semver tag (reuse `parseTag`), else `refuse`.
        The loopback exception is load-bearing: the API-200, API-fallback,
        and non-semver cases all run against a loopback server, so the API
        pass must be reachable in tests even though the base is
        non-production.
     2. **Redirect pass**: the existing no-follow `/releases/latest` read.
        Used when there is no token, the base is non-GitHub-and-not-a-test
        base, or the API pass did not yield a tag (non-200 such as 403/404 on
        a private repo without a token, an older API shape, **or a transport
        error on `api.github.com`**).
   - **Fall-through, not fail-fast, on the API pass.** A transport/HTTP error
     from `api.github.com` (network down to the API host even when
     `github.com` is reachable) must NOT return code 7 immediately: it must
     fall through to the redirect pass, which is what a public-repo
     anonymous user already relies on today. Code 7
     (`release_host_unreachable`) is reported only when the **redirect pass
     also** fails. This is what keeps the public/anonymous path
     byte-identical to today (no token → API pass skipped entirely) and
     avoids regressing a user whose network permits `github.com` but not
     `api.github.com`.
- `internal/template/template.go`: pass the token through to
  `upgrade.ResolveLatest` (same env read). No other change.
- `cmd/seed/main.go:235` and `cmd/seed/template_cmd.go:40`: set the new
  `Options.Token` from `os.Getenv("SEED_GITHUB_TOKEN")` (fall back to
  `GH_TOKEN` if `SEED_GITHUB_TOKEN` is unset). Both commands already read
  `SEED_UPGRADE_BASE_URL` here, so the wiring is one line each.
- `internal/upgrade/upgrade_test.go`: table-driven tests with a loopback
  `httptest` server (both the HTML redirect and the API endpoint served by
  the fake, via `SEED_UPGRADE_BASE_URL` + `SEED_API_BASE_URL`) covering
  (a) token present + API 200 → returns the API `tag_name`; (b) token
  present + API 403/404 → falls back to the redirect and returns the
  redirect tag; (c) token present + API transport error → falls back to
  the redirect (code 7 only if the redirect also fails); (d) no token →
  API pass skipped, redirect path byte-identical to today; (e) API returns
  a non-semver `tag_name` → `refuse`. Keep the existing public/anonymous
  assertions green.
- `README.md` (engine): document `SEED_GITHUB_TOKEN`/`GH_TOKEN` and that it
  makes private-repo release resolution work; note the API endpoint and the
  redirect fallback.
