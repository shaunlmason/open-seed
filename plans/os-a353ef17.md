# Plan: engine: resolve latest release via api.github.com with optional token (private-fork fallback) (os-a353ef17)

`seed upgrade` and `seed template upgrade` resolve the target release by
following the HTML `/releases/latest` redirect
(open-seed-engine `internal/upgrade/upgrade.go:207` `resolveLatest`, shared
by `seed upgrade` (`upgrade.go:279`) and `seed template upgrade`
(`internal/template/template.go:236` via `upgrade.ResolveLatest`). That
endpoint 404s for a private repo even with a Bearer token, because
github.com HTML does not honor token auth the way api.github.com does.
open-seed is public today, but anyone running open-seed from a private fork
hits `template_host_unreachable` regardless of credentials.

Origin: os-0f76f772 closed with the engine-side fallback "a separate
open-seed-engine change, out of scope for this repo"; the original gap card
os-bb20001f was cancelled when the repo went public without resolving this;
no open issue exists in open-seed-engine (verified 2026-08-24).

Cross-repo: the change lands in **open-seed-engine** (the Go engine), but the
plan file and the task card live in this (template) repo, mirroring

## Where the change lands (open-seed-engine)

- `internal/upgrade/upgrade.go`:
  - Add `Token string` to `Options` and to the shared helper signature
    (`ResolveLatest`). Read from a single env var (below) at the CLI call
    sites; keep the helper pure so tests can pass it explicitly.
  - Make `resolveLatest` two-pass:
    1. **API pass** (only when a token is present AND the base is GitHub,
       i.e. the default base or one whose host is a GitHub host; for a
       non-GitHub/loopback test base skip straight to the redirect):
       `GET <apiBase>/repos/<repo>/releases/latest` with
       `Authorization: Bearer <token>` and `Accept: application/vnd.github+json`.
       `apiBase` is derived from `SEED_UPGRADE_BASE_URL` when set
       (so a loopback API fake works in tests), else `https://api.github.com`.
       On a 200, read `tag_name` from the JSON body (small struct
       `struct{ TagName string \`json:"tag_name"\` }`); validate it is a
       non-empty semver tag (reuse `parseTag`), else `refuse`.
    2. **Redirect pass**: the existing no-follow `/releases/latest` read.
       Used when there is no token, the base is non-GitHub, or the API call
       returned non-200 (403/404 on a private repo without a token, or an
       older API shape) — so the public/anonymous path is byte-identical to
       today.
  - Error name stays `release_host_unreachable` (code 7) for a genuine
    network/HTTP failure on the API pass too; a 404 that still has the
    redirect available falls through rather than erroring.
- `internal/template/template.go`: pass the token through to
  `upgrade.ResolveLatest` (same env read). No other change.
- `cmd/seed/main.go:235` and `cmd/seed/template_cmd.go:40`: set the new
  `Options.Token` from `os.Getenv("SEED_GITHUB_TOKEN")` (fall back to
  `GH_TOKEN` if `SEED_GITHUB_TOKEN` is unset). Both commands already read
  `SEED_UPGRADE_BASE_URL` here, so the wiring is one line each.
- `internal/upgrade/upgrade_test.go`: table-driven tests with a fake
  `httptest` server covering (a) token present + API 200 → returns the API
  `tag_name`; (b) token present + API 403/404 → falls back to the redirect
  and returns the redirect tag; (c) no token → API pass skipped, redirect
  path byte-identical to today; (d) API returns a non-semver `tag_name` →
  `refuse`. Keep the existing public/anonymous assertions green.
- `README.md` (engine): document `SEED_GITHUB_TOKEN`/`GH_TOKEN` and that it
  makes private-repo release resolution work; note the API endpoint and the
  redirect fallback.

## Steps

1. **Add the token plumbing + two-pass resolution** in
   `internal/upgrade/upgrade.go` as above, keeping `ResolveLatest` the single
   shared helper so `seed upgrade` and `seed template upgrade` both get the
   behavior with no duplication.
2. **Wire the env var** at both CLI call sites
   (`cmd/seed/main.go`, `cmd/seed/template_cmd.go`) using the same
   `SEED_UPGRADE_BASE_URL` pattern already there.
3. **Tests** in `upgrade_test.go` for the four cases above, using a loopback
   `httptest` server (the existing `SEED_UPGRADE_BASE_URL`/non-HTTPS-allowed
   on loopback rule already permits it) and an explicit token.
4. **Docs**: engine `README.md` upgrade/`template upgrade` section names the
   env var and the private-repo behavior. Then a one-line note in the
   template's `docs/handbook.md` upgrade section pointing at it (the consumer
   doc), so a private-fork user finds the fix.
5. **Build/verify** in open-seed-engine: `go build ./...`, `go test
   ./internal/upgrade/... ./internal/template/... ./cmd/seed/...` green; the
   public/anonymous path unchanged.
6. **Cross-repo close**: land the engine PR; in the template repo, close
   `os-a353ef17` via the D7 no-PR path with evidence citing the engine PR (as
