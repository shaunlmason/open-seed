## Design decisions (binding for this task)

- **D1 — the scoped exit is met; the pillar is not, and the record
  says both.** The build plan's Phase 8 exit line names two things:
  the same-rule-set property test (landed as 8.2's prefix-sweeping
  regression class, #163) and a stable, versioned envelope schema
  (`seed-envelope/0` with the spec's own bump discipline in
  `next/spec/envelope.md`). Both are met, so the phase exits. Charter
  III.I as a whole is **not** claimable at this exit, and the record
  walks all five rows rather than the two the exit line scopes.
- **D2 — rows 1, 2, and 4 are recorded MET with their carve-outs
  named, never glossed.** Row 1 (versioned schema-stable envelope,
  structured errors, meaningful exit codes, the verbs currently legal
  for this actor on this subject, the position it was computed at):
  met by #160, naming two bounded carve-outs the implementation
  already documents — a response carrying no actor+subject context
  (keyless read surfaces; probes must be signed, so a fingerprint
  alone cannot compute a list) carries the empty list, which is the
  honest answer where no such set exists rather than a gap; and
  `actor.enrolled` is listed only where the prober could supply the
  subject's public key, which no fingerprint-holder can derive. Row 2
  (same rule set, listed-refused-at-position a bug class with a
  regression test): met by #160's computation plus #163's sweep,
  which re-drafts every listed verb through the enforcing `Check` at
  every position of the shared scenario for all seven enrolled-lane
  pairs. Row 4 (refusal rates tracked as an affordance-gap metric):
  met by #165's attempts journal and report v10 section.
- **D3 — rows 3 and 5 are recorded UNMET and routed by amendment.**
  Row 3 (the CLI is the complete interface; a machine-protocol
  surface exposes identical semantics; platform parity including
  Windows documented and tested) has no machine-protocol surface and
  no platform-parity documentation or test today. Row 5 (matching
  promoted lessons surface in packets and envelopes at claim time)
  presupposes the curator's promoted-lesson store, which does not
  exist yet. Neither is routed anywhere in the build plan, so this
  task extends the build plan to name them where they land: row 3 as
  a new **Phase 13** item (the phase for Part III items Phases 0–12
  deliberately defer, whose exit line already gates full Part III
  conformance), with III.I added to that exit line's named criteria;
  row 5 in **Phase 11 item 2**'s own text, beside the applies-when
  the promotion gate already records. Full III.I conformance is
  therefore claimable only once Phase 11 and Phase 13 both close, and
  the record says so in those words.
- **D4 — one spec sentence is corrected in the same PR.**
  `next/spec/envelope.md` says `position` "is `null` until the ledger
  lands (Phase 1); from then on every response stamps it." That
  overclaims: a refusal that never opened a ledger (a malformed
  invocation) has no position to state, and the implementation
  correctly declines to fabricate one — the 8.3 seam rule turns on
  exactly this distinction. Replace the sentence with the truth
  (stamped by every response that read the ledger; `null` on
  refusals that never got that far, which never invent a position),
  keeping spec and frontier telling one story, exactly as the Phase 7
  record corrected `budgets.md`.
- **D5 — scope guard.** Docs and one spec sentence only: no code, no
  test, no phase/dependency renumbering, no new exit criteria beyond
  naming III.I on Phase 13's existing line. The v1-template
  ergonomics cards filed alongside this phase were **cancelled** under
  the operator's promotion-first directive (v1 is not extended; their
  durable obligations were re-aimed at Seed's own lane contracts in
  `os-68ea0b2d`), so the record cites no v1 work and claims no
  conformance from any.
- **D6 — the frontier states the destination, not just the next
  step.** The goal driving this work is Seed's **promotion**
  (spin-out): the build plan names spin-out in its ground rules and
  its escalation list but defines no criteria, phase, or cutover, so
  a reader who finishes every phase still has no stated finish line
  for "Seed can take over." Defining it belongs to card
  `os-768361cc`'s own plan-gated amendment, not to this record; what
  this record does is make the frontier name the destination and the
  path to it, so the next agent resumes toward promotion rather than
  merely toward the next phase number. No promotion criteria are
  asserted here — the frontier points at the card that will set them.

   marker, or one torn write poisons every later read (the attempts
