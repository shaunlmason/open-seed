# Plan: fastcards backend: SQLite builtin (os-94ac6371)

A second builtin engine backend for single-machine throughput: the R4 write
ceiling exists because every filecards verb is a fetch→commit→push on one
shared ref. For a solo dev hammering the loop locally, that is pure
overhead. fastcards keeps coordination state in a local SQLite database with
transactional atomicity: same verbs, same evaluator, same card format,
trading state portability for speed, and saying so.

## Steps

0. **Design amendment first** (authority rule: this plan does not override
   the design doc): a separate reviewed PR amends
   `docs/design-options.md` §7.3 (adding fastcards to the builtin backend
   roadmap) and §8 R4 (fastcards as the *single-machine* throughput
   answer, beads remaining the multi-writer one). That amendment must
   also make the **builtin/plugin boundary** explicit (§7.1/§7.5:
   builtin stores: filecards today, fastcards joining it, live inside
   the engine behind the same port and store interface; the plugin seam
   is for external substrates) and define the **local operator close
   path** (machine-local state means the CI close/maintenance lane does
   not apply: the solo human closes review cards locally through the
   port, evidence recorded on the card). Implementation of the steps
   below is authorized only after that amendment merges; this plan's
   approval alone changes nothing in the design.
1. **Store abstraction** (engine): extract the storage contract the task
   layer already uses (`Sync`, `ReadFile`, `ListDir`, `Halted`, `Mutate`
   with one-atomic-unit-per-verb semantics) into an interface implemented
   by the existing git state ref and by a new SQLite store. The SQLite
   store keeps the **same path-keyed layout** (`tasks/<id>.md` blobs,
   `run-log.jsonl` appends, `handoff/…`) so card parsing, effects, lint,
   and report code are reused unchanged; "head" is a monotonic transaction
   id. Pure-Go driver (`modernc.org/sqlite`, no CGO: the cross-compile
   matrix must not regress).
2. **Atomicity**: each verb runs in one `BEGIN IMMEDIATE` transaction:
   real atomic claims (the contention loser exits 2 without any push-wins
   emulation); leases and fencing behave identically to filecards.
   **SQLITE_BUSY is handled, not assumed away**: the connection sets a
   `busy_timeout`, and transaction acquisition wraps `BEGIN IMMEDIATE`
   in a bounded retry so a loser blocked by a live writer waits, re-reads
   the claimed card, and exits 2, never surfaces a raw SQLITE_BUSY as
   exit 5. The contention test holds the first transaction open while
   the rival attempts its claim, exercising exactly this path.
3. **Wiring**: manifest `entry = "builtin"` with `name = "fastcards"`; the
   engine selects the builtin store by backend name. The DB path resolves
   through **`git rev-parse --git-common-dir`** (never a literal `.git/`
   path): linked worktrees: the loop creates one per task, have a `.git`
   *file*, and resolving per-worktree would fragment coordination; the
   common dir gives every worktree the same claims DB. Never committed, no
   gitignore entry needed. `seed init` creates the schema. A
   linked-worktree integration test claims from the main checkout and
   observes the claim from a worktree (and the contention exit from a
   rival there).
4. **Declared variances** (backend README + capability manifest):
   `offline = "native"`, `atomic_claim = "native"`, and, so capability
   negotiation can *inspect* the variance rather than read prose: the
   manifest schema (`.seed/port-schema/backend.schema.json`) gains an
   optional `state_portability` field (`repo` | `replica` | `server` |
   `machine`); fastcards declares `machine` (existing manifests adopt
   the field in their own PRs). **State is
   machine-local**: it does not travel with clones, forks, or CI; the
   state-ref integrity story (anchors, HALT-by-lint, push-access trust) is
   replaced by local-filesystem trust; maintenance workflows that fetch
   the state ref see nothing (documented: fastcards is for local solo
   loops, not for repos where CI closes cards).
5. **Tests** (engine): the existing task-layer integration suite runs
   against both stores via the interface (claim contention, fencing,
   reap, cascade, lint where applicable); a throughput smoke asserts N
   sequential verbs complete without network; filecards suite unchanged.
6. **Migration is a real command, not a promise** (engine): `seed state
   export` dumps every card (ids, states, blocked_on, rejections,
   evidence, comments) plus the run log as one JSON document from the
   active store; `seed state import` loads that document into the newly
   configured backend **preserving ids and history** and refuses a
   non-empty target. A round-trip test moves representative cards
   filecards → fastcards → filecards losslessly. Without this, "switch
   backends" strands the source store's state behind a config line.
7. **Handbook §6**: position fastcards on the ladder: below beads, for
   one machine; switching is a config line **plus the export/import
   round-trip from step 6** (documented as the swap procedure), and the
   local operator close path from the design amendment is spelled out.

## File Scope

- Engine repo: `internal/stateref/` (interface extraction),
  `internal/fastcards/` (new), `internal/task/`, `cmd/seed/`, `go.mod`
- Template: `.seed/backends/fastcards/backend.toml`,
  `.seed/backends/fastcards/README.md`,
  `.seed/port-schema/backend.schema.json` (the `state_portability`
  field), `.seed/backends.lock.json`, `.seed/engine.lock` (the new
  engine release pin + checksums: a builtin backend exists only in the
  engine the shim actually downloads), `docs/handbook.md`
- Design (separate PR, step 0): `docs/design-options.md` §7.3 + §8 R4

## Acceptance Criteria

- The full task-layer suite passes against both stores; filecards
  behavior is byte-identical to before the interface extraction.
- Concurrent claims on the SQLite store produce exactly one winner; the
  loser: including one that hits a live writer's lock mid-`BEGIN
  IMMEDIATE`: waits out `busy_timeout`, re-reads, and exits 2 (never a
  raw SQLITE_BUSY failure), proven by a test that holds a transaction
  open during the rival claim.
- `seed state export | import` round-trips representative cards between
  filecards and fastcards preserving ids, states, dependency edges,
  rejection history, and evidence.
- Cross-compilation stays CGO-free for all six targets.
- The machine-local variance is declared in manifest + README + handbook.
