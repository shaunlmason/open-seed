# Plan: beads backend plugin (os-3e2a8d92)

The first external backend behind the port (design §7.1; research/10 Part 5 as
amended). Two halves: the engine's external-plugin dispatch seam (currently only
`entry = "builtin"` exists), and the beads plugin itself wrapping the `bd` CLI
(research: `docs/research/inspirations/01-git-native-task-substrates.md` §1).

## Steps

1. **Engine: external dispatch** (open-seed-engine repo): when
   `.seed/config.toml` names a backend whose manifest `entry` is not
   `builtin`, the shim verifies the plugin (backend.toml parses against
   backend.schema.json; when `.seed/backends.lock.json` carries a `sha256`,
   re-hash the plugin dir and refuse on mismatch: in-template plugins may pin
   `"source": "in-template"` with review as the control), then executes
   `.seed/backends/<name>/<entry> <verb> [args] --json` with a minimal
   environment (PATH/HOME plus manifest `requires_env` only), validates
   stdout against the envelope schema (`ok` + `schema_version`; type errors
   are exit 10 and the response is discarded), and passes exit codes through
   unchanged. Tests use a fake plugin executable.
2. **Template: `.seed/backends/beads/`**: `backend.toml` (capabilities:
   `atomic_claim = "native"`, `offline = "native"`, optional
   `lease-renew`, `dep`, `ready_squad`; `budget = "none"`),
   `bin/seed-backend` (POSIX sh wrapping `bd`, mapping below), `README.md`
   (install/pin `bd`, state mapping, declared variances), `test.sh` +
   `testdata/fake-bd` (contract test against the documented CLI, no real
   beads install needed), and the lock entry.
3. **Verb → bd mapping** (state model: port `backlog→deferred`,
   `ready→open`, `in_progress→in_progress`, `blocked→blocked`,
   `review→open + label seed:review`, `done→closed`,
   `cancelled→closed + label seed:cancelled`):
   - `create` → `bd create -t task -p <0..3> --description … --json`
     (+ `bd defer` to land in backlog); port priority P0–P3 → bd 0–3
   - `ready` → `bd ready --json --sort priority` (squad filter via
     `--label squad:<name>`)
   - `get`/`list` → `bd show/list --json`, states mapped back
   - `claim` → `bd update <id> --claim --json` (native, idempotent);
     claim contention → exit 2 with holder from `assignee`
   - `transition`/`release` → `bd update` status/assignee per mapping;
     review/cancelled via labels
   - `close` → `bd close <id> --reason … --json` (native blocker-cascade)
   - `comment`/`attach-evidence` → `bd comment` / `bd note`
   - `lease-renew` → bd lease heartbeat (re-claim is idempotent fallback)
   - `event-append` → **emulated**: task-scoped events become `bd comment`
     entries; bd's Dolt history is the audit substrate (declared in README:
     the seed run-log stays authoritative only for the filecards backend)
4. **Declared variances** (README + backend.toml, never silent): the fence
   token is **emulated** (assignee-match, not a rotating token: bd's
   `revision` is surfaced when available); leases are enforceable only on
   the granting replica (bd semantics); `review` is a label convention, so
   external bd users can move cards in ways the D1 table would refuse: the
   state lint's replay does not apply to this backend.
5. **Handbook §6**: make the upgrade path concrete (install bd, `bd init`,
   set `backend = "beads"`, migrate open cards with a documented one-shot
   `seed task list` → `bd create` loop).

## File Scope

- Engine repo: `internal/backend/` (new), `internal/task/` (dispatch seam),
  `cmd/seed/`
- Template: `.seed/backends/beads/**`, `.seed/backends.lock.json`,
  `docs/handbook.md`, `scripts/validate.sh` (wire the contract test)

## Acceptance Criteria

- With `backend = "beads"` and a fake `bd` on PATH, all nine required verbs
  round-trip through the plugin with schema-valid envelopes and correct exit
  codes (0/2/3/4/6 mapped per contract).
- The engine refuses a plugin whose directory hash mismatches its lock
  `sha256`, and discards schema-invalid plugin output with exit 10.
- Filecards behavior is unchanged (full existing suite green).
- Declared variances are in the plugin README and manifest, not discovered.

## Validation Commands

- `test -x .seed/backends/beads/bin/seed-backend`
- `sh .seed/backends/beads/test.sh`
- `sh scripts/validate.sh`
