# Plan: validate the beads plugin against a live bd install (os-435d7b61)

The beads adapter's contract test runs against `testdata/fake-bd` — a
reimplementation of the documented CLI surface. The README promises
validation against the real thing. This card delivers it: install a
**pinned** real `bd` (v1.2.x, installable via Go modules — verified
reachable), run the same contract corpus end-to-end against it, and
reconcile any drift (flags, JSON shapes, lease semantics) in whichever
artifact is wrong — the adapter if bd's real surface differs from what
we call, the fake if it differs from what it imitates.

## Steps

1. **Live-test harness**: `.seed/backends/beads/live-test.sh` — skips
   with a clear message when `bd` is not on PATH (CI stays green and
   credential-free); otherwise creates a scratch repo, `bd init`, and
   drives the SAME corpus as `test.sh` through the adapter against
   real bd: create/backlog landing, promote, ready ordering, claim +
   minted-token fence (rotation, stale-token exit 6), contention,
   plan parking + entry-exact unblock, reviewer lockout, close
   review-only, cascade on close AND cancel, comment/evidence ids,
   audit sink, `--state` list filter. Shared assertions are factored
   so the fake test and the live test cannot drift apart silently.
2. **Pin + install path**: the validated bd version is pinned in the
   README (install command incl. the module path, e.g.
   `go install github.com/steveyegge/beads/...@v1.2.2` — exact cmd
   path confirmed during implementation) and echoed by live-test on
   start; running against an unpinned version prints a warning, not a
   refusal (drift discovery is the point).
3. **Reconcile drift**: every divergence the live run surfaces is
   fixed where the truth is — adapter flags/parsing when bd's real
   CLI differs from our calls; `testdata/fake-bd` when the fake
   mis-imitates real output (fake fixes re-run the offline suite);
   genuine bd-version behavior changes are declared in the README's
   variance section. Nothing is silently tolerated.
4. **Wire-in**: `scripts/validate.sh` runs live-test after the fake
   suite (it self-skips without bd); the README's testing section
   documents both suites and the pin.
5. **Evidence**: the live run is executed in-session (bd installed
   from the pinned version) and its transcript attached to this card;
   LEARNINGS gains any drift found.

## File Scope

- `.seed/backends/beads/live-test.sh` (new),
  `.seed/backends/beads/test.sh` (shared-assertion factoring only),
  `.seed/backends/beads/bin/seed-backend` (drift fixes if surfaced),
  `.seed/backends/beads/testdata/fake-bd` (fidelity fixes if
  surfaced), `.seed/backends/beads/README.md`, `scripts/validate.sh`

## Acceptance Criteria

- live-test passes the full corpus against the pinned real bd, and
  self-skips (exit 0, explicit message) where bd is absent — CI
  needs no new binaries.
- Any adapter or fake drift surfaced by the live run is fixed at the
  source of truth and covered by the offline suite; remaining
  version-specific variances are declared in the README.
- The README pins the validated bd version with its install command;
  the card carries the live-run transcript as evidence.
