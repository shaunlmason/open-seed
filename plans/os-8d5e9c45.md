## Design: enforcement in two layers

A static lint cannot decide "this call writes under a projection root"
in general, so the boundary is enforced by a precise lint plus a
structural runtime layer, each with its own enforcing test:

1. **The lint (source layer).** A Go test in `next/internal/project`
   (being a test, it is wired into `check-next` by construction) that
   parses every non-test Go file under `next/` outside
   `next/internal/project/**` with `go/parser` and refuses any string
   literal from the publication vocabulary: exactly `"CURRENT"`,
   `"projection.json"`, and `"builds"`. Nothing outside the engine may
   construct projection paths by hand; consumers reach views only
   through the engine's exported read seam (`project.Current`, the
   `seed project current` verb once 4.2 lands). Test files stay
   exempt: drills read the published layout to assert it, and reading
   is not a boundary violation. The exemption and the literal set are
   stated in the spec as the lint's contract, so widening either is a
   reviewed spec change, not a quiet edit.
2. **Read-only publication (runtime layer).** The engine publishes
   every file in a build tree (the stamp, the view files, `CURRENT`)
   with mode `0444`. A direct overwrite by any code path then fails at
   the operating system, whatever the source tree missed. Directories
   keep default modes deliberately: on POSIX, unlink needs write
   permission on the parent directory, not the file, so **deletion
   (the sanctioned recovery operation) stays trivial** — `rm -rf` and
   the engine's own prune/discard paths still work — while in-place
   mutation of published bytes does not. Pointer swaps stay legal:
   `os.Rename` over a read-only `CURRENT` needs only parent-directory
   permission.

## Steps

1. **Publication modes.** In `next/internal/project`: publish build
   tree files and `CURRENT` with mode `0444`; verify prune, the
   same-id discard path, repeat rebuilds, and the interrupted-partial
   cleanup all still succeed over read-only files (they operate via
   parent directories).
2. **The lint test.** `boundary_lint_test.go` in
   `next/internal/project`: walk `next/`, parse non-test files outside
   the engine package, collect string literals, refuse the publication
   vocabulary with file:line in the failure. The detector itself is
   exercised against synthetic source fixtures (one violating file
   parsed from memory must be flagged; a clean one must not), so the
   lint failing to fire is itself a test failure — the enforcing test
   for the enforcer.
3. **Boundary drills.** After a rebuild: a direct `os.WriteFile` to a
   published view file and to the stamp fails without altering bytes;
   a direct write to `CURRENT` fails; deleting the whole output tree
   by ordinary recursive removal succeeds and the next rebuild
   reproduces it byte-identically (modes do not regress the Phase 4
   byte-identical drill, which hashes contents); the engine's own
   repeat-rebuild and interruption drills stay green over read-only
   trees.
4. **Spec.** Extend `next/spec/projections.md` with a "Write boundary"
   section: the two layers, the lint's literal set and test-file
   exemption, the read-only-files/writable-dirs trade and why deletion
   must stay easy (rebuildability is the recovery path), and the
   conformance-mapping update marking III.D's lint row implemented.

## Acceptance Criteria

**Boundary set (new, shown working):**

- The lint refuses publication-vocabulary literals in non-test code
  outside the engine, with a self-check proving the detector fires on
  a planted violation and stays quiet on clean source.
- Published build files and `CURRENT` carry mode `0444`; direct
  overwrites of a view file, the stamp, and the pointer fail without
  changing published bytes.
- Ordinary recursive deletion of the output tree succeeds without
  permission games, and the next rebuild reproduces the tree
  byte-identically.
- The engine's existing drills (repeat rebuild, same-id discard,
  interrupted publication, prune) pass unchanged over read-only
  publication.

**Retention set (existing, shown unharmed):**

- All existing verb suites pass unchanged
  (`cd next && go test ./internal/... ./cmd/... -count=1`).
- The repo-wide gate stays green with the ≥90% coverage gate
  (`make check`), which is what "lint wired into `check-next`" means
  here: the lint is a test in the suite `check-next` already runs.
