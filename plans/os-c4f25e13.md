# Plan: engine — accept must require the D7 exemption when no plan exists (os-c4f25e13)

`accept` (review → done) carries one precondition, `resolution_present`. It
checks that the operator said *something* evidences the work. It does not
check *what*: a card with no `plans/<id>.md` accepted without `--no-pr`
lands in `done` carrying a bare merged-PR URL, and the D3/D7
done-consistency lint (`internal/task/statelint.go:125`) fails on it from
then on, because the lint reads the `no-pr:` prefix and finds none.

`done` is terminal. `.seed/port-schema/transitions.json` declares exactly
one transition touching it (review → done via accept) and its own note says
so: "done is terminal, so no transition can repair it." Verified at the CLI
on 2026-09-07: `task close --no-pr` on a done card returns
`invalid_transition`; `task record-evidence --no-pr` returns
`evidence_already_recorded`; `reinstate` is `cancelled → backlog` only; the
port spec declares no amend, edit or repair verb. **No verb can add the
missing marker.**

Recovery is therefore out-of-band, and there are exactly two routes. The
first is a hand edit of the seed-state ref, which AGENTS.md forbids agents
and which is a protected surface. The second is to author a
`plans/<id>.md` after the fact: the lint resolves the plan by file, so the
file's existence satisfies it. #365 took that second route on 2026-09-07,
landing retrospective artifacts for all three live instances, and each says
plainly that it "does not retroactively confer plan approval: the
authorization of record is the human `accept` already on the card, and this
file exists so the lint can resolve `plans/<task-id>.md`."

That route works and it is honest, but it is recovery, not prevention, and
it is not free: it mints a plan document for work that was never planned,
so the D3 record grows entries whose own text says they are not plans. The
statement the situation actually wants is "this card legitimately required
no plan", which is precisely what the `no-pr:` marker means and precisely
what no verb can record after the fact. The cost of the missing flag is
therefore paid every time in ceremony or in a forbidden edit, and it is
paid under a halt: a failing lint refuses **every mutating verb for every
actor**, so the repository is stopped while somebody writes the artifact.
Observed 2026-09-07: HALT at 06:52 after three accepts at 06:26, resume at
07:18, HALT again at 07:38, resume at 07:41, cleared only once #365 landed.

**This exact defect has been fixed once already, and the precedent is the
design.** `RecordEvidence`'s doc comment records it: "`accept` used to take
an empty `--resolution`, and the resulting card failed the D7
done-consistency lint forever with no way back: a single missing flag could
red every PR in the repository. The companion half of this change refuses
that accept at the door, so this verb is the repair for cards created
before the refusal existed rather than a routine part of the loop." That
fix was two halves: a precondition at the door, and a bounded repair for
cards minted before it. This card is the same defect one field over, and
takes the same two halves.

Authority: `docs/CONTRIBUTING-AGENTS.md` (D3 plan gate, D7 no-PR
exemption), `docs/design-options.md` R10 (identity is asserted, enforcement
is push access plus server-attributed gates). Tier: standard. Cross-repo:
the implementation lands in **open-seed-engine**; the card and this plan
live in the template, mirroring os-a353ef17 and os-488323ec.

## Design decisions (binding for this task)

- **D1. The door: a second accept precondition, `plan_or_exemption`.**
  Accept refuses when the card has no resolvable `plans/<id>.md` and the
  request did not pass `--no-pr`, with `fail_error: plan_or_exemption`,
  `fail_exit: 3`, and a fail detail naming both remedies (land the plan, or
  accept with `--no-pr --resolution <artifact URL>`). It sits beside
  `resolution_present` on the same edge, declared in the table, evaluated in
  `internal/port`.
- **D2. The port stays a pure decision core; the caller supplies the
  facts.** `internal/port` has no filesystem and must not gain one: the
  engine's AGENTS.md names it "the pure decision core … which deliberately
  contains no policy of its own and reads the contract from the port-schema
  tables". So `port.Request` gains two supplied facts beside `Resolution`,
  `PlanPresent bool` and `NoPR bool`, computed by the task service (which
  holds `sv.Root`) and read by the precondition. This is exactly how
  `Resolution` already works: the caller supplies, the table decides. No
  second enforcement path is created.
- **D3. The table upgrade rides the existing seam.** `spec.ensureAcceptEvidence`
  already upgrades an accept edge whose shipped table predates its
  precondition, for the stated reason that the table ships in each consuming
  repository's `.seed/port-schema/` and moves independently of the binary.
  The new precondition is added to that same upgrade (renaming the helper to
  `ensureAcceptPreconditions`), so a consumer on an older table is protected
  by the binary alone and enforcement stays in one place.
- **D4. The lint does not change.** Treating any merged-PR evidence as
  satisfying D7 would let a card that genuinely skipped a required plan pass
  D3, which is the check's whole purpose. The `no-pr:` marker stays an
  explicit, attributable operator assertion that this card legitimately had
  no plan. Rejected alternative, recorded in the task PR's dead ends.
- **D5. No repair verb, and why one was considered.** An earlier draft of
  this plan added a narrowed `record-evidence` amend so an operator could add
  the marker to an already-done card, mirroring how `RecordEvidence` itself
  was added as the repair half of the empty-resolution fix. It is dropped.
  Every live instance was recovered by #365 before this plan was reviewed,
  and D1 prevents new ones, so the verb would ship with nothing to repair.
  A repair path for a case that cannot recur is dead code that still widens
  the surface able to rewrite a terminal card's evidence. If a future
  instance is somehow minted, the retrospective-artifact route remains, and
  the verb can be reconsidered then against a real customer. Recorded in the
  task PR's dead ends.

## Steps

1. **The precondition.** Add `plan_or_exemption` to `internal/spec`
   beside `acceptEvidence`; extend the upgrade helper to add both; add the
   `PlanPresent` and `NoPR` fields to `port.Request` and the case to
   `checkPrecondition`.
2. **The caller.** In `internal/task`, populate the two fields at the accept
   call site from `sv.Root` and the action's `NoPR`.
3. **Tests.** The drills below, in `internal/spec`, `internal/port` and
   `internal/task`.
4. **Docs.** The engine `README.md` accept/close section names the new
   refusal; the template's `.seed/port-schema/transitions.json` gains the
   declared precondition (protected surface: owner review), and
   `docs/CONTRIBUTING-AGENTS.md` names it beside the D7 exemption.
5. **Close.** The engine PR carries the implementation under its own D7
   no-PR exemption (the os-488323ec shape). The template card closes through
   the normal `seed/os-c4f25e13` task PR with a receipt citing the merged
   engine PR.

## Named drills

- **`TestAcceptRefusesPlanlessCloseWithoutExemption` (internal/task):** a
  card in review with no `plans/<id>.md` refuses accept with
  `plan_or_exemption` (exit 3) and stays in `review`; the same accept with
  `--no-pr` lands and writes the `no-pr:` prefix; a card that does have a
  plan accepts unchanged with no flag.
- **`TestAcceptPreconditionsUpgradeAnOlderTable` (internal/spec):** a table
  declaring neither precondition gains both; one declaring only
  `resolution_present` gains the second; one declaring both is left
  byte-identical.
- **`TestLintStillRefusesAPlanlessDoneCard` (internal/task):** the D3/D7
  rule is unchanged: a done card with neither a resolvable plan nor the
  marker still fails `lintDone`, one carrying the marker passes, and one
  carrying a plan file passes. This pins D4 so a later change cannot quietly
  soften the lint into accepting any merged-PR evidence.

## Acceptance Criteria

**Boundary set (new, shown working):**

1. Accepting a card with no resolvable plan and no `--no-pr` refuses
   `plan_or_exemption` at exit 3, leaves the card in `review`, and names both
   remedies; with `--no-pr` it lands carrying the marker.
2. A table shipped before either precondition gains both from the binary, so
   a consumer on an older `.seed/port-schema/` is protected without updating.
3. The D3/D7 lint is byte-unchanged in behavior: plan-less and marker-less
   still fails, marker passes, plan passes.

**Retention set (existing, shown unharmed):**

- `resolution_present` still refuses an empty resolution; every other
  precondition, transition and effect is unchanged; `done` remains terminal
  with accept its only inbound edge.
- `record-evidence` is untouched in every path, including its
  `evidence_already_recorded` refusal.
- The lint's other rules (accepted review block, non-empty evidence,
  operator roster) are untouched, and a done card with a plan and no marker
  still passes.
- `gofmt -l .` empty, `go vet ./...`, `go build ./...`, `go test ./...` green
  in the engine; `make check` green in the template.

## Validation Commands

The substantive change on this card lands in `open-seed-engine`, a separate
repository. What lands *here* is the contract row the engine reads, so these
are the commands this repo's receipt gate (D4.5) can execute against this
repo's diff, and every one of them runs for real.

- Boundary: `test "$(jq -r '[.transitions[] | select(.verb=="accept") | .preconditions[].name] | index("plan_or_exemption")' .seed/port-schema/transitions.json)" != "null"`
- Retention: `scripts/seed spec lint`
- Retention: `make check`

The boundary command discriminates: it exits 1 against the table on the
default branch and 0 once the row is declared.

**Why no `$SEED_ENGINE_SRC` commands.** An earlier draft of this section
guarded two engine commands on `$SEED_ENGINE_SRC`. The verify job never sets
that variable, so a `test -n "$VAR" && ...` guard exits 1 and fails the gate,
while a guard that skips instead exits 0 without running `go test`, `gofmt`,
`go vet` or `go build`. The second is worse than the first: it converts
absent validation into a green receipt, which is exactly what D4.5 says the
gate must not do. Provisioning an engine checkout inside the gate is a
`.github/**` change that a plan PR may not make, and a plan file that clones
a remote is shell this repo executes with the workflow's credentials, which
D3 is explicit about not wanting. So the engine commands are recorded as
prose below rather than executed vacuously.

## Engine-side validation

Gated by `open-seed-engine`'s own CI on the pull request carrying the change:
`gofmt -l .` empty, `go vet ./...`, `go build ./...`, `go test ./...`. From a
checkout of that repo the three drills this card adds are reproduced with
`go test ./internal/spec/... ./internal/port/... ./internal/task/... -run
'AcceptRefusesPlanless|AcceptPreconditionsUpgrade|LintStillRefusesAPlanless'
-count=1`.

These are deliberately not listed under `## Validation Commands`: that
section is executed by this repo's gate, and a command that cannot run there
must not sit in it. The task PR cites the engine pull request so the two
halves are linked from the record.

## Expected diff shape

One precondition declared beside an existing one, two supplied fields on the
port request, and three drills; a README paragraph, one declared table row in
the template, and the record files. Roughly 5 to 8 engine files and 4
template files, comfortably under 300 net lines. No new verb, no relaxed
refusal, no new state, no change to terminality or to the lint, and no
second enforcement path.
