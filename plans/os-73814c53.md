# Plan: Linear backend adapter (os-73814c53)

External plugin over Linear's GraphQL API: the cleanest external
state-model fit surveyed: Linear's default team workflow (Backlog, Todo,
In Progress, In Review, Done, Canceled) maps onto the port states with no
label tricks at all.

## Steps

1. **Adapter**: `.seed/backends/linear/bin/seed-backend` (POSIX sh +
   curl + jq) speaking GraphQL to `https://api.linear.app/graphql`. Env
   via `requires_env`: `LINEAR_API_KEY`, `LINEAR_TEAM_ID`. Verb mapping:
   - `create` → `issueCreate` (state Backlog); priority P0–P3 → Linear
     urgent/high/medium/low
   - `ready` → issues query filtered to state name `Todo`, unassigned
   - `get`/`list` → issue queries; state mapping **by workflow state
     name** against the documented convention (Backlog→backlog,
     Todo→ready, In Progress→in_progress, In Review→review,
     **Blocked→blocked**: a required custom state teams add once,
     documented with a one-click setup note: Done→done,
     Canceled→cancelled). The adapter refuses with exit 5 and a clear
     message when the team's workflow lacks one of these states
     (declared requirement, README table). Without a Blocked state, plan
     parking (`in_progress → blocked`) would be impossible for every
     above-L1 task, so it is part of the convention, not optional.
   - `claim` → read assignee, refuse with exit 2 + holder if set,
     **refuse with exit 2 `rejected_author` when the caller carries the
     `seed:rejected:<actor>` label** (the D1 lockout, persisted in
     Linear labels exactly as the beads adapter does: review submission
     labels the implementer `seed:author:`, reject converts it), else
     `issueUpdate` assignee + state In Progress. **Emulated**: Linear's
     update is last-write-wins, so there is a read-check race window:
     declared, same honesty rule as filecards' push-wins but weaker
     (no server arbitration). Fence = assignee-match (exit 6).
     `ready` filters rejected authors and blocked-entry carriers too.
   - `transition`/operator verbs → `issueUpdate` to the mapped state;
     unsupported target → exit 3. Parking persists `blocked_on` entries
     as `seed:bo:<entry>` labels; `plan-unblock`/`unblock` remove only
     their own entry and release only when the set empties.
   - `close` → **Done only, and only from review** (the binding
     transition table defines close as accept + cascade, review → done;
     any other source state is the server-agnostic exit 3). Cancellation
     is the separate `cancel` verb → Canceled. **Both close and cancel
     run the required cascade** (the table puts the cascade effect on
     every nonterminal→cancelled edge too: declaring the optional `dep`
     *editing* verb absent does not waive it): dep entries from
     `--blocked-by` ride `seed:bo:dep:<id>` labels; close/cancel remove
     their entry everywhere and move blocked issues whose set empties
     back to Todo, returning the released ids in `cascaded`. Contract
     cases cover the cascade on close AND on cancel, and close refused
     outside review.
   - `comment`/`attach-evidence` → `commentCreate`; `event-append` →
     comment on the task, Linear's own history is the audit substrate
   - `lease-renew` → no-op success (no lease concept; declared)
2. **Manifest + lock**: `atomic_claim = "emulated"`, `offline = "none"`,
   `budget = "none"`; in-template lock entry.
3. **Contract test**: `test.sh` + `testdata/fake-linear` (Python3
   `http.server` implementing the GraphQL subset with in-memory state).
   Covers every required verb, claim race refusal, missing-workflow-state
   refusal. Wired into validate.sh behind the python3 guard.
4. **README**: API key scopes, team workflow requirement table, declared
   variances (last-write-wins claim window, no leases, server is truth;
   the cascade is **emulated via `seed:bo:*` labels**: implemented and
   tested, never described as absent; its limitation is that label
   bookkeeping is only as trustworthy as label write access), rate-limit
   note.
5. **Handbook §6**: one line adding Linear to the backend menu.

## File Scope

- `.seed/backends/linear/**`, `.seed/backends.lock.json`,
  `scripts/validate.sh`, `docs/handbook.md`

## Acceptance Criteria

- All nine required verbs round-trip against the fake server with valid
  envelopes and mapped exit codes; claim contention exits 2 with holder;
  missing workflow state exits 5 with a remediation message.
- Plan parking round-trips (park with `plan:<pr>`, `get` surfaces it,
  plan-unblock releases only when the set empties); a rejected author's
  claim exits 2 and `ready` hides the card from them; closing **or
  cancelling** a blocker readies its dependents (both cascades covered
  by the contract test); close outside review exits 3.
- No engine changes (v0.7.0 dispatch seam suffices); existing backends'
  validate chain unchanged.
- Every variance declared in README + manifest.

## Validation Commands

- `test -x .seed/backends/linear/bin/seed-backend`
- `sh .seed/backends/linear/test.sh`
- `sh scripts/validate.sh`
