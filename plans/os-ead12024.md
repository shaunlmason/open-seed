# Plan: next Phase 1.2 — chain append/verify, segment storage, HEAD (os-ead12024)

Implements [`docs/next-build-plan.md`](../docs/next-build-plan.md) Phase 1
item 2: `next/internal/ledger`, the append-only chain over
`next/internal/event` (os-aa146827) with the fixed-default storage layout
(JSONL segments, one file per UTC day, `HEAD` record with tip hash). Design
authority: [`SEED-NEXT.md`](../SEED-NEXT.md) Part II §1; encodings per
[`next/spec/protocol.md`](../next/spec/protocol.md). Conformance: III.A —
the chain verifies from genesis in one command path, any mutation within
retained history is detected, ordering authority is admitted ancestry.

## Steps

1. **Store.** `ledger.Store` rooted at a directory (the future checkout of
   `refs/seed/ledger`): segments under `segments/<YYYY-MM-DD>.jsonl` (UTC day
   of append), one ledger record per line; `HEAD` (JSON: tip hash, event
   count, last segment) rewritten atomically on append. Reads stream in
   segment-name order, then line order; the derived position of an event is
   its zero-based ordinal in that stream (the projection/citation ordinal
   the spec derives, never asserts). **Segment names never regress**: an
   append whose UTC day sorts at or after the newest existing segment opens
   or extends that day's file; if the host clock reads *earlier* than the
   newest segment name (clock regression), the append continues in the
   newest existing segment rather than creating an older-named file, so the
   read order can never place a record before its `prev`.
2. **Append, with segments as truth.** The segment stream is authoritative
   and `HEAD` is a derived cache of it. `Append(record)` derives the true
   tip by reconciling: read `HEAD`, then scan forward from its claimed
   position to the end of the segment stream (cheap when clean, correct
   when a crash left `HEAD` stale). It verifies the record's signature,
   checks `prev` cites the derived tip hash (the empty hash for the first
   event), appends the line durably, then rewrites `HEAD` atomically
   (temp + rename). A crash between the line write and the `HEAD` rename
   therefore cannot fork the chain: the next open reconciles `HEAD` forward
   from the stream and the half-recorded state heals. Refusals are typed
   errors (bad signature, wrong prev, tip mismatch) so later phases map
   them to envelope codes.
3. **Verify.** `VerifyFromGenesis()` replays every record: recompute JCS
   bytes, check hash linkage from the empty hash forward, verify every
   signature, confirm `HEAD` matches the replayed tip (a stale-but-behind
   `HEAD` is reported distinctly from a wrong one); report the first
   failure with its position and reason. This is the engine `seed ledger
   verify` (Phase 1.7) will call.
4. **Corrupted fixtures + tests** (conformance III.A): fixture chains under
   `testdata/` — valid multi-day chain, reordered events, rewritten payload,
   forged signature, bad `prev`, truncated tail, `HEAD` mismatch — each
   detected with the right reason; append/tip round-trips; UTC day-boundary
   segment split; **crash injection between the segment-line write and the
   `HEAD` rename** (simulated by writing the line and skipping the rename):
   the next open reconciles and the next append extends, never forks;
   **clock-regression injection** (injected clock earlier than the newest
   segment name): the append lands in the newest segment and read order
   stays linear; atomic `HEAD` rewrite mechanics (temp + rename).

## Acceptance Criteria

**Boundary set (what this task adds, shown working):**

- Append maintains `prev` linkage from the empty hash; the derived ordinal
  is computable from the stream; no writer-asserted sequence numbers exist
  anywhere in the package.
- `VerifyFromGenesis` accepts the valid fixture and rejects every corrupted
  fixture (reorder, rewrite, forged sig, bad prev, truncation, HEAD
  mismatch), each with a distinct typed reason naming the failing position.
- Segments split on UTC day boundaries and never regress in name; the
  clock-regression test shows an append under a backdated clock landing in
  the newest segment with linear read order.
- The crash-injection test shows a durable segment line with a stale `HEAD`
  healing on the next open: no sibling record, no fork, the next append
  extends the stream.
- `HEAD` converges to the true tip after every append and every
  reconciliation; the store never mutates or deletes an existing line.

**Retention set (what already works, shown unharmed):**

- Phase 0 CLI behavior: `seed version` still emits the v0 envelope and
  refuses extra operands (`cd next && go test ./cmd/... -count=1`).
- Phase 1.1 event core: JCS vector, mutation-breakage, wrapper round-trip,
  fingerprint and key-loading suites still pass unchanged
  (`cd next && go test ./internal/event/... ./internal/envelope/... -count=1`).
- The repo-wide gate stays green, coverage gate (≥90% on
  `next/internal/...`) included (`make check`).
