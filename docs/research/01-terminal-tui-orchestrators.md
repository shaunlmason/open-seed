# Research: Parallel Coding Agents: Terminal (TUI/CLI)

> Category survey of [awesome-agent-orchestrators](https://github.com/andyrewlee/awesome-agent-orchestrators),
> researched 2026-08-21 for the open-seed design study. Focus: which patterns can live
> *inside* a template repo (config, scripts, conventions) vs. require an external app.

All 14 repos were live and fetchable. Findings per project, then synthesis oriented toward what open-seed can check into a template repo.

---

## 1. buhuipao/agent-console: Rust, 15 stars, 27 commits
(a) Local terminal dashboard that discovers, monitors, and resumes existing Codex and Claude Code sessions across workspaces. (b) Topology: not an orchestrator: a passive monitoring/resumption layer over independent parallel sessions; no coordination. (c) Tasks = sessions, grouped by workspace, with status (working/waiting/idle/failed); titles derived from the first user prompt; searchable index over prompts and summaries. (d) Isolation: tmux-style persistent shell panes in the agent's own workspace; state under `~/.local/state/agent-console`. (e) Guardrails: essentially none; an out-of-conversation summarizer process (disableable via `AGENT_CONSOLE_SUMMARIZER=off`). (f) Config: `~/.config/agent-console/config.toml`; nothing checked into user repos. (g) Agents: Claude Code, Codex only. (h) Very early (15 stars). (i) Steal: the idea of indexing/searching sessions by first prompt + summary is a nice convention for naming task records.

## 2. asheshgoplani/agent-deck: Go, 769 stars, 2,849 commits, very active
(a) "AI agent command center": terminal session manager orchestrating multiple agents across projects. (b) Topology: the richest in the category: **hierarchical**: persistent "conductor" sessions supervise child sessions, detect waiting/error states, and escalate remotely via Telegram/Slack; declarative session groups with concurrency caps and per-group accounts; parent-child dispatch linkage. (c) Tasks: polled status per session (running/waiting/idle/error), notification bar, real-time cost dashboard (token usage + spend, SQLite-backed). (d) Isolation: git worktrees (with sparse-checkout inheritance for monorepos), tmux with optional socket isolation, and optional Docker sandboxes with auto-injected host auth. (e) Guardrails: cost budgets (`[costs.budgets]` daily/weekly/monthly), MCP socket pooling with crash recovery, HMAC-verified GitHub webhooks with event dedup. (f) Config: global TOML at `~/.config/agent-deck/config.toml`; **checked into the repo**: `.agent-deck/worktree-setup.sh` (imperative per-worktree setup), `.agent-deck/skills.toml`, and `.worktreeinclude` (copies gitignored files like `.env` into new worktrees). Also ships `skills/agent-deck/SKILL.md` and `.github/skills/agent-deck-contributor` for AI-assisted contribution. (g) Agents: Claude Code, Gemini CLI, OpenCode fully; Codex, Copilot, Crush, Cursor, DeepSeek partially; custom via `[tools.*]`. (h) Mature and fast-moving. (i) Steal: `.worktreeinclude` + `worktree-setup.sh` as checked-in worktree bootstrap contract; cost budgets; the "conductor" pattern as a documented role rather than a daemon.

## 3. YoanWai/agent-manager: Go, 345 stars, 449 commits
(a) tmux-based TUI managing multiple AI agents in parallel with live status, diff review, and worktree support. (b) Topology: flat, single-user parallel sessions in a private tmux server (`agentmgr` namespace, `am_*` sessions), groupable/foldable by project. (c) Tasks: session list with built-in status detection per agent CLI; prompts sent without attaching. (d) Isolation: tmux sessions + optional per-session worktrees at `<repo>-worktrees/<name>` with branch convention `am/<name>`; no containers: reuses the user's own logins/MCP config. (e) Guardrails: notable **human-in-the-loop review**: `ctrl+r` opens syntax-highlighted full-file diffs with line-level commenting; comments compile into a review prompt sent back to the agent. (f) Config: TOML, user-level; `[tools.<name>]` blocks for custom tools with status rules; nothing repo-checked-in. (g) Agents: Claude Code, OpenCode, Codex, Grok Build, Gemini CLI, Pi, Hermes; generic fallback. (h) Healthy mid-size. (i) Steal: the diff-comment → review-prompt loop; branch/worktree naming conventions (`am/<name>`, sibling `-worktrees` dir).

## 4. agent-of-empires/agent-of-empires: Rust, 3.1k stars, 2,161 commits
(a) Terminal + web session manager for many agents with worktree isolation and container sandboxing. (b) Topology: flat parallel sessions across branches; sessions persist through disconnects; multi-repo workspaces (one session driving several repos). (c) Tasks: real-time status (running/waiting/idle/error) in TUI and a web dashboard with structured plan panels, tool-call cards, and "swipe-to-approve" via the Agent Client Protocol (ACP). (d) Isolation: tmux + git worktrees + optional Docker/Podman with shared auth volumes. (e) Guardrails: per-project repo config & hooks; diff review before applying. (f) Config: per-project settings implied in a `.aoe/` directory; session state in home dir. (g) Agents: widest list in category: Claude Code, OpenCode, Mistral Vibe, Codex, Gemini, Antigravity, Cursor, Copilot, Pi.dev, OMP, Factory Droid, Hermes, Kiro, Qwen Code, Kimi Code. (h) One of the two big projects here; very active (122 issues). (i) Steal: approval-oriented structured views (ACP) and per-project hooks directory.

## 5. madarco/agentbox: TypeScript, 367 stars, 1,133 commits
(a) Infrastructure tool running agents in parallel sandboxed boxes (Docker locally or cloud VMs: Hetzner, Daytona, Vercel, E2B, DigitalOcean). (b) Topology: flat parallel boxes (`agentbox claude`, `agentbox attach <n>`). (c) Tasks: an in-box `agentbox-ctl` daemon tracks "services + tasks"; `agentbox status` and a dashboard. (d) Isolation: strongest in category: Docker containers with FUSE overlay filesystem for workspace layering, checkpoint snapshots, tmux for persistent shells; git credentials stay on host with explicit permission requests to push. (e) Guardrails: sandbox-by-default; push gating. (f) Config: **`agentbox.yaml` checked into the project**, defining workspace defaults, services, tasks, setup wizards; layered global → project → workspace. Also carries `AGENTS.md` and a `.claude-plugin`. (g) Agents: Claude Code primarily, Codex, OpenCode. (h) Solid, active. (i) Steal: a checked-in `agentbox.yaml`-style declarative "services + tasks + setup" file; the layered config precedence model.

## 6. umputun/agterm: Swift, 484 stars, 689 commits
(a) Native macOS minimalist terminal with a full control API, built for watching many concurrent agent sessions. (b) Topology: named workspaces containing parallel long-lived sessions; grid dashboard of live output. (c) Tasks: status glyphs per session row ("active, blocked, or completed") reported by agents. (d) Isolation: plain shell sessions with own scrollback; no tmux/worktrees/containers. (e) Guardrails: none. (f) Config: `keymap.conf`; nothing repo-checked-in; ships an installable "agent skill" so agents can drive the terminal ("Help → Install Agent Skill"). (g) Agents: Claude Code, Codex, Pi, OpenCode. (h) Niche but active; macOS-only. (i) Steal: distributing an agent-facing skill/cookbook so the agent knows how to use the surrounding tooling: directly analogous to checking a `SKILL.md` into a template repo.

## 7. andyrewlee/amux: Go, 148 stars, 867 commits
(a) TUI orchestrating parallel agents on git worktrees + tmux, with confirmation-gated git write actions. (b) Topology: flat parallel workspaces. (c) Tasks: workspaces as units; two explicit gated write ops: `c` commit, `M` merge (`git merge --no-ff`), which refuses if the base branch isn't checked out in the primary repo. (d) Isolation: worktrees + tmux (≥3.2); repo git hooks disabled by default during its operations (`AMUX_ALLOW_GIT_HOOKS` to override). (e) Guardrails: **trust approval system for repo-supplied scripts**: commands in `.amux/workspaces.json` are gated until explicitly approved (tracked in `~/.amux/trusted-scripts.json`); conflict detection with abort-not-autoresolve; archive scripts time-boxed to 2 min. (f) Config: **checked-in `.amux/workspaces.json`** with exactly three lifecycle commands: `setup-workspace` (once per new workspace), `run` (dev server, port-parameterized via `AMUX_PORT`), `archive` (cleanup pre-deletion). User config in `~/.amux/config.json`. Ships `docs/ORCHESTRATION.md`: a documented tmux-level contract for *external* orchestrators. (g) Agents: Claude Code, Codex, OpenCode, Droid, Cursor, Pi, Antigravity, FX, Grok, Amp, Cline: "no wrappers." (h) Small but disciplined (extensive ARCHITECTURE/LINTING docs). (i) Steal: the minimal three-verb lifecycle contract (`setup`/`run`/`archive`) and the trust-gating of checked-in scripts; `AMUX_PORT`-style port allocation to avoid dev-server collisions.

## 8. smtg-ai/claude-squad: Go, 8.3k stars, 222 commits, AGPL-3.0
(a) The category-defining terminal app managing multiple agents in isolated workspaces. (b) Topology: flat parallel sessions ("instances"), with an auto-accept ("yolo") background mode. (c) Tasks: TUI instance list with preview and diff tabs. (d) Isolation: the canonical **tmux session + git worktree per task** pairing. (e) Guardrails: `c` checkout: "commit and pause the session" for human review before push; diff inspection. (f) Config: `~/.claude-squad/config.json` with named program profiles; nothing checked into repos. (g) Agents: Claude Code, Codex, Gemini, Aider, any local CLI via `-p "program"`. (h) Most-starred, but relatively few commits: a popular archetype more than an evolving platform. (i) Steal: mostly the archetype itself; "commit-and-pause" as an explicit review gate is worth encoding as a convention.

## 9. standardagents/dmux: TypeScript, 1.7k stars, 747 commits
(a) "Development agent multiplexer": a tmux pane + dedicated worktree/branch per task. (b) Topology: flat parallel panes; multi-select to launch several agents at once. (c) Tasks: durable panes that restore directory and *resume the agent's conversation* when recreated. (d) Isolation: worktrees + tmux panes; no containers. (e/f) Guardrails & config converge on one strong idea: a **checked-in `.dmux-hooks/` directory of lifecycle scripts**: run on worktree create, pre-merge, post-merge, etc.: plus "smart merging" (auto-commit, merge, clean up in one step) and a built-in file browser. Repo also carries `AGENTS.md` and `CLAUDE.md`. (g) Agents: Claude Code, Codex, OpenCode, Cline, Gemini, Qwen, Amp, pi, Cursor, Copilot, Crush. (h) Large and active. (i) Steal: `.dmux-hooks/`: named lifecycle hook scripts in-repo is exactly the checked-in guardrail surface open-seed wants (pre-merge = the natural quality gate slot).

## 10. ogulcancelik/herdr: Rust, 31.3k stars, 2.2k forks, 1,456 commits
(a) A background terminal-multiplexer *runtime* ("one rust binary, no electron") that owns agents' terminals and lets them coordinate. (b) Topology: closest to a **peer swarm**: agents "spawn panes, prompt each other, and wait until another agent is genuinely blocked" via CLI + socket API: agent-to-agent tasking without a fixed hierarchy. (c) Tasks: every pane marked working/blocked/idle; blocked-and-needs-answer surfaced explicitly. (d) Isolation: server-side persistent sessions (survive lid-close, network drop, restart; reattach over SSH); tmux-compatible. (e) Guardrails: only dev-side (`just check`). (f) Config: not repo-based, but the repo itself demonstrates the pattern: `AGENTS.md`, `CLAUDE.md`, `skills/herdr/` skill directory, plugin marketplace (agentbox even ships a `herdr-plugin.toml`). (g) Agents: "claude code, codex, cursor, opencode, grok and th rest — herdr doesn't wrap or replace them; it owns their terminals." (h) The runaway hit of the category. (i) Steal: the primitive set: spawn / prompt / wait-until-blocked: as the minimal vocabulary for inter-agent coordination; shipping a `skills/<tool>/` directory so agents can learn the tool.

## 11. TechDufus/openkanban: Go, 141 stars, 118 commits
(a) TUI **kanban board** where each ticket spawns an agent in its own worktree with an embedded terminal. (b) Topology: flat; one agent per ticket. (c) Tasks: the kanban board *is* the task system: columns as workflow stages, `space` advances a ticket. (d) Isolation: worktree + isolated branch per ticket; no tmux or containers. (e) Guardrails: none documented. (f) Config: `~/.config/openkanban/config.json` (agents, keybindings, branch naming, cleanup); nothing repo-checked-in. (g) Agents: "Anyagent — OpenCode, Claude Code, Gemini, Codex, Aider, or whatever CLI." (h) Young. (i) Steal: the ticket↔branch↔worktree 1:1:1 mapping, and configurable branch-naming tied to task IDs: trivially expressible as a checked-in markdown/JSON convention.

## 12. AliHamzaAzam/repomon: Rust/Tauri, 16 stars, 728 commits
(a) "Mission control" desktop app + TUI for fleets of agents across many repos. (b) Topology: hierarchical: an orchestrator agent ("repomind") autonomously spawns workers, answers permission prompts, and merges finished work; MCP server exposes fleet status; "fleet mail" addresses one agent, a lane (`lane-12/*`), or all (`*`). (c) Tasks: "lanes" (repo × worktree), sorted by needs-you-first. (d) Isolation: worktrees + tmux (bundled portable tmux; ConPTY host on Windows). (e) Guardrails: the most explicit **autonomy budget** in category: per-session action cap (100), concurrent-agent limit (4), 15-second dedup, two-phase confirm for lane deletion, three autonomy levels (`autonomous`/`supervised`/`read-only`). (f) Config: none checked into repos; systemd/launchd service. (g) Agents: Claude Code, Codex, Antigravity, OpenCode, Cursor, Aider. (h) Tiny audience despite heavy engineering. (i) Steal: numeric autonomy budgets + named autonomy levels: perfect content for a checked-in guardrails config that hooks can enforce.

## 13. Thurbeen/thurbox: Rust, 48 stars, 1,155 commits
(a) TUI orchestrator with persistent tmux sessions and a fully Lua-customizable interface. (b) Topology: flat parallel sessions, plus session forking with recorded parent-child lineage; remote SSH/WSL hosts via `hosts.toml`. (c) Tasks: built-in todo list (`thurbox-cli task`) whose items connect to agents via Send/Spawn actions. (d) Isolation: per-session worktrees (`--worktree-branch`), multi-repo sessions via a shared symlink workspace; tmux (psmux on Windows). (e) Guardrails: **capability-by-absence plugin sandboxing**: Lua plugins get no `io`/`os`/`debug`/`package` unless the user grants capabilities; `plugin check` validates before load. (f) Config: TOML in `~/.config/thurbox/` (`agents.toml` defining agent CLIs as data: command + args templates: plus `hosts.toml`, `settings.toml`, `plugins.lock`); nothing repo-checked-in. (g) Agents: Claude, Codex, Antigravity, OpenCode, Aider, Vibe, Copilot; any CLI addable as data. (h) Prolific solo project; v2 unstable. (i) Steal: defining agent harnesses as *data* (command templates in TOML) rather than code: ideal for a checked-in `agents.toml` in a template.

## 14. wavyrai/tmux-ide: TypeScript, 539 stars, 1,437 commits
(a) An additive agent-aware UI layer over plain tmux. (b) Topology: peer coordination over a **shared status bus**: agents task each other by writing to prompts and block on teammates. (c) Tasks: ground-truth working/blocked/done detection via Claude Code hooks, or a one-line self-report any agent can emit: `tmux set-option -p @agent_state "working:$(date +%s)"`; toasts on blocked/done; `tmux-ide wait output %2 --match "tests passed"` / `wait agent-status api --status done` exit 0/1 for scripting. (d) Isolation: tmux + optional worktree flow (worktree + adopted session per branch); crash-safe because everything is plain tmux config. (e) Guardrails: none beyond observability. (f) Config: **checked-in `.tmux-ide/workspace.yml`** (versioned schema: `version: 1`, `name`, `terminal.rows[].panes[]` with `title`/`command`/`focus`/`size`); legacy `ide.yml` migrates via `tmux-ide migrate`; `tmux-ide init` auto-detects the stack and scaffolds it. (g) Agents: Claude Code natively; Codex, cursor-agent, Aider, any agent via self-report protocol. (h) Active and well-documented. (i) Steal: three things: the versioned checked-in workspace layout; the one-line vendor-neutral status protocol; `wait` as a shell-scriptable synchronization primitive.

# SYNTHESIS

**The common denominator is unambiguous: tmux + git worktrees, one agent per worktree/branch, with polled status detection.** 10 of 14 projects (claude-squad, dmux, amux, agent-manager, agent-of-empires, agent-deck, openkanban, repomon, thurbox, tmux-ide) build on exactly this substrate. Containers/VMs are a *premium optional layer* (agentbox, agent-deck, agent-of-empires), never the default. Topology is overwhelmingly flat single-user parallelism; hierarchy appears only in the two most ambitious tools (agent-deck's conductors, repomon's repomind), and peer-swarm coordination only in herdr and tmux-ide: both achieved via a tiny primitive set (spawn, prompt, wait-until-blocked) rather than a planner. The near-universal status vocabulary is a four-state enum: **working / waiting(blocked) / idle / error(done)**: this is effectively a de-facto standard. Task tracking is thin everywhere: sessions *are* tasks in most tools; only openkanban (kanban board) and thurbox (todo CLI) have an explicit task object, which is a gap open-seed can fill with checked-in markdown.

**Where the app/daemon boundary falls:** the TUIs themselves, status polling, dashboards, and notifications require an external process, not template material. But every mature project has been forced to push a *contract* into the user's repo, and those contracts are precisely what a template can standardize:

**Most transferable ideas (checked-in, no daemon required):**

1. **Worktree lifecycle hooks as a named script directory**: dmux's `.dmux-hooks/` (on-create, pre-merge, post-merge) unified with amux's minimal three-verb `.amux/workspaces.json` contract (`setup-workspace`, `run`, `archive`) and agent-deck's `.agent-deck/worktree-setup.sh` + `.worktreeinclude`. open-seed should ship a `hooks/` (or `.seed/hooks/`) directory with those five named slots, plus a `.worktreeinclude` for propagating gitignored env files. **Pre-merge is the natural quality-gate slot**: lint/test enforced by convention, runnable by any orchestrator or by CI. Adopt amux's trust posture: document that repo-supplied scripts must be explicitly approved.

2. **A versioned declarative workspace file**: tmux-ide's `.tmux-ide/workspace.yml` (`version: 1`, rows/panes/commands/focus) and agentbox's layered `agentbox.yaml` (services, tasks, setup). A checked-in `workspace.yml` that both humans (`tmux-ide`-style launcher script) and agents can read gives every clone the same layout with zero external app.

3. **A vendor-neutral status/coordination protocol**: tmux-ide's one-liner (`tmux set-option -p @agent_state "working:<ts>"`) plus a `wait`-style script (block until pane output matches / status reaches done). This is ~50 lines of checked-in shell and makes the four-state enum (working/blocked/idle/done) a repo convention any harness can emit: with Claude Code hooks providing it automatically.

4. **Agents-as-data + agent-facing docs**: thurbox's `agents.toml` (harness = command template, not code) checked in alongside the now-universal `AGENTS.md`/`CLAUDE.md` and a `skills/<project>/SKILL.md` directory (herdr, agent-deck, agterm all ship these). This is how a template teaches whatever harness the team uses: Claude Code, Codex, Gemini, OpenCode, to operate the repo's own orchestration scripts.

5. **Checked-in guardrail budgets and naming conventions**: repomon's numeric autonomy budgets (action cap, max concurrent agents, autonomy level: autonomous/supervised/read-only) and agent-deck's cost budgets belong in a small `guardrails.yml` that hooks and CI read; openkanban/agent-manager-style branch conventions (`am/<task>`, task-id-derived branches, sibling `<repo>-worktrees/` dir) cost nothing to standardize and make every agent's work auditable in plain git.

A team cloning open-seed with those five pieces gets ~80% of what claude-squad/dmux/amux provide, harness-agnostic and CI-enforceable, while remaining compatible with any of these external TUIs a developer later chooses to layer on top.
