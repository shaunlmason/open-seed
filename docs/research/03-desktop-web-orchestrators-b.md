# Research: Parallel Coding Agents — Desktop & Web (Part B)

> Category survey of [awesome-agent-orchestrators](https://github.com/andyrewlee/awesome-agent-orchestrators),
> researched 2026-08-21 for the open-seed design study. Focus: what can live *inside* a repo
> vs. what requires an external app/daemon.

Scope: 25 repos surveyed via GitHub pages + READMEs, 2026-08-21. Almost all of these are apps/daemons; the checked-in surface area each one defines is called out explicitly.

## Deep dives

### 1. coder/mux — now branded "Xum" (Coder Technologies)
(a) Desktop coding-agent multiplexer with its own custom agent loop (inspired by Claude Code) rather than wrapping CLIs. (b) Concurrent independent agent workspaces under one control plane: unified git-divergence visualization, per-agent sidebar status, aggregated token/cost tracking. (c) Tasks = workspaces; no kanban — status indicators plus rich markdown output and context-compaction dialogs. (d) Three runtimes: **Local** (in-place), **Worktree** (local git worktrees), **SSH** (remote), all with central git-divergence view. (e) Plan/Exec modes with "mode prompts" (per-mode instruction files), integrated code review UI, opportunistic compaction; enforcement is UI-side, not file-side. (f) `.mcp.json` in repo; instruction files referenced but repo-checked config paths not documented. (g) Model-level multi-provider (it is model-agnostic rather than harness-agnostic, since it runs its own loop). (h) ~2.0k stars, 3,555 commits, AGPL-3.0, corporate-backed, very active. (i) Steal: **mode prompts** — distinct checked-in instruction files per lifecycle mode (plan vs. exec) rather than one monolithic AGENTS.md; and "git divergence as the primary fleet dashboard metric."

### 2. Ivy-Interactive/Ivy-Tendril
(a) Electron desktop "Agentic Software Factory" orchestrating CLI agents through a plan-first pipeline. (b) Parallel git worktrees per job; main branch stays clean until review/approve/merge. (c) **Plan-based lifecycle**: markdown plans ("drafts") → annotated inline to revise agent goals → converted to active jobs. An **Inbox folder** watches GitHub Issues and jam.dev bug reports via webhooks and turns markdown specs into executable jobs. Pipeline is built from modular "**promptwares**" — CreatePlan, ExecutePlan, ExpandPlan, CreatePr — each with its own prompts, tools, memory, and hooks. (d) Git worktrees. (e) The standout: **Verification Gates** — "wire up build, test, lint, and format checks; plans only advance when all checks pass." Same gates reused at review time before merge. (f) No documented repo-checked config; plans themselves are markdown. (g) Any CLI agent: Claude Code, Copilot, Gemini, OpenCode, Codex. (h) 171 stars, 3,291 commits, FSL-1.1-ALv2 license, active. (i) Steal: the whole shape — **plan file → gated advancement → PR**, and the promptware decomposition (separate prompt+tool bundles per pipeline stage) maps directly onto checked-in slash commands/skills. Inbox-folder-as-ingestion is also reproducible in-repo (a `tasks/inbox/` dir + CI webhook).

### 3. ouijit/ouijit
(a) Git-worktree task and terminal-session manager "customizable via lifecycle hooks, scripts, and a session-aware CLI." (b) One worktree + integrated terminal per task; live agent status with notifications. (c) Kanban statuses driven by a scriptable CLI: `ouijit task list/current/create-and-start`, `ouijit task set-status 5 in_review` — **JSON output for programmatic access**, so agents themselves can move tasks. (d) Worktrees plus **VM sandboxing for untrusted code**. (e) **Lifecycle hooks** bound to task stages, e.g. `ouijit hook set start --command 'claude "$OUIJIT_TASK_DESCRIPTION"'` — the hook receives task context via env vars; named scripts (`ouijit script run Lint`) serve as reusable quality checks. (f) Config via GUI/CLI; repo-level config exists but paths aren't documented in the README. (g) Claude Code, Codex, Pi, OpenCode. (h) 154 stars, 519 commits, TypeScript, AGPL-3.0, active releases, no-telemetry stance. (i) Steal: **env-var task-context contract** (`$OUIJIT_TASK_DESCRIPTION`) into hook commands, and a machine-readable (JSON) task CLI that agents can call to self-report status — both trivially reproducible as a checked-in script + convention.

### 4. kdlbs/kandev
(a) Self-hostable kanban orchestration platform ("Humans stay in control... build agentic workflows with gates"). (b) Go server orchestrating distributed executors over **ACP (Agent Client Protocol)**; React frontend. (c) Kanban boards with workflow automation; sub-tasks resume from the parent task's session; tasks can span multiple repos with per-repo worktrees/branches/PRs; shareable task snapshots. (d) Four executor types: local process, **Docker**, SSH, Sprites cloud; worktree per task per repo. (e) Review-first workflow (change panels, LSP editor, diff viz); **workflow gates** between kanban steps; automated transitions on events ("message sent," "agent completion"). (f) **Workflows export/import as portable YAML**; per-repo agent config via `CLAUDE.md`/`AGENTS.md`; state in `~/.kandev` (sqlite). (g) 21+ agents via ACP adapters, plus CLI passthrough for native TUIs. (h) 674 stars, 2,648 commits, AGPL-3.0, nightly pre-releases. (i) Steal: the marquee pattern — **multi-step pipelines assigning a different agent per step**: "Claude Code Opus designs the plan, Copilot Sonnet implements, Codex GPT reviews." A portable YAML workflow definition is exactly the kind of artifact a template repo can check in.

### 5. superset-sh/superset
(a) Electron "agentic IDE" for running 100+ CLI agents in parallel. (b) One worktree + branch + terminal + environment per agent; sidebar fleet monitoring, command palette, per-workspace dev-server port detection. (c) Workspaces, not tickets; notification-driven attention routing. (d) Worktrees. (e) Diff viewer with inline commenting and in-app editing before commit/push — human review, no automated gates. (f) **The best checked-in convention in the set**: `.superset/config.json` with `{"setup": ["./.superset/setup.sh"], "teardown": [...], "run": [...]}` — script arrays the app executes at workspace creation/teardown/run, living in the user's repo so every clone inherits them. (g) Widest harness list surveyed: Amp, Claude Code, Codex, Cursor Agent, Droid, Gemini, Copilot, Grok, Kimi, Mastra, Mistral Vibe, OpenCode, Pi, "any CLI agent." (h) 13.2k stars, 3,776 commits, Elastic License 2.0, daily releases. (i) Steal: the `.superset/` pattern verbatim — a dot-directory of **setup/teardown/run scripts that any orchestrator (or plain human) can execute**, making worktrees bootable regardless of which tool created them.

### 6. pingdotgg/t3code
(a) Theo/ping.gg's "agent harness control surface": local Node server + web/iOS/Android/Electron clients to drive your existing agent subscriptions from anywhere. (b) Server-on-your-machine, thin remote clients; threads per agent session. (c) Threads; no ticket system. (d) Runs harness CLIs on the host; remote-ready rather than sandbox-focused. (e) Four **permission modes** — Supervised ("ask before commands and file changes"), Auto-accept edits, Auto ("routine actions proceed, risky ones request approval," provider-dependent translation), Full access (default) — set **per thread in the UI and inherited by child threads**; notably *not* file-configurable. (f) No user-repo conventions documented. (g) Codex, Claude Code, Cursor, Grok Build, OpenCode. (h) 19.9k stars / 4.7k forks in weeks, 2,724 commits, MIT, self-described "very very early." (i) Steal: the **named permission-mode ladder with inheritance** — a vocabulary worth standardizing in a repo policy file even though t3code itself keeps it UI-only; also proof that harness-abstraction of permission semantics is messy.

## Survey of the rest

**intentic/intentic** — Self-hosted "co-piloted" agent workspace: agents in container sandboxes + worktrees on your own hardware, browser UI over outbound-only Cloudflare tunnel. Fleet board (Attention/Active/Finished) with token spend and diff size per agent. Plan-mode-by-default; **per-file and per-hunk diff approval**; environment changes (Dockerfile overlays) themselves proposed as reviewable diffs; credentials injected per-turn, never shown in UI. 23 stars but 1,878 commits, MIT, strong eng hygiene. Steal: environment-as-reviewable-diff, hunk-level approval granularity.

**joewinke/jat** — SvelteKit swarm model with Epics→Tasks dependency graphs, `/jat:tasktree` command converting requirements to task hierarchies, P0–P4 priorities, Agent Registry + "Agent Mail" message passing between agents. Isolation is only tmux sessions. Guardrails: clickable question/approval UI, auto-proceed rules by task type/priority, "Overseer" **L0–L3 autonomy levels**. 251 stars, 5,120 commits, MIT. Steal: graduated autonomy levels per task class; epic/task markdown trees.

**coollabsio/jean** (Coolify team) — Tauri desktop dev-environment for agents: multi-project, worktree automation, Plan/Build/**Yolo** execution modes, "magic commands" (issue investigation, code review, PR generation), session recaps/digests. Repo-checked `jean.json`; GitHub + Linear integration. 8 harnesses. 1.2k stars, 1,565 commits, Apache-2.0. Steal: named execution modes tied to approval strictness; repo-checked `jean.json`.

**nimbalyst/nimbalyst** — Electron visual workspace (markdown/mockup/diagram WYSIWYG + agent sessions, kanban, mobile companion). Key line: "**open storage of content and status in markdown, workflow in slash commands, and plain files on disk or in git**" — the most template-friendly philosophy in the set. 1.5k stars, 5,680 commits, MIT. Steal: markdown-as-database, slash-commands-as-workflow.

**ShreyPaharia/octomux** — Local dashboard for Claude Code + Cursor fleets. Kanban: backlog→planned→in progress→review→PR→done; orchestrator agent dispatches child subtasks (task trees); worktree+tmux per task. Guardrails: **centralized permission inbox** (all "allow this tool?" prompts in one queue), human-gated review publishing, **loop budgets** (iteration caps, token/time limits). Config: `~/.octomux/octomux.yml` plus **per-repo `.octomux/hooks/<event>.d/` lifecycle hook directories** — a fully checked-in, run-parts-style hook convention. 21 stars but 1,667 commits, MIT. Steal: the `hooks/<event>.d/` directory convention and loop budgets.

**openchamber/openchamber** — Big (9.1k stars) multi-surface workspace (desktop/web/VS Code/mobile) built **exclusively on OpenCode**. Session Goals persisting until done/blocked/limit; multi-run comparison across up to 5 models with "Fusion" to combine the best parts; cron-scheduled recurring work; Changes Walkthrough guided review. MIT, 2,642 commits. Steal: N-run fan-out + fusion; persistent session goals.

**stablyai/orca** — YC-backed "Agent Development Environment," the category's gorilla: **50.7k stars**, 9,002 commits, ships daily, MIT. Fan one prompt across five agents in parallel worktrees, compare, "merge the winner." 30+ harnesses. Native GitHub + Linear boards in-app. Repo contains `orca.yaml`. Steal: tournament-style fan-out/compare/merge as a first-class workflow.

**johannesjo/parallel-code** — Electron; branch-per-task worktrees with **symlinked node_modules**, optional Docker sandbox via repo-checked `.parallel-code/Dockerfile`, "Steps tracking panel," `.claude/steps.json` progress file, inline diff comments, CI-status desktop notifications. 985 stars, 1,158 commits, MIT. Steal: checked-in sandbox Dockerfile; machine-readable steps.json progress contract.

**proliferate-ai/proliferate** — Rust-backend open "AI IDE"; worktree per task, subagent delegation, shared MCP/skills config across agents, recurring/event-driven workflows (nightly review passes, triage on alerts, dependency bumps). 212 stars, 2,904 commits, AGPL-3.0. Steal: scheduled maintenance workflows — directly portable to CI cron.

**yc-software/qm** — "Multiplayer agent harness for work" (Slack + web), 14.0k stars, MIT. Postgres core (identity, policy, scheduler, agent loop); persistent sandbox per person/room scope. Guardrails: three postures — **Strict** (approve everything), **Auto** (content classifier screens external data before the model sees it — prompt-injection defense), **Dangerous** — plus predeclared command policies that deny destructive ops in all postures. Deployment via **org-owned repo with `deploy/layers/<org>/`** overlay (custom tools/skills/infra) while core stays "byte-identical to upstream." Steal: the layered org-overlay-repo pattern and predeclared command policy files.

**supabitapp/supacode** — Native Swift/macOS command center; worktree+terminal per task, session daemon for background persistence, live busy/awaiting/idle states, repo-specific setup/archive scripts. Notable governance line: "a human (never an AI agent) is the accountable author." 2.3k stars, 1,984 commits. Steal: human-accountable-author policy language.

**Emanuele-web04/synara** — Bun/TypeScript desktop workspace: Projects→Threads→Provider Sessions; managed worktrees; **task handoff between provider runtimes preserving project context**. 9 harnesses. 1.6k stars, 3,009 commits, early-stage. Steal: cross-harness handoff with preserved context.

**banteg/takopi** — Python **Telegram bridge**: group chats/topics map to repo+branch (worktree) contexts; per-session queues; streaming progress; steer/cancel from chat. 1k stars, 382 commits, MIT. Chat-topology-as-task-router is the one idea.

**tempestai-dev/tempest** — Tauri desktop; differentiator is **Token Intelligence**: a shared local code-knowledge graph indexed once and served to all sessions (claims 86% token reduction across 7 repos). Serious OS-level sandboxing layer ("Hephaestus"): Windows Job Objects, macOS Seatbelt, Linux bubblewrap — agents run permissionless-by-default inside it. 135 stars, 284 commits, Apache-2.0, early. Steal: shared index as a cached artifact; OS sandbox + full autonomy as a trade.

**tlbx-ai/tlbx** — .NET self-hosted browser terminal multiplexer (persistent PTYs) over HTTPS/WS + Tailscale. 104 stars, 3,426 commits, AGPL. Infrastructure, not orchestration; skip.

**traycerai/traycer** — "Nerve Center for Agentic Coding": durable Task sessions, **agent-to-agent communication** (agents debating architecture, peer reviews), shareable team boards, real-time co-editing, unified context across providers with mid-task model switching. 1.2k stars, 841 commits. Steal: peer-review-between-agents as an explicit step.

**sahithvibudhi/vibe-tree** — Worktree-per-task fleet controller with persistent terminals; fleet status (working/waiting/done). Repo-checked **`.vibetree/hooks/` (post-create, pre-remove scripts)**. Any terminal program. 266 stars, 281 commits. Steal: minimal two-hook worktree lifecycle.

**rayzhudev/vibecraft** — RTS-game-style canvas for Claude/Codex. 35 stars, 25 commits; novelty UI, trivial for our purposes.

**egoist/waku** — Rust/GPUI native desktop over a `waku-daemon`; SQLite state; **git-backed checkpoints for conversation-aware task revert**. 8 harnesses. 1.1k stars, 378 commits. Steal: checkpoint/revert tied to git state.

## SYNTHESIS

**The category has converged hard.** ~20 of 25 use the identical core: *task → git worktree + branch → agent in a terminal → diff review → merge/PR*, with a fleet dashboard on top. Worktree isolation is the industry answer; containers/VMs (kandev, intentic, tempest, parallel-code, ouijit) are a second, optional ring for untrusted execution. This means open-seed can treat "worktree-per-task with a naming convention" as settled ground that every external tool will interoperate with.

**Recurring design patterns:**

1. **Plan-based lifecycle with verification gates** (Ivy-Tendril is the purest): markdown plan → inline annotation → gated execution where *plans only advance when build/test/lint/format all pass* → review with the same gates → PR. Intentic ("plan mode by default"), mux (Plan/Exec modes), jean (Plan/Build/Yolo) are weaker cousins: everyone separates a cheap deliberation phase from an expensive execution phase, and the best ones put mechanical checks at the boundary.
2. **Lifecycle hooks as checked-in script directories**: octomux's per-repo `.octomux/hooks/<event>.d/`, vibe-tree's `.vibetree/hooks/` (post-create/pre-remove), superset's `.superset/config.json` setup/teardown/run arrays, ouijit's `hook set <event> --command` with task context in env vars. Three independent projects landed on "dot-directory of scripts fired at worktree/task lifecycle events."
3. **Multi-step workflows with different agents per step**: kandev's portable-YAML pipelines (Opus plans → Copilot implements → Codex reviews, with gates between kanban columns and event-driven transitions); Ivy-Tendril's promptwares (CreatePlan/ExecutePlan/ExpandPlan/CreatePr, each with own prompts+tools+hooks); traycer's agent peer review. The insight: stage boundaries are where you swap both the *prompt bundle* and the *model*.
4. **Fan-out/compare/merge tournaments**: orca ("fan one prompt across five agents, merge the winner"), openchamber (5-model multi-run + Fusion). Needs only worktrees + a comparison step.
5. **Graduated autonomy as named policy**: t3code's four permission modes with thread inheritance, jat's L0–L3 overseer levels, qm's Strict/Auto/Dangerous postures with always-on destructive-command denylists, octomux's loop budgets (iteration/token/time caps). Everyone reinvents this vocabulary; nobody checks it into the repo — a gap open-seed can fill.
6. **Machine-readable task state agents can drive**: ouijit's JSON CLI, parallel-code's `.claude/steps.json`, nimbalyst's "markdown for content/status, slash commands for workflow, plain files in git" — the local-first minority that proves the whole loop can live in-repo.

**Most transferable to a checked-in template (top 5):**

1. **A lifecycle-script convention** merging superset + octomux + vibe-tree: `config.json`/`hooks/` with `setup`, `run`, `teardown`, `post-create.d/`, `pre-merge.d/` — tool-agnostic scripts any orchestrator, CI job, or human can execute, receiving task context via documented env vars (ouijit's pattern).
2. **Plan-file lifecycle with gate enforcement in CI** (Ivy-Tendril, reimplemented repo-side): `tasks/` markdown with status front-matter (inbox → planned → in-progress → in-review → done), plus a CI/hook gate that blocks status advancement and merge unless build/test/lint/format pass. Ingestion from GitHub Issues into `tasks/inbox/` via a workflow.
3. **A portable workflow YAML** (kandev's export format as inspiration): checked-in pipeline definitions naming steps, the harness/model per step (plan/implement/review), gate commands between steps, and event transitions — executable by a thin script even without any GUI.
4. **A permissions/autonomy policy file**: named modes (supervised / auto-edit / auto / full) à la t3code, per-task-class autonomy levels à la jat, an always-on destructive-command denylist and loop budgets à la qm/octomux — checked in so guardrails are versioned and reviewable, unlike every surveyed tool where they live in app settings.
5. **Machine-readable task/progress contract**: JSON-emitting task CLI or `steps.json` convention so agents self-report status and any dashboard (or plain `jq`) can render the fleet — following nimbalyst's "plain files in git" philosophy, which is the only storage model that survives tool churn in this fast-moving, heavily-AGPL'd category.
