# Research: Parallel Coding Agents — Desktop & Web (Part A)

> Category survey of [awesome-agent-orchestrators](https://github.com/andyrewlee/awesome-agent-orchestrators),
> researched 2026-08-21 for the open-seed design study. Focus: what can live *inside* a repo
> vs. what requires an external app/daemon.

Method: fetched each GitHub repo page (plus raw READMEs where needed) on 2026-08-21. Note upfront: **nearly everything in this category is an external app** (Electron/Tauri desktop or local web server). The transferable value is in the small set of checked-in conventions these apps read or write.

## Project-by-project

**1. Untrivial-ai/agent-orchestrator** — Desktop IDE for managing fleets of coding agents ("AO"). ~9.7k stars, 1.4k forks, 2,300+ commits, Apache-2.0, TypeScript, active. Topology: a repo-level "project orchestrator" agent plans and delegates, spawning focused worker agents that execute autonomously. Task tracking: live kanban of worker sessions with status columns **Working / Needs you / In review / Ready to merge**; each card aggregates task + agent + branch + PR + CI state + review status. Isolation: dedicated branch + git worktree per worker; "scratch" workers get branchless managed dirs; even per-worker browser profiles. Guardrails: built-in PR/CI tracking, agent-assisted reviews, merge-conflict coordination, review feedback routed back to the owning agent. **Checked-in artifact: `.agents/skills/` directories with structured `SKILL.md` files (e.g. a bug-triage skill)** — the clearest repo-resident convention in this group. Harnesses: 26 including Claude Code, Cursor, Aider, Copilot, Cline, Devin. One of the strongest projects here.

**2. agent-squid/squid** — Browser UI meta-harness unifying local CLIs (Claude Code, Codex, Cursor Agent, OpenCode, Pi) via `#topic@agent` lanes: FIFO queue per topic-session plus ephemeral `!` adhoc turns for context experiments; per-prompt token/cost analytics. Python, 13 stars, no repo-checked config — niche but the "compare full-session vs limited-context prompt" experiment idea is cute.

**3. ramarlina/agx** — Local Electron workspace running agents against **tickets** (Jira/Linear import), with "human-in-the-loop at every gate": explicit approve/reject flows and a **reviewer agent that does a first pass on PRs so the human reviews only what needs judgment**. Worktree isolation, checkpointed resumable state, provider switching mid-thread (Claude/Codex/Gemini/Ollama). Config in `~/.agx/config.json`, nothing checked in. 27 stars, 707 commits, MIT — small but active.

**4. 23blocks-OS/ai-maestro** — "AI Agent Orchestrator with Skills System": peer-mesh, no central server; agents message each other via a signed email-like "Agent Messaging Protocol" across machines. Kanban with dependencies and five columns; teams with split-pane "war rooms." Isolation: tmux, Docker, EC2, or Fargate. Guardrails: gateway-level prompt-injection screening ("34 patterns") before content reaches agents; Slack/Discord/Email/WhatsApp gateways. Agent-agnostic (any terminal agent). 754 stars, v0.36.x, MIT, Next.js/CozoDB, active. No mandatory repo files. Notable for: cross-machine mesh + inbound-content sanitization as a guardrail category.

**5. vivy-company/aizen** — macOS (Apple Silicon-only) parallel-dev workspace: isolated environment per project/branch (worktree, folder, or copy) each with terminal, files, browser, and **ACP-registry agent sessions** (Claude Code, Codex, OpenCode). CI visibility (GitHub Actions/GitLab) in the worktree sidebar; diffs and PR review views. GUI config only, Swift, GPL-3.0, 300 stars, 1,500+ commits; 2.0 rewrite underway.

**6. Kc1t/alethe-agents** — Tauri/Rust local-first terminal workspace: projects → containers → panes → sub-tabs, each a real PTY; shared MCP servers/skills across agents; a "handoff" mechanism that passes Claude Code conversations to Codex via locally-redacted context packets. Worktrees, per-project todos, session crash recovery. Reads the agents' own config files (Claude/Codex/OpenCode). 384 stars, AGPL-3.0, early but active.

**7. AndyMik90/Aperant** — The big kanban-driven autonomous framework: up to 12 parallel agents in isolated worktrees driven by a kanban board; **"self-validating QA" loop that catches issues before human review**; AI-powered merge conflict resolution; a memory layer persisting insights across sessions; imports GitHub/GitLab issues and syncs Linear. Requires Claude Code + Pro/Max. Electron/TypeScript. **14.5k stars, 1.9k forks** — largest in this half; v2.x in maintenance while v3.0 (cloud) is rebuilt. Config is GUI-side, not checked in. The QA-agent-between-worker-and-human pattern is its signature.

**8. AutoMaker-Org/automaker** — Autonomous "AI development studio" on the Claude Agent SDK; **archived / "no longer actively maintained"** but architecturally instructive. Kanban: **Backlog → In Progress → Waiting Approval → Verified**, with configurable concurrency (default 3 features at once); "spec mode" has a planning agent decompose work, then per-task dedicated agents. **Everything is checked into the project: `.automaker/features/{featureId}/` JSON cards, `agent-output.md` logs, `.automaker/settings.json`, and an `app_spec.txt` (XML) project spec** — the most fully repo-resident task representation in this survey. Guardrails: optional plan-approval before implementation, an explicit human "Waiting Approval" verification column, per-feature model/thinking-depth config, worktree + optional Docker sandbox + `ALLOWED_ROOT_DIRECTORY` fence. 3.2k stars.

**9. get-bb/bb** — "Agentic IDE that builds itself": desktop + web + CLI + HTTP API surfaces over threads you can follow live, steer, or hand off between agents; task-board UI; worktree support with deterministic dev-data dirs; **AGENTS.md** convention documented. 2.5k stars, 5,041 commits, MIT, nightly builds — very active. Guardrails via review threads and checks; details thin on the page.

**10. block/berd** — Block's open-source Tauri 2/React 19 desktop front-end for **Goose**: talks to a `goose serve` sidecar over an **ACP WebSocket**, with the backend pinned via `goose-backend.lock.json`. No kanban; GitHub-issues-driven, collaborator-only PRs (strong governance). Quality gates are for the app itself (`just check`: Biome, design-system, i18n, contract, type checks). Two transferable ideas: (a) **portable "Agent Skills" published from a `skills/` directory** (e.g. `buzz-handoff`, which sends only an *explicitly approved* reply outward — approval baked into the skill contract); (b) **enterprise overlay distributions** — private agents/config/signing layered on the public repo without forking it. 677 stars, Apache-2.0, active.

**11. ofekron/better-agent** — FastAPI + React local workspace: per-session runners for Claude/Codex/Antigravity that survive UI disconnects; fork sessions, delegate bounded work; full tool-call traceability; SDK for external orchestrators via authenticated loopback API. 58 stars, 2,782 commits, active. No worktrees/containers; "run only in trusted environments."

**12. amirfish1/claude-command-center** — Local dashboard unifying 8+ harness sessions. Kanban derived from session state (Backlog → Planning → Working → Review → **In Testing** → Verified); "Flow" containers group sessions; **WatchTower durable ticket queues with worker dispatch**; a sibling-ask API (`POST /api/ask`) so sessions query each other without human relay. Worktree spawns at `<repo>-wt/<slug>` on `feat/<slug>` branches with optional init scripts. Guardrails: inline approval prompts, **GitHub issue verification that closes issues with commit-SHA comments**, "needs-you" signals mined from transcripts, cost-aware resumption routing. 126 stars but 3,552 commits, v5.21.0 (Aug 2026), source-available/non-commercial. Idea-dense despite low stars.

**13. codika-io/clave** — macOS Electron multi-session PTY grid (Claude Code/Codex/Antigravity); `.clave` workspace files; "Dangerous Mode" as an explicit opt-in to skip permission checks; git panel + MagicSync commits. 47 stars, MIT. No orchestration or task model.

**14. rustykuntz/clideck** — Browser dashboard for parallel CLI agents with live status detection, an "autopilot" router, and `clideck ask` cross-session consultation; E2E-encrypted mobile remote. 151 stars, MIT, npm. Chat-sidebar organization, no kanban/guardrails.

**15. NeuralNomadsAI/CodeNomad** — Desktop/server workspace wrapping **OpenCode only**; multi-instance sessions, worktrees, JSON "SideCar" config for companion tools behind its server. 2.5k stars, MIT, active — popular but single-harness and no task/QA model.

**16. collabs-inc/collab-public** — Electron "infinite canvas" of terminal/editor/file tiles for running agents; state in `~/.collaborator/*.json`. 2.9k stars but no orchestration topology, task tracking, or guardrails documented. A workspace shell, not an orchestrator.

**17. zeronsh/comet (Zeron)** — Rust local-first control plane: a small engine per device stores sessions locally with optional cross-device sync; worktrees; Claude Code/Codex/Cursor/Grok/Hermes/Pi. 1.1k stars, active. Task tracking/guardrails not documented.

**18. owengretzinger/constellagent** — macOS app: side-by-side agents each with isolated terminal/editor/worktree; **cron-based scheduled agent runs with sleep/wake recovery that coalesces missed runs**. 214 stars, 75 commits, TypeScript/Bun, signed DMG. Thin otherwise; the cron-with-coalescing idea is the takeaway.

**19. cristicretu/diri** — Rust/GPUI native orchestrator; background daemon owns PTYs so sessions outlive the GUI; worktrees or remote SSH+tmux hosts; **agent status ("working / needs-you / done") derived from screen-content analysis**, driven by per-agent **JSON manifests describing spawn, resume, approval keys, and screen rules**; MCP server for agent-to-agent orchestration. 268 stars, Apache-2.0, active. The declarative harness-manifest idea is neat.

**20. Charlie85270/Dorothy** — Electron orchestrator running 10+ agents in PTYs with a **"Super Agent" meta-agent that controls the others via MCP tools** (capability-based assignment, progress monitoring). Kanban (Backlog → Planned → Ongoing → Done) with priority, 0-100% progress, skill requirements, and auto-assignment; output delivery to Telegram/Slack/GitHub comments/JIRA transitions. Worktrees + `--add-dir` multi-repo context. Runs agents with permission checks skipped for unattended mode — guardrails are notification-shaped, not gate-shaped. 338 stars, MIT, active.

**21. generalaction/emdash** — YC W26 desktop app; 5.5k stars, 9,667 commits, very active. One worktree + branch per agent task; auto-detects installed provider CLIs (Claude Code, Codex, Cursor, OpenCode, Amp, Devin, Qwen, Droid, Copilot) and **installs lifecycle hooks into provider configs to track status and make sessions resumable**. Task tracking is deliberately external: **pipes issues/tickets from Linear, GitHub, Jira, GitLab, Asana, Monday, Featurebase, Forgejo, Plain directly into agents** — no native board. Review diffs, create PRs, inspect CI checks, merge from one place; human review before merge, no automated gates. Config: `.emdash.json` + local SQLite. The "ticket system is the task board; the orchestrator is just the runner" stance is the interesting contrast with Aperant/Automaker.

**22. fwdai/fletch** — macOS Tauri IDE with the most pipeline-like model here: **workflows as shareable YAML** — plan → build → review → test with `review→fix` loops that repeat "until a verdict says done," parallel fan-out/join blocks, named pause points, and **budgets (turns, iterations, wall-clock, tokens)**. Isolation: per-agent macOS Seatbelt sandbox profiles (deny writes outside workspace) or Docker; agents get shared-object git clones; pushes/PR creation are host-side brokered RPC so credentials never enter the sandbox. "Nothing merges without you." Harness auto-detect + normalized transcripts; vendored codegraph index served over MCP. Only 20 stars / 1,495 commits, AGPL-3.0 — obscure but the YAML-workflow-with-budgets design is directly steal-able.

**23. cfal/garcon** — Self-hosted browser workspace, up to 4 live sessions in split panes; queue-next-instruction, mid-turn interrupt/steer, in-place tool-use approval; Telegram alerts on completion/permission-needed. TypeScript/Bun/SvelteKit, GPL-3.0, 57 stars, active. Config via env vars in `~/.garcon`; no repo files.

**24. humanlayer/humanlayer** — 11.3k stars, 938 forks, 2,098 commits — but the README **now declares the code "pretty much all deprecated,"** pointing to a rebuild at humanlayer.com; no recent releases. The repo tree still shows the architecture that made it influential: `hld` (local daemon managing Claude Code sessions), `humanlayer-wui` (the CodeLayer desktop UI), `claudecode-go` (Go SDK), `hlyr` (CLI, including the `thoughts` tool), and a `.claude/` directory. Historically this was the flagship of two patterns: (1) **human-in-the-loop approvals as a first-class primitive** — originally an SDK (`@require_approval`, contact-human channels via Slack/email) for arbitrary agents, later re-aimed at coding: the daemon intercepted Claude Code tool permission requests (via MCP permission prompting) and routed approve/deny to humans in the WUI or Slack; (2) **checked-in markdown workflow conventions** — the research → plan → implement slash-command set (`.claude/commands/`: research_codebase, create_plan, implement_plan) operating on markdown plan documents, plus the `thoughts/` directory synced by `hlyr thoughts` to keep agent context/notes versioned outside app state. These conventions ("Advanced Context Engineering for Coding Agents") were widely copied and are exactly the repo-resident, app-optional pattern open-seed wants — worth mining from the deprecated tree and community forks even though the product moved to a closed rebuild.

**25. im4codes/imcodes** — Messaging + memory layer across harnesses (Claude Code, Codex, Gemini CLI, Copilot, Cursor, OpenCode, OpenClaw, Qwen) over tmux or SDK transports. Rich guardrails: multi-phase "team discussions" (audit→review→plan) before implementation; **supervised execution with audit→rework loops issuing evidence-based verdicts (PASS/REWORK/BLOCKED)**; fail-closed automation; circuit breakers on agent-to-agent messaging (depth limit, rate limit, broadcast cap); human owns final release. Task tracking: **OpenSpec Auto Deliver — checked-in `tasks.md` change definitions with spec audit, task-driven implementation, module scoring (spec/tasks/implementation/tests/risk), and rework gates**. 960 stars, 2,975 commits, MIT, explicitly "personal project, no guarantees." Idea-dense on verification vocabulary.

## SYNTHESIS

**Recurring patterns across this half of the category:**

1. **Worktree-per-task is the universal isolation substrate.** ~15 of 25 use git worktrees as the default; containers are the *optional* upgrade (Automaker, ai-maestro, fletch, CodeNomad), and only fletch does real OS-level sandboxing (Seatbelt profiles + host-brokered git push, keeping credentials out of the sandbox). Naming conventions recur: `<repo>-wt/<slug>` on `feat/<slug>` branches.

2. **The kanban board as agent dispatcher, with a canonical column grammar.** Boards aren't just visualization — cards *drive* agent spawning (Aperant, Automaker, Dorothy, ai-maestro, agent-orchestrator, claude-command-center). Two column vocabularies recur: work-state (Backlog→In Progress→Done) and, more interestingly, **verification-state**: Automaker's Backlog → In Progress → **Waiting Approval → Verified** and command-center's … Review → **In Testing → Verified**. The mature ones make "agent finished" and "human verified" distinct states. The alternative stance (emdash, agx) is *no native board*: external ticket systems (Linear/Jira/GitHub) are the source of truth and the orchestrator just routes tickets to agents.

3. **QA loops are converging on a reviewer-agent-before-human pattern.** Aperant's self-validating QA loop, agx's first-pass reviewer agent, fletch's `review→fix` loop repeating "until a verdict says done," imcodes' audit→rework gates with PASS/REWORK/BLOCKED verdicts, agent-orchestrator's interactive agent reviews feeding PR state. The common shape: worker output → machine verdict with a bounded retry loop → human sees only what survives. imcodes adds fail-closed defaults and structured evidence; fletch adds hard **budgets** (turns/tokens/wall-clock) so loops can't spin forever.

4. **Approval flows split into tool-level and milestone-level.** Tool-level: humanlayer's intercepted permission requests, garcon's in-place tool approvals, diri's manifest "approval keys." Milestone-level: Automaker's plan-approval before implementation and Waiting Approval column, agx's approve/reject at every gate, fletch's named pause points and "nothing merges without you." The anti-pattern also recurs: some tools skip permission prompts entirely for unattended mode and substitute *notification* (Telegram/Slack) for *gating*. CI-failure fixing is surprisingly thin in this half — agent-orchestrator and emdash surface CI state on cards and route feedback back to the owning agent, but nobody here closes the CI-red→auto-fix loop as a named feature.

5. **Status legibility via "needs-you" detection.** agent-orchestrator's "Needs you" column, diri's screen-scrape-derived working/needs-you/done states, command-center's transcript-mined signals, emdash's lifecycle hooks installed into provider configs. Everyone needs a machine-readable answer to "is the agent blocked on me?"

**Most transferable ideas for a checked-in template repo (open-seed):**

1. **Task-as-file, in-repo (Automaker + imcodes).** Automaker's `.automaker/features/{id}/` JSON cards + `agent-output.md` + `app_spec.txt` proves the whole board can live in the repo: columns are just a status field, diffable, PR-reviewable, and app-optional. Pair with imcodes' OpenSpec `tasks.md` style. For open-seed: a task directory of markdown/JSON cards with a status field encoding Backlog → In Progress → **Waiting Approval → Verified** — the two-stage done state is the part worth standardizing.

2. **Humanlayer's checked-in workflow trilogy.** `.claude/commands/` research → plan → implement slash commands operating on markdown plan documents, plus a versioned `thoughts/` directory for agent context/notes. This is the single most proven "orchestration inside the repo, no daemon required" pattern in the category — and with the product now closed-source-rebuilt, the open convention is free to adopt.

3. **Skills as repo directories (agent-orchestrator + berd).** `.agents/skills/<name>/SKILL.md` structured skill definitions checked into the repo (AO's bug-triage skill) and berd's portable `skills/` publishing. Open-seed should ship a skills directory convention that multiple harnesses can read, aligned with the emerging `AGENTS.md` standard.

4. **Declarative workflow specs with verdicts and budgets (fletch + imcodes).** A checked-in YAML pipeline — plan → build → review→fix-loop → test — with explicit gates, named pause points, PASS/REWORK/BLOCKED verdict vocabulary, and budgets (max iterations/turns/tokens). Even without fletch's runtime, the spec file standardizes what "the QA loop" means, and a thin CI job or script can enforce it.

5. **Worktree conventions + verification receipts (command-center).** Check in a small script/config establishing `<repo>-wt/<slug>` + `feat/<slug>` naming with a per-worktree init hook; and steal the "close the loop with evidence" trick — issues closed with commit-SHA comments — as a template convention: every Verified task card must reference the commit/PR and the check run that proved it.

Overall: the category's apps differ mainly in chrome; the durable, template-compatible substance is (a) file-based task cards with an approval/verified state machine, (b) markdown plan/research conventions plus slash commands, (c) skills directories, (d) YAML-declared review loops with budgets, and (e) worktree naming + evidence-linked closure. All five can be expressed as checked-in markdown/YAML/scripts with zero daemon dependency — which is exactly open-seed's lane.
